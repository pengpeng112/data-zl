## 2. 设计理念

### 2.1 一句话定位

> **「医院数据资产的指挥中心」**——冷静、专业、信息密度高；青蓝冷调传达科技感与信任感；玻璃拟态与微光营造高端沉浸；统一语义色让状态一目了然。

### 2.2 设计关键词

- **指挥中心**：首页 Dashboard 像作战室大屏，信息分层清晰。
- **青蓝科技**：天青 + 深海青为主，辅以靛蓝、紫罗兰点缀关系链路。
- **玻璃拟态**：登录页、Dashboard 卡片、抽屉使用半透明磨砂质感。
- **微光与呼吸**：关键数据、选中节点、hover 状态带柔和光晕。
- **信息密度**：业务表格页保持紧凑；驾驶舱页保持呼吸感。

### 2.3 设计原则

1. **单一配色源**：所有颜色从 CSS 变量派生，禁止业务页内联 `style="color:#xxx"`（S3/S8 根治）。
2. **token 驱动**：圆角/间距/阴影/字号/动效/渐变全部 token 化，业务页只消费不发明（S2 根治）。
3. **组件复用**：统计卡/页头/图表/空状态/加载统一组件，消灭复制（S4/S5 根治）。
4. **保留亮点**：图谱 SVG 配色体系升级为全局语义色基线；tables 左树右表、quality 6-Tab、ops timeline 审计保留。
5. **渐进可逆**：每一步都保证 `pnpm typecheck` + `pnpm build` 全绿，不做大爆炸式重写。
6. **深浅分层**：Dashboard/图谱/登录用深色沉浸式，业务表格页用浅色高效率（D4）。

### 2.4 本次已调用的设计技能与采纳口径

本方案已综合以下前端设计 skills，作为后续执行 AI 的约束来源：

| Skill | 采纳重点 | 在本文落点 |
|---|---|---|
| `frontend-dev` | 避免普通后台感；强调视觉锤、微动效、真实文案、移动端与空/错/加载状态 | §2、§3、§6、§7、§15 |
| `medical-ui-design-system` | 医疗系统可信、稳重、低噪声；统一 CSS 变量、卡片层级、语义色 | §3、§4、§8 |
| `medical-dashboard-screen` | 首页要回答“系统是否正常、风险集中在哪里、下一步看哪里”；图表有空/错/加载状态 | §5、§7、§15 |
| `medical-table-experience` | 表格页高密度但清晰；摘要、筛选、工具栏、固定列、分页、空态完整 | §11 |
| `medical-detail-redesign` | 详情抽屉优先展示风险、证据、整改状态；长内容左右分栏 | §12 |
| `medical-workflow-visualization` | 任务/质控/同步链路用 stepper、timeline、pipeline 表达，失败状态必须可解释 | §13 |

## 11. 业务表格页体验规范（来自 `medical-table-experience`）

业务页不能只换颜色。数据资产平台的高端感主要来自“信息组织清楚、操作路径短、状态一眼能懂”。所有列表页按以下结构收敛：

### 11.1 标准页面结构

```
RePageHeader（标题 / 副标题 / 主要操作）
  ↓
摘要条 ReStatCard × 3-5（总数 / 异常 / 待处理 / 最近更新时间）
  ↓
筛选区（常用筛选一行展示，高级筛选折叠）
  ↓
ReToolbar（刷新 / 导出 / 列设置 / 密度 / 批量操作）
  ↓
ElTable（关键列固定、状态 tag、长文本 tooltip、操作列固定右侧）
  ↓
分页区（总数 / 每页数量 / 已选数量）
```

### 11.2 表格页必须保留的交互

- 搜索按钮明确触发，输入框回车也触发。
- 重置只重置当前页筛选，不清空全局用户偏好。
- 筛选后分页回到第一页。
- 导出按钮必须有 loading/disabled 反馈，避免重复点击。
- 长文本使用省略 + tooltip；医学结论、规则说明可使用 2-3 行 clamp。
- `NULL`、空字符串、缺失字段统一展示为 `-` 或“需要人工确认”，禁止编造。
- 行点击不要和行内按钮点击冲突；按钮点击必须 `stopPropagation`。

### 11.3 表格视觉标准

```scss
.medical-data-table {
  --el-table-header-bg-color: var(--bg-elevated);
  --el-table-row-hover-bg-color: rgba(14, 165, 233, 0.06);
  --el-table-border-color: var(--border-light);
  font-size: 13px;
}
```

- 表头：`13px/600`，slate-700，背景 `bg-elevated`。
- 表体：`13px/400`，行高控制在 44-48px。
- 操作列：固定右侧，宽度按按钮数量明确给定，避免横向挤压。
- 1366px 下主要列必须可读；次要列允许进入列设置默认隐藏。

## 12. 详情抽屉与证据页规范（来自 `medical-detail-redesign`）

涉及表详情、字段详情、关系证据、质控问题、审计日志、同步差异的页面，优先使用右侧抽屉，不再用长弹窗堆字段。

### 12.1 标准详情布局

```
Drawer 72vw（移动端 100vw）
┌──────────────────────────────────────────────┐
│ 头部：对象名称 / 风险等级 / 状态 / 主要操作     │
```

### 12.2 详情内容分组

- **资产对象详情**：基本信息、库/Schema、中文名、业务域、数据粒度、纳入治理状态、来源文件。
- **字段详情**：字段含义、类型长度、是否主键候选、是否关联字段、是否敏感、建议质量规则。

## 13. 工作流与链路可视化规范（来自 `medical-workflow-visualization`）

平台后续会包含质量执行器、AI SQL、同步任务、运维审批、关系复核等流程。流程状态要“可解释”，不能只显示成功/失败。

### 13.1 推荐组件模式

| 场景 | 组件 | 说明 |
|---|---|---|
| 单条记录执行进度 | Stepper | 展示当前卡在哪一步 |
| 审批/反馈历史 | Timeline | 展示发现、提交、审批、执行、关闭 |
| 首页链路总览 | Pipeline | 展示“元数据采集 → 资产入库 → 关系验证 → 质量分析 → 治理发布” |
| 批量任务统计 | Funnel/Stacked Bar | 展示总数、成功、失败、跳过、待处理 |

### 13.2 标准流程节点

```
数据读取 → 参数校验 → 任务排队 → 执行中 → 结果解析 → 结果入库 → 审计记录 → 完成/失败
```

不同模块可替换节点文案，但不能隐藏失败、跳过、人工覆盖等状态。

### 13.3 状态文案规则

- “失败”必须说明原因，例如“SQL 校验失败：存在非 SELECT 语句”。
- “跳过”必须说明业务语义，例如“字段缺少中文名，等待人工确认”。
- “运行中”必须展示开始时间、耗时、当前阶段、成功/失败计数。
- “可重试”必须有入口；不可重试必须说明原因。

### 13.4 首页 Pipeline 建议

首页 Dashboard 底部可增加一条轻量流程链路：

```
活库元数据 → 资产治理导入 → 关系验证 → 质量规则 → 图谱发布
```

每个节点展示：状态、最近时间、成功数、异常数。该区域不做复杂动画，使用轻微呼吸点和连线即可。

## 16. 风险与控制

| 风险 | 控制措施 |
|---|---|
| 改动面大，引入回归 | 每阶段独立可发布；每阶段 typecheck/build 全绿才进下一步 |
| Token 改动影响现有页面 | 阶段1只加 token 不删旧值；旧值在阶段4随业务页改造逐步替换 |
| ECharts 改造导致图表渲染异常 | `ReChart` 封装后先在 overview 单页验证，再推广 |
| 图谱模块过度改动破坏双引擎 | 图谱只做视觉对齐不重写；保留 SVG/G6 切换与降级逻辑 |
| 深色主题业务页未适配 | D4 明确业务表格页保持浅色，避免范围蔓延 |
| 中英混杂改动涉及文案语义 | 改前对照后端 API 字段含义，不误改 |
| 玻璃拟态在低版本浏览器失效 | 提供 solid 回退背景色，保证可读性 |
| 过度追求动效影响后台效率 | D8 明确只用轻量 CSS/Vue/ECharts 动效，不引入重型动效库 |
| 表格页为了好看牺牲信息密度 | 按 §11 保留高密度表格结构，次要列进列设置，不删关键字段 |
| 详情页信息过载 | 按 §12 分组，技术信息折叠，风险和证据优先 |
