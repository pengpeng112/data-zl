## 2. 测试策略（四线+三补充；执行顺序=最硬产出优先）

**期望码表（S0 建立，先于一切探针）**：无 token=401、坏 token=403（两种分开探）；`ge=1` 分页 page=0/负=422 属契约非 bug；流式/CSV 导出端点不做 JSON 探针（仅鉴权探针）；login/refresh/logout 无 Origin 头=403（CSRF 设计）；`/get-async-routes` 返回空数组（设计）。**只有 5xx、鉴权 200 旁路、声明-实现双向矛盾、写路径业务断言失败进问题清单**——从根上消灭设计性误报。

1. **S 线·全路由探针**（TestClient+openapi.json 实测路由全集）：GET 五探针（无 token/坏 token/必填缺失/类型错/分页边界——分页参数按各路由 schema 实名）；写类（POST/PUT/PATCH/DELETE）分两类——**副作用黑名单端点**（S0 建立：connection-test、/jobs、/patrol/*、identity/dict sync run、/ops runs、/admin/snapshots、checkSource 等可空 body 或连真实源/LLM/调度者）**只发无 token+必炸残缺 schema 两种**；**纯平台库写端点允许成功路径**（throwaway 数据+每例清理+回读断言+重复提交幂等探针+审计行断言）。探针用**显式无头 TestClient**（不复用 conftest Bearer）；管理员合法 token 第三态用于成功路径。路径参数用占位值+资源 ID 从种子数据/依赖链取；204/302/流式按期望码表归类。
2. **C 线·前后端契约比对**：全仓检索 `http.(get|post|put|patch|delete|request)`（含 views/composables 动态拼接与模板字符串路径），排除 types.ts（13 个请求模块）；路径模板规范化后与 openapi 匹配；**报告解析覆盖率**（检出调用数/估算总数），漏检风险进不确定项；漂移=路径/方法/参数名/响应字段消费（字段消费追踪到 views/store 使用点，抽样 ≥30 条人工核）。
3. **A 线·前端源码规则扫荡**（10 条规则+白名单先定性）：v-html（白名单：reportMarkdown 已 escapeHtml、ai-quality 演示页）、写按钮无 v-perms、硬编码地址/魔法串、死路由（router modules vs views）与死 API、console 残留、空 catch、`as any` 泛滥（聚合计数不逐条，P3 限流）、明文敏感串、菜单 auths vs 后端权限码对照、`<img onerror>` 类内联事件。每命中 file:line+人工定性后入库。
4. **V 线·薄弱页补测**：薄弱页=**路由可达且无任何测试引用**的页面（客观算法：router modules×views×tests import 关系，S0 产出清单取 top）；补源码断言式测试放 `output_r173/`（**不进 pnpm test 门禁**），断言失败=问题证据。
5. **补充一·RBAC 抽查矩阵**：角色×路由正负抽查各 ≥20（无权 403/有权 200，复用 security_audit 基建思路但做运行时实测）。
6. **补充二·全局健康探针**：startup/全局异常/中间件（畸形 body/超长 header/非法 JSON→应为 4xx 非 500）。
7. **补充三·构建与迁移门禁**（只记录）：`pnpm run typecheck`、`pnpm run build`（gzip 预算）、隔离**空库** `alembic upgrade head`（建临时 schema 验证，不动 data_asset_test 主体）、只读 lint（`npx eslint --no-fix` 等效，禁 `pnpm lint` 的 --fix）。
