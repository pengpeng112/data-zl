# 平台一次性完善与 bug 修复执行计划（153）

## 0. 背景与目标

平台后端（FastAPI，31 路由模块/92 services，全量 pytest 1091 passed/1 skipped）与前端（Vue3+Element Plus，166 tests+双 typecheck+build 全过）生产运行中。经双路系统性只读扫描 + 三方 AI 互查（kimi/grok/codex 独立审查、25 项分歧全部裁决），确认一批**有行号证据**的真实问题。本计划把它们组织为**一次性执行**（P0→P7 八批），供单一执行 AI 在一个长会话内完成；周期可长，不拆轮。

设计原则：
1. **一次性完成**：八批顺序执行，每批独立验收+checkpoint 摘要（中断可从最近批次续跑）。
2. **代码不冗余**：修 bug 同时做收敛型重构（重复样板上移、死代码删除），禁止复制粘贴式修补。
3. **零迁移**：不新增 alembic 迁移、不改表结构（唯一例外：P1 权限码只动 RESOURCE_CATALOG 常量与种子脚本逻辑，不建新表）。
4. **零外部动作**：不部署、不连业务库、不执行 git commit/push/索引操作（`git mv` 亦禁用）；发布由主 AI 另行执行。
