## 2. 已观察到的两类错误

### 2.1 G6 图引擎错误

用户最初提供的核心异常为：

```text
[AdvancedRelationGraph] init failed: Error: Edge already exists: 2360267796d30d9a9977d94b910bda5c
```

调用栈来自旧图谱包 `AdvancedRelationGraph-VYRod6-S.js`，位置在 G6/Graphlib 的 `addEdges/doAddEdge`。该异常会触发页面的 G6→SVG 回退逻辑，是图谱问题的有效证据。

### 2.2 无关的外网头像错误

```text
Failed to load resource: net::ERR_NAME_NOT_RESOLVED
https://xiaoxian521.github.io/hyperlink/svg/smile5.svg
```

该 URL 来自 `frontend/src/layout/components/lay-notice/data.ts` 的模板通知头像，不属于关系图谱数据或 G6 资源。内网无法解析该域名会产生控制台红色错误，但不能解释 `Edge already exists`，也不能单独解释图谱无法打开。

## 11. 根因定位与修复验收记录（2026-08-06）

### 11.1 根因（已用生产数据 + 真实 Chrome 复现确认）

`frontend/src/views/asset/components/AdvancedRelationGraph.vue` 的 `nodeLabel()` 把节点 `label` 字段当字符串使用，但组件内部 `normalizeGraphData()` 已把 `label` 覆盖为 echarts 风格对象 `{show, formatter, ...}`。该对象被原样传给 G6 的 `labelText`，G6 文本布局对非字符串调用 `.split`，抛：

```text
[AdvancedRelationGraph] render failed: TypeError: F.split is not a function
```

这导致 G6 初始化必然失败（08-05 的边 ID 修复消除了更早暴露的 `Edge already exists`，本错误是其后的下一个阻断点）。该故障只在真实 G6 Canvas 运行时出现，typecheck/Vitest（jsdom）无法覆盖——这正是此前"测试全过但用户仍打不开"的原因。

### 11.2 取证链（按 S0–S3 执行）

1. S1 发布链路：nginx 日志确认用户浏览器（10.10.6.56）07:47 已加载当日新 chunk `vsPqY6kp` 且三个图谱 API 全部 200（响应 210KB），排除缓存/发布问题，定位为浏览器运行时故障。
2. S2 生产响应脱敏提取：容器内直接调用接口函数（绕过 HTTP 认证、只读），默认视图 127 节点/106 边；重复节点/边 ID=0、空端点=0、自环=0、孤儿边=0、物理键全部 5 段——数据形状健康，排除数据根因。
3. S2/S3 离线复现：`frontend/repro/` 最小复现页 + 生产脱敏响应 + 本机真实 Chrome（CDP），G6 引擎稳定复现 `split is not a function`；同数据 SVG 引擎 127 节点/106 边正常。
4. 修复后同一复现链路确认 G6 渲染成功（renderError=false、canvas 建立、0 错误）。

### 11.3 修改内容（最小修复）

`AdvancedRelationGraph.vue`：

1. `nodeLabel()` 排除对象形态 label（取 `label.formatter` 或回退中文字段/表名/ID），保证 `labelText` 必为字符串（约第 78–86 行）。
2. 布局由 d3-force 换为 `force-atlas2`（`layoutOptions()`，约第 123–130 行）：旧 force 配置在 127 个 132px 宽节点下不扩散、全部堆叠不可读；force-atlas2 依赖节点尺寸排重叠，收敛后结构可读。radial 模式不变。

回归测试：`frontend/tests/advancedRelationGraph.test.ts`（Mock G6 Graph 捕获 setData 输入，断言 labelText 为字符串且非 `[object Object]`、渲染边 ID 不复用后端证据 ID）。
