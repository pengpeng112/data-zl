# 188 · 未探索业务数据库只读探索执行计划（结构关系、容量、基础分类分级与值域）

## 0. 目标、范围与完成含义

让后续 AI 按顺序完成各系统数据库盘点，说明“有哪些库、表、字段，业务主线是什么，表如何关联，规模有多大，哪些资产核心，编码是什么意思”，形成可追溯、可导入当前平台的资产包。

**业务源库全程只读、零 DML/DDL、零建对象、零改权限、零改统计信息。只读不等于无负载；扫描范围、并发、超时、取消和停机条件必须同时受控。不得承诺绝对零影响。**

本轮交付分两步，尽量连续推进，不在每个系统完成后重复询问：

1. **步骤一 S0—S9：只读探索与入库准备。** 完成已授权范围内的源库低负载元数据采集、离线结构分析、容量统计、分类建议、值域候选、平台差异预览和隔离验收。没有源库窗口时先完成平台元数据和离线工作。平台生产业务资产保持不写；既有受控通道的正常审计不得关闭。
2. **步骤二 S10—S11：批准后纳入平台并回读验收。** 仅将批准的元数据及候选写入数据资产平台；业务源库仍只读。平台 apply、迁移、发布和人工治理终态分别遵守批准门禁。步骤一结束只集中提交一次具体批准材料；批准已覆盖的项目连续执行，不逐库重复索取。

“只读探索完成”“入库材料就绪”“已纳入生产平台”“人工确认完成”分别记录。生成 JSON 不算已入库，关系候选不算正式关系，受阻不算已完成。

### 2.2 允许与禁止

**允许：** 经平台登记通道读取数据字典、现有统计及空间元数据；离线解析安全处理后的定义；经批准且满足预算的键限定只读验证；本地证据整理、脚本适配及已核实隔离库测试。

**禁止：** INSERT/UPDATE/DELETE/MERGE/TRUNCATE、SELECT INTO建表、DDL、建临时表/视图/索引/函数、GRANT、执行存储过程/触发器/动态SQL、锁表/SELECT FOR UPDATE、统计刷新/ANALYZE/VACUUM/DBMS_STATS、EXPLAIN ANALYZE、Oracle EXPLAIN PLAN写PLAN_TABLE、服务器或源库参数修改、业务源写修复。

- SELECT内调用不明函数/有副作用函数、序列NEXTVAL、DBLINK或远程外部访问同样禁止。SQL须经既有守卫验证，不能只判断首词SELECT。
- 视图/过程/触发器定义只作为文本证据读取，绝不执行。元数据定义、默认值和注释也可能含凭据、患者字面量，必须先脱敏。
- Oracle只读事务、PG/MySQL只读事务及会话级超时，仅通过已经核实的连接器会话初始化白名单建立；SQLServer不假设存在等效的通用只读事务开关。应用只读守卫与受控账号共同约束。
- 只读账号权限不足时，不换管理员、不改账号、不申请后立即自行授权。`USER_*`只代表登录账号自己的对象；只读账号名下0表不能作为业务库为空的证据。
- 不关闭审计。不把填上`source_writes=0`当作验证；必须有执行SQL指纹、通道、会话保护、返回/取消记录支持。
- 不主动持有显式锁；普通SELECT仍可能产生引擎内部锁、I/O和缓存压力，按§3管理。

## 3. 低负载执行预算与熔断（先过此门，再采集）

以下是本计划的**保守初始上限，待执行器能力验证**；来源技能/DBA限制更严则取更严值。不是数据库性能保证，也不是绕过通道默认门禁的理由。

| 项目 | 初始上限/规则 |
|---|---|
| 全局源端并发 | 全部源合计1条在途查询、1个采集工作会话；共享实例/RAC/多schema共用预算 |
| 登录 | 连接超时5秒；失败一次记录；无外部恢复证据不重复试登录 |
| SQL执行 | 单条目标5秒，锁等待可配置时≤1秒；既有90/120秒默认值不直接采用 |
| 元数据分批 | 每批≤100对象、返回≤2000条元数据；字段/索引多时按稳定键续页，定义按对象单取 |
| 分页 | 用字典自然键/对象ID继续；避免高OFFSET、重复全字典排序与多次COUNT计算总页数 |
| 节流 | 每条结束间隔至少2秒；每50条休息60秒，并检查预算、窗口及异常 |
| 每源每次 | ≤500条SQL、累计数据库执行≤10分钟、墙钟≤45分钟；任一达到即保存断点（同一次连续执行内预算独立的下一源可继续） |
| 全局并发与总量 | **v2.1（用户授权2026-09-13）**：剩余10源一次性连续顺序执行，取消"每夜≤3物理库/2小时"上限；全部源合计并发仍=1；驱动器总墙钟上限6小时（防挂死护栏，非负载预算）；熔断规则不变，冻结对应物理源后继续队列内其他源 |
| 定义文本 | 单对象≤256KiB；超限标记截断，不循环拼出超大定义，不输出原文到聊天 |
| 业务键验证 | 默认不执行；需要时每源每夜≤10候选、每候选≤2条SQL、驱动键≤50、返回聚合/安全枚举≤100行；全部计入上面总预算 |
| 超大表 | 估算超过1000万行的批量普查仅元数据；统计缺失/陈旧且无可靠量级证据的也按高风险处理 |

### 3.1 每条SQL提交前的六项检查

1. 目标库/owner/对象在本批白名单；条件参数受控；无敏感字面量泄漏。
2. 语义只读，无UDF副作用、锁、过程、跨源调用。
3. 元数据查询已按schema/对象分段，不连出笛卡尔放大；索引/列按完整复合键及序号关联。
4. 若读取业务表，必须有可用索引的业务键或可证实的有限分区/时间范围，过滤保持可索引；子查询和JOIN两侧都受控。
5. 超时、服务端取消与结果关闭可用，剩余预算足够；不能仅依赖网络read_timeout。
6. 审计记录包含SQL模板/指纹、参数范围摘要、预算、预计访问依据；患者键只保存在受控执行器内，不进入证据正文。

估算行数、返回上限与WHERE日期条件均不能单独证明低成本。禁止全表COUNT、无界DISTINCT/GROUP BY/COUNT(DISTINCT)、全表MIN/MAX、ORDER BY随机抽样、大范围相关子查询、视图全量执行。不要用NOLOCK作为安全替代。

### 3.2 执行计划和超时的处理

- 优先使用已有索引/分区元数据和已留存计划证据；确需计划时仅使用已核实不写入、不执行目标查询的引擎路径，逐库版本适配，不能统一下发EXPLAIN。
- Oracle禁止本计划执行EXPLAIN PLAN；无现成计划且不能证明访问范围，业务验证留待核实。
- 源端驱动超时可能只是客户端不再等待。先在本地/隔离环境验证取消路径，再在首批小字典查询验证连接清理；不能用源库SLEEP或昂贵查询测试超时。
- 不能确认取消能力的源仅做已证实低成本的身份/有限元数据读取；业务统计与扩大批次保持BLOCKED_CANCEL_CAPABILITY。
- 达到超时立即取消**本任务语句**并关闭本任务连接；取消结果未知时冻结该物理实例队列，转DBA协助确认。不得擅自KILL其他会话。

### 3.3 熔断与恢复

以下任一出现立即暂停该物理源：一次查询超时/明显锁等待、ORA-04030或类似内存错误、业务卡顿反馈、取消状态不明、主机/数据库已有监控告警、查询耗时连续3次超过试点中位数2倍、预算耗尽。

监控有权限且已经可用时只读复用已有仪表；不另开高频性能探针，不假装没有监控就证明没有影响。出现全局服务器异常暂停全部源队列。权限错误停止对应对象/能力；网络认证失败停止该源；不能证明共享实例独立时先暂停相关队列。

不在故障后立即“降级换字典再试”。记录原因、SQL指纹、耗时、取消状态和已完成分片；性能故障需DBA/运维确认恢复或后续明确批准，才在更小批次续跑。仅预算耗尽可在后续已批准窗口自动续跑。无异常且预算足够时正常进入下一系统。

## 5. S3—S4：表字段底座与关系理顺

### S3 结构元数据

成功系统覆盖白名单内全部对象；“全部”指最终多批覆盖，不要求单次全量SQL。

- 物理身份：数据库/服务/PDB、source、namespace、owner、引擎版本、统计/采集时间。
- 表与视图：原始名称、类型、注释、是否分区、临时/历史/日志/系统组件线索；权限不可见与不存在分开。
- 字段：原序号、类型、长度/精度/小数位、可空、默认值、注释、计算列、标识列等。
- PK/UK/FK：完整列序、引用目标、启用/验证状态；不把禁用或不可信FK当现行数据保证。
- 索引：owner+表+索引+列序，唯一性、过滤/表达式/包含列能力按库型注明；不能仅按索引名JOIN。
- 视图/同义词/依赖：定义可见状态、对象级依赖、跨库引用；物化视图存储单列，普通视图无独立基础行数。
- 快照为每项保存来源方法、时间、partial/error；字段缺项用null和原因，不能填猜测值。

Oracle SYSTEM等内部owner原则排除；历史已证实业务对象位于SYSTEM时按已有对象白名单采集，不排空整个业务，也不扩为整个SYSTEM。CDB/PDB、SQLServer多数据库、PG数据库+schema、MySQL数据库按真实身份建层级。

### S4 离线关系分析

1. 读取当前正式关系/候选/配方并查重，不依赖聊天记忆。
2. 声明FK保留方向、完整组合键及验证状态，作为结构证据；实际数据覆盖率未知时明确未知。
3. 视图定义按方言解析FROM/JOIN、旧式WHERE关联、CTE、别名、UNION分支、嵌套查询、CASE映射与过滤；视图依赖表不等于字段JOIN关系。
4. JOIN条件保留全部字段配对、连接类型、状态/日期/非空限定、类型转换和粒度；多表去重/聚合才能成立的进入配方草稿。
5. 过程/触发器仅在业务主题有缺口且定义读取获准时离线分析。动态SQL、临时对象、加密/缺失/截断定义列unresolved，不猜补。
6. 同名同型字段仅作为线索；不自动生成全库两两匹配，也不凭名称假设PATIENT_ID跨系统相同。
7. 跨实例关系为D类待验证，未经验证和审核不进正式推导；不为验证建立或调用DBLINK。
8. 每源形成业务主线：主实体→事件/就诊→明细→结果/报告→字典，逐节点标注真实对象、粒度、键、证据、冲突。主线不适用于该业务时如实调整。

关系证据字段至少含：source/system/namespace、from/to对象及列数组、join_type、qualifiers、evidence_kind、SQL脱敏指纹、metadata_snapshot_id、existing_relation_id、intake_status、confidence、validation_scope、review_required=true。

仅凭独立两张表各取100行再求交集不能验证关系。确需验证时，用同一受控父键集限制双方，检查父键重复、子键覆盖、匹配计数/放大；多对多且fanout不可控的停止。只报告范围内结论，不推广为全库完整性证明。

## 6. S5：每个数据库的数据量与容量

### 6.1 三层输出与统一口径

| 层次 | 必交付内容 |
|---|---|
| 物理数据库 | 引擎、唯一身份/别名、业务归属、估算行数汇总、表数据/索引/LOB占用、文件已分配空间、日志空间（能读才填）、统计日期/覆盖率 |
| schema/owner | 基础表/视图数、已知/未知行数表数、估算行数合计、已知表占用合计、共享/不可归属对象 |
| 表 | 估算行数、统计来源/日期、数据/索引/LOB/合计字节、是否包含分区或下属对象、缺项原因 |

字节使用整数bytes，展示GiB=bytes/1024^3；保留原值。估算行数跨表相加只表示物理记录条数，不是患者数/就诊数。普通视图不加行数；同一表的非聚集索引不加记录数；分区父与子不得双加。

数据库“文件分配空间”不等于业务数据占用；日志、空闲、临时区分别标注，不塞进业务表总计。无法在共享库中精确归属时报告共享池/未知，不平均分配。影像文件、对象存储、附件目录不在SQL数据库大小内；本计划不扫描文件系统，明确“外部文件未计入”。

### 6.2 按库型取现成统计（能力验证后执行，不是可直接复制的SQL）

| 引擎 | 估算行数来源方向 | 空间来源方向及陷阱 |
|---|---|---|
| Oracle | 可见的ALL/DBA/USER_TABLES NUM_ROWS、LAST_ANALYZED及适用分区统计 | 已授权SEGMENTS/文件字典；表、索引、LOB及分区按唯一segment映射；allocated bytes不冒充实际有效内容大小；USER_*仅登录owner |
| MySQL/MariaDB | information_schema.TABLES TABLE_ROWS，按引擎注明估算性质 | DATA_LENGTH/INDEX_LENGTH；DATA_FREE可能为共享空间不可逐表累加；不把表统计合计称磁盘文件总量；若读取字典触发昂贵统计则缩批或停 |
| SQLServer | sys.partitions等既有元数据，只计heap/clustered基础行（常规index_id 0/1），按分区求和 | 可访问分区/分配页及文件元数据；pages按引擎页大小换算，防allocation JOIN重复、LOB重复；无权限不调用sp_spaceused或DBCC补齐 |
| PostgreSQL/兼容库 | pg_class.reltuples或已授权pg_stat_user_tables估计；负值/缺失为未知 | 已核实只读的relation/table/index/database size接口或可用目录统计；逐对象限流，父分区与子表/TOAST按包含规则去重；国产兼容差异记录 |

执行AI须按实际版本核对目录字段、权限和含义，可查厂商官方文档；禁止凭上表拼出未经验证的查询。取不到数据库级空间时交付已知表空间下界与覆盖率，不升级权限、不COUNT补齐、不运行刷新统计命令。

### 6.3 数据质量和去重

- 每个度量含`metric_name/value/unit/method/collected_at/statistics_at/coverage/status/reason/includes`。
- 行数默认`estimated`；即使某引擎统计接近准确，也不能写“实时精确”。未知=null，不写0；陈旧统计中的0也不证明空表。
- 首轮将行数统计超过7天或日期不明标记stale/unknown_age，作为风险提示，不触发自动刷新。该7天是本计划展示阈值，不是统一数据库统计更新要求。
- 汇总披露已知表数/总表数、已知估算合计与未知表数；部分容量不直接排完整容量名次，TOP列表注明仅已知范围。
- RAC双节点同一DB只计一次。HIS源与ODS副本可分别展示物理占用，但不能把跨系统记录合计称唯一业务数据量；共享实例多系统先列物理总量再列可归属部分。
- 187中的表/字段计数是资产覆盖数，不能转换成数据库GB。

## 7. S6：基础业务分类与核心分级

### 7.1 分类维度

业务分类先用有限集合：患者与就诊、诊疗医嘱、检验检查与报告、手术麻醉、护理、药品物资、费用医保、病案质量、运营办公、基础字典、技术支撑、待判定。系统可多域；每表一个主域，可附次级标签。

对象角色另记master/detail/event/result/dictionary/mapping/config/log/history/staging/unknown；粒度另记“一患者/一次就诊/一张申请/一条明细”等，证据不足写未知。字段继承表的业务域，但主键、业务键、状态值域、时间、金额、描述和敏感属性可独立标注。

### 7.2 核心分级规则（版本basic-v1）

| 分级 | 判据 | 示例与限制 |
|---|---|---|
| 核心 core | 当前业务主要实体、关键过程/结果/结算；或其不可缺少的明细、主数据/字典/映射；有现行业务定义、已确认查询/视图链或人工证据 | 就诊主表、检验报告、费用明细、关键状态字典；表小或无FK也可核心 |
| 非核心 non_core | 有证据表明是可替代技术辅助、非关键展示缓存、非主业务临时中间数据等，且不承担关键审计/追溯 | 不能仅凭LOG/TMP/BAK名称、低引用、0行统计或历史日期判非核心 |
| 待判定 undecided | 缺业务含义、用途冲突、只靠命名推测、定义/权限不足 | 是待处理状态，不强制塞入非核心 |

- 重要性与数据量、探索优先级、关系置信度A/B/C/D、数据敏感性是不同维度，不互相替代。
- 日志可能是关键审计，历史表可能是唯一追溯依据，字典可能决定业务解释；依赖核心流程的对象要检查遗漏。
- 核心/非核心均为首轮建议`review_status=proposed`，附reason、evidence_refs、rule_version、confidence、reviewer、reviewed_at。不能设置confirmed冒充人工确认。
- 不用表级核心标签推导每个字段都核心；字段首轮只标关键业务角色即可，不要求逐列人工分级。
- 不覆盖现有人工确认结论。冲突形成diff，保持旧版本可追溯；不删除非核心表，不改变查询权限，不把分类用作自动清理规则。

### 7.3 全量覆盖策略与验收

B类按新元数据判断；A类及其他当前平台系统按既有注释、业务说明、关系/视图/认证查询判断，缺项列待判定，不自动重采。每个系统及表都有建议或明确待判定原因。容量/关系引用度仅帮助排序人工复核，不能单独决定核心性。

先交付核心表清单、核心依赖字典/明细清单、非核心建议、待判定清单及每系统统计。第一轮可以待判定较多，但覆盖分母与证据不得缺失；人工先审核心业务主线和冲突，不要求本轮确认所有字段。

## 8. S7：值域发现、取证和复用

### 8.1 取证顺序

1. 读取平台`GET /api/v1/ai/system-context?system_code=...`的confirmed值域与陷阱，保留version_no；注意分页/截断，不能把响应前50张表当系统全量。
2. 平台不可用时回退同源离线值域资产，超过max_age_days=7标注陈旧；148是导出参考，不手改。
3. 离线分析CHECK约束、字段注释、已读取视图CASE/DECODE、字典FK、既有认证SQL与厂商说明。CHECK只证明允许形式/值，不自动证明业务中文含义。
4. 缺少含义且存在已确认字典关系时，生成该字典按业务键/代码范围限定的查询。通过§3及通道审批后读取必要code/meaning/有效期字段，不SELECT *。
5. 字典覆盖无法证明、无安全访问条件或可能含敏感内容，保留待确认；不对全部编码列运行DISTINCT或分组普查。

### 8.2 第一轮范围与值域合同

对所有字段做离线候选识别；优先核心表的状态、类型、来源、有效/作废标志、就诊类别、收费医保、报告审核等。首轮每源最多选择20个高价值字段深入整理证据；其余仍在候选清单，有优先级和缺口。需要源端业务验证时还受每夜≤10候选总预算限制，不因20字段突破预算。

每条至少记录：system/source/namespace/schema/table/column、domain_kind、原始code字符串、meaning、scope_condition、有效起止/版本、来源字典键、证据类型及定位、采集时间、统计范围、status、冲突说明、review_required。

- 字符串"01"、"1"和数字1不能随意合并；NULL、空串、空白、0、未知、其他、作废分别处理，遵循实际引擎语义。
- 同名字段在不同系统/owner/表可能不同义；同一个字典被不同类型限定时保留联合字典键与条件。
- 视图映射可能仅适用于某个过滤子集或历史版本，不能升级为全局口径。
- enum/range/trap/mapping等domain_kind实际取值以现行平台合同为准；计划的说明类型先做适配，不自行往生产塞未知枚举。
- 新观察到的code≠已确认meaning；样本未见值≠不存在该值。频次只描述已限定样本，不外推全库分布。
- 确认值域保持confirmed原版本；新证据进pending候选、冲突保留conflicted；确认/裁决由人工，AI不自动升终态。
- 患者标识、姓名、证件、电话、地址、自由文本、诊断叙述不作为枚举样本输出；必要验证在执行器内完成，仅保留安全汇总。字典名称/含义也先过敏感检查。

**验收：** 每源有候选字段总数、已复用confirmed数、pending数、冲突数、因负载/权限延期数，以及最优先待人工确认项；不能只交“值域已获取”一句话。
