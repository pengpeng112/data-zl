## 0. 复核结论与本版修订

原计划方向成立，但不能原样执行。本次逐项核对前端、后端路由、DTO、权限种子和 144 当前未提交成果后，作出以下确定性修订：

| 原计划问题 | 最终裁决 |
|---|---|
| 标称“5 阶段 27 个任务” | 实际为 `5+4+3+5+11=28` 个任务组，本版按 28 组管理 |
| query-center 迁出 `/asset/queries` | 不迁 canonical 路径；保留 `/asset/queries`、`/asset/queries/accuracy` 和 144 已有实现，只做权限、API 层与体验收口 |
| systems 的 `system_type` 复用 `dbTypes` | 禁止；前者是 HIS/ODS/EMR 等业务系统分类，后者是 Oracle/PostgreSQL 等数据库类型 |
| diff 页直接消费现有 `/metadata-changes/diff` | 不可行；现接口会持久化事件且不返回 changes，新增无副作用的字段级 `diff-preview` 契约，原生成接口保留并幂等化 |
| dict/general 只补页面 CRUD | 不可行；前端 `/dict-general` 与后端 `/dictionaries`、字段名、导入体均错配，先统一契约再补界面 |
| persons 只拆前端筛选 | 不可行；后端必须新增独立 `classification` 参数并保留旧 `person_type` 兼容语义 |
| 后端 9 项均“待确认” | 已核清：配方流转和 query 权限资源已有；其余缺口按第 7 章实施，无需再次询问 |
| 参数 JSON 解析失败保持现状 | 改为阻断提交并提示字段错误；这是确定性输入校验，不是二次确认 |
| 快照“删除” | 改为受保护的归档/软删除语义，保留引用保护和审计，禁止物理删除 |
| 每个 catch 一律弹消息 | 只治理用户触发的请求/写操作；用户取消、剪贴板降级、JSON 探测等预期分支不得误报 |
