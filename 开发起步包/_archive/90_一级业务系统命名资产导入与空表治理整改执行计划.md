# 一级业务系统命名、资产导入与空表治理整改执行计划

## 1. 整改目标

本计划解决以下三个相互关联的问题，执行 AI 不得只改前端文字：

1. 所有出现“第一层业务系统”的页面和接口，都必须以 `asset.asset_systems.system_name_cn`（系统总览名称）为唯一显示名称来源，不再各自维护名称映射。
2. 表资产取消“其他业务系统”这一虚拟父级。Docare 手术麻醉、嘉和电子病历、LIS、PACS、移动护理、无纸化病案、超声内镜等必须与 HIS、HRP、数据中心平行展示。
3. 将本地已完成探库的表、字段、关系、中文名称来源和连接引用完整、幂等地导入平台；经只读存在性核验确认数据行为 0 的对象不进入平台资产目录，该规则覆盖当前及以后所有数据库类型和业务系统。

本轮是平台资产库和展示层整改。业务源库严格只读，只允许元数据查询和受限 `SELECT` 存在性探测，禁止任何 DML/DDL。

本计划已吸收 91 号复核报告。91 中提出的环境、编码、历史口径、迁移和空表风险均已在下文裁决；执行 AI 不得再次停在“需要用户确认”，也不得恢复 74/76 的旧展示方案。

## 2. 统一业务口径

### 2.1 唯一的一级系统集合

一级节点以系统总览中的有效物理业务系统为准，当前应为：

| system_code | 系统总览标准中文名 | 一级展示要求 |
|---|---|---|
| `HIS_SOURCE` | HIS | 平行一级节点 |
| `HRP` | HRP | 平行一级节点 |
| `DATA_CENTER` | 数据中心 | 平行一级节点；ODS 只能作为其连接、库或 Owner 语义出现 |
| `JHEMR_VASTBASE` | 嘉和电子病历 | 平行一级节点 |
| `DOCARE` | Docare手术麻醉 | 平行一级节点 |
| `MOBILE_NURSING` | 移动护理 | 平行一级节点 |
| `LIS_SOURCE` | LIS | 平行一级节点 |
| `PACS_SOURCE` | PACS | 平行一级节点 |
| `PAPERLESS_CDMS` | 无纸化病案 | 平行一级节点 |
| `ULTRASOUND_ENDOSCOPY` | 超声内镜 | 平行一级节点 |

最终名称必须从生产平台 `asset_systems.system_name_cn` 读取；上表用于回填、测试和异常兜底，不允许成为前端第二套硬编码名称。若系统总览名称以后被管理员修改，数据库连接、数据资源树、表资产、关系复核和图谱应自动同步显示新名称。

### 2.2 历史口径冲突的最终裁决

以下为本轮确定口径，替代 74/76 中“一级系统仅 HIS/HRP/数据中心”的旧展示结论：

1. **独立源端与数据中心镜像并存**：独立 LIS、PACS、Docare、嘉和电子病历、移动护理是一级业务系统；数据中心内的 `LIS/PACS/SM/JHEMR/YDHL` 是数据中心 Owner/镜像区。二者不能合并、不能重复冒充一级系统，关系用同步/镜像血缘表达。
2. **物理连接去重仍有效**：同一一级系统内按真实 `connection_identity_key` 去重；不同物理源即使表名相同也不能合并。76 的连接去重逻辑保留，但不再用于把独立业务系统降为数据中心 Owner。
3. **ODS 不是第十一个一级系统**：原表资产的 ODS 一级标签统一显示为“数据中心”，ODS 仅是其下 Owner/Schema/库语义。
4. **总览人工名称优先**：现有非空且人工确认的 `system_name_cn` 不被 AI 猜名覆盖；只有旧默认名、空名和本计划明确的标准化对象才允许在 dry-run 清单确认后回填。此后所有页面实时读取总览名称。

### 2.3 system_code 权威映射与旧码处理

| 旧码/别名 | 权威 system_code | 处理规则 |
|---|---|---|
| `HIS` | `HIS_SOURCE` | 旧码标记 merged/alias，资产与连接重挂权威码 |
| `EMR` | `JHEMR_VASTBASE` | 仅独立嘉和源端；数据中心 MTL/JHEMR Owner 不迁出 DATA_CENTER |
| `LIS` | `LIS_SOURCE` | 仅独立 LIS 源端；数据中心 LIS Owner 仍属 DATA_CENTER |
| `PACS` | `PACS_SOURCE` | 仅独立 PACS 源端；数据中心 PACS Owner 仍属 DATA_CENTER |
| `SM` | `DOCARE` | 仅独立 Docare 旧码；数据中心 SM Owner 仍属 DATA_CENTER |
| `YDHL` | `MOBILE_NURSING` | 仅独立移动护理旧码；数据中心 YDHL Owner 仍属 DATA_CENTER |

迁移必须先输出逐行映射、资产数、连接数、冲突和孤儿。禁止只按短码全局替换；必须结合物理 source/endpoint 判断独立源端还是数据中心镜像。旧系统行若仍被历史审计引用则软标记 `merged` 并保留 `canonical_system_code`；不得破坏历史记录。

### 2.6 统一展示层级

所有页面复用同一层级：

```text
业务系统（system_name_cn）
  └─ 数据库连接（IP:端口 / database 或 service）
      └─ Schema/Owner 中文用途（物理名称）
          └─ 表中文名（物理表名）
              └─ 字段中文名（物理字段名）
```

具体规则：

- 第一层不得出现“其他业务系统”“平台元数据系统”“HIS 源端系统”“HRP 源端系统”等人为大类。
- 表资产当前显示的 `ODS` 一级项改为系统总览标准名“数据中心”；ODS、HIS、CDA、MTL、JHEMR、YDHL、SM、LIS、PACS 等只作为数据中心连接下的库/Owner/Schema 节点。
- 独立源端的 Docare、嘉和电子病历、LIS、PACS、移动护理等与“数据中心”平行，不能因为表资产分类函数未识别而落入兜底组。
- 一个系统可有多个物理连接；同一 `connection_identity_key` 只显示一次，但其下的多个 database/service/Schema 不得丢失。
- 系统编码、source_code、物理库名用于接口定位和辅助说明，不得替代一级中文名称。

### S4：建立全数据库类型的非空对象核验规范

“0 行不记录”必须依赖可靠证据，不能直接信任陈旧统计量：

1. 表对象：统计值明确大于 0 可直接标记 `nonempty_by_stats`；统计为 0 或未知时，执行只读、限时、最多返回 1 行的存在性查询。
2. Oracle：`SELECT 1 FROM owner.table WHERE ROWNUM <= 1`；使用 thick 模式，设置 statement timeout/call timeout，不做 `COUNT(*)`。
3. PostgreSQL/Vastbase：`SELECT 1 FROM schema.table LIMIT 1`，事务只读并设置 statement timeout。
4. MySQL：`SELECT 1 FROM db.table LIMIT 1`，只读会话。
5. SQL Server：`SELECT TOP (1) 1 FROM [db].[schema].[table] WITH (NOLOCK)`，READ UNCOMMITTED；不跨未授权数据库。
6. 视图：不能用系统统计判断。允许在安全名单内执行同样的限 1 查询；超时、权限不足或依赖失效均记为 `unknown/blocked`，不得当作 0 删除。
7. 大表只做存在性查询，禁止 `COUNT(*)`、无条件聚合或扫描；`HIS.LAB_RESULT` 等仍遵守仓库专项限制。
8. 只有探测成功且确认为“无返回行”的对象才是 `confirmed_empty`；超时、连接失败、权限不足、统计未知均不是空表。
9. 核验输出只保留对象标识、状态、耗时、错误类别和时间，不保留任何业务数据样本。
10. 默认单连接并发不超过 2、单对象超时 5 秒、重试最多 1 次；夜间窗口执行。某来源连续 10 个对象超时则熔断该来源，其余对象标记 `blocked`，不得继续施压源库。
11. `HIS.LAB_RESULT` 等大表不执行通用存在性探测，沿用已知活数据证据直接标记 `nonempty_by_evidence`；其他重视图默认 `unknown`，只有白名单视图才执行限 1 查询。
12. 行存在状态需要持久化时，在 `asset_tables` 增加 `row_presence_status/checked_at/method/error_code`，迁移必须手写并保留 downgrade；不保存业务样本。

### S6：本地探库成果全量导入与历史零表清理

1. 平台库先做可恢复备份并记录文件、大小、SHA-256、当前 Alembic head。
2. 对各本地快照先运行存在性核验；无法重连的来源不得把统计 0 直接认定为空，只列待核。
3. 运行统一导入 dry-run，按十个系统分别输出：新增、更新、不变、确认空表排除、未知保留、字段排除、关系排除、冲突、孤儿。

7. 全程统计 `business_source_writes=0`；发现任何源库写意图立即停止。
