# 业务系统、数据资源与关系图谱一体化整改计划

## 1. 整改目标

本轮不再把“系统总览”“数据源与库”“表资产”作为互相割裂、概念重复的页面。平台统一围绕真实数据库连接组织资产：

`业务系统 → 数据库连接/库实例 → Schema/Owner → 表 → 字段`

同时重构关系图谱，使用户进入页面后可以明确知道：图中展示什么、如何筛选、如何定位表、如何查看上下游、线条代表什么、点击节点或关系后能做什么。

最终目标：

1. 一级业务系统严格按真实目标数据库 IP 归并，当前固定为 HIS、HRP、数据中心三个。
2. 同一 IP 上的多个 service/database/schema 不重复创建系统，而作为该系统下的库实例或命名空间。
3. 系统详情中直接查看和配置数据库类型、地址、端口、服务名/数据库名、用户名凭据状态、连接模式、环境、启用状态和最近检测。
4. 密码可在系统中设置或更新，但永不明文回显、永不进入平台业务表、日志、Git 或文档。
5. 数据中心中的 LIS/PACS/YDHL/SM/JHEMR/CDA/ODS/HIS 等按 Owner/Schema/业务域展示，不作为一级系统。
6. 未来接入 LIS/PACS/移动护理/手麻独立源库时，按其真实目标 IP 自动或人工建立新的一级系统，不和数据中心镜像混淆。
7. 数据资源页面使用稳定、易理解的树形导航和详情布局。
8. 关系图谱可以稳定显示，无错行、重叠、空白和错误归组，并提供功能说明、图例、空状态和诊断信息。

## 2. 当前实现核查与问题定位

### 2.1 页面和菜单割裂

当前前端路由：

| 路径 | 当前页面 | 问题 |
|---|---|---|
| `/asset/systems` | 系统总览 | 只维护 `system_code/system_name/system_type/status`，看不到所属数据库连接和资产数量 |
| `/asset/sources` | 数据源与库 | 单独维护连接、采集和快照，系统信息与连接信息来回切换 |
| `/asset/tables` | 表资产 | 已有五层树，但使用“系统大类/系统库/Owner”等多套概念，用户难以理解 |
| `/asset/graph` | 关系图谱 | 功能多但缺少任务引导；双引擎、标签和布局存在显示风险 |

系统页面和数据源页面分别直接调用 `/api/v1/systems` 与 `/api/v1/sources`，没有聚合详情接口，也没有统一页面状态。

### 2.2 业务系统分类不符合真实连接口径

当前 `_classify_asset_source()` 会根据 `system_code/source_code` 把 LIS、PACS、EMR、移动护理、手麻等划入独立或周边分类；主数据中心源又按 Owner 拆成多个“抽取区”。这些分类适合描述数据中心内部主题，但不应成为一级业务系统。

当前正确一级系统口径：

| 一级系统 | 真实目标 | 当前数据角色 |
|---|---|---|
| HIS | HIS 业务库真实目标 IP | HIS 多 Owner 业务源端 |
| HRP | HRP 业务库真实目标 IP | HRP 源端；待完成直连补采 |
| 数据中心 | 数据中心真实目标 IP | 汇聚 ODS；内部含 HIS/LIS/PACS/YDHL/SM/JHEMR/CDA 等 Owner/Schema |

注意：跳板机 IP、应用服务器 IP、Nginx 地址不是业务系统身份。归并使用数据库连接最终目标 IP，不使用跳板机地址。

### 2.3 连接配置不完整且安全语义不清

后端 `AssetDataSource` 已有 `db_type/host_masked/port/service_name/database_name/connection_mode/credential_ref`，但当前列表接口没有返回连接详情，前端表单也没有完整展示 service/database/credential_ref，更没有“用户名可见、密码只写”的明确流程。

必须区分：

- 数据库地址和用户名：按权限可查看。
- 密码：只允许设置、更新、清除，不允许读取或回显。
- `credential_ref`：平台只保存安全凭据引用，不保存明文密码。
- 连通性检测：服务端解析凭据，返回状态、耗时和脱敏错误，不返回用户名密码。

### 2.4 数据源与库页面可用性不足

当前页面主要是普通表格 + 平铺 Schema 列表：

- 系统、连接、库、Schema、表没有形成统一层级。
- 缺少系统卡片的资产统计、连接健康、最近采集、异常数量。
- 表格列宽固定，操作区拥挤，层级关系不明显。
- 新增数据源时需要手工输入系统编码，容易产生错误系统。
- 快照和采集结果与连接详情分散。

### 2.5 关系图谱显示和认知问题

当前图谱同时维护 `RelationGraph.vue`（SVG）和 `AdvancedRelationGraph.vue`（G6）：

- 默认引擎是 SVG，但允许切换 G6；两套节点尺寸、标签、布局和事件解析不一致。
- 节点 ID、显示名、表名、Schema、source_code/system_code 多套字段同时参与归一，存在边端点找不到节点或错误归组风险。
- G6 的节点徽标、边标签、固定尺寸容易造成文字错行、遮挡和重叠。
- 图谱区域使用深色容器，而 G6 内部又是浅色画布，视觉不一致。
- 默认加载关系等级和隐藏 D 类规则不直观，用户可能看到空图但不知道原因。
- 工具栏功能很多，缺少“全局关系、上下游、血缘、待验证关系”的任务解释。
- 图例没有解释点击节点、点击边、定位表、深度、方向、聚合和双引擎的用途。

## 3. 统一概念模型

### 3.1 五层定义

| 层级 | 定义 | 示例 | 是否一级系统 |
|---|---|---|---|
| 业务系统 | 以真实数据库目标 IP 为归并主依据的业务系统 | HIS、HRP、数据中心 | 是 |
| 数据库连接/库实例 | 同一 IP 下的端口 + service/database 连接实例 | Oracle service、PostgreSQL database | 否 |
| Schema/Owner | 数据库内部命名空间 | HIS、LIS、PACS、YDHL、SM、JHEMR、CDA | 否 |
| 表 | 资产表或视图 | PAT_VISIT、EXAM_MASTER | 否 |
| 字段 | 表字段 | PATIENT_ID、VISIT_ID | 否 |

“LIS/PACS/移动护理/手麻”只有在未来接入其独立真实数据库 IP 后，才可成为新的一级业务系统。数据中心 IP 下同名 Owner 仍然属于数据中心。

### 3.2 系统身份和归并键

严格执行用户口径：同一真实目标 IP 归为同一系统。

建议字段：

- `endpoint_host_normalized`：规范化目标 IP；域名必须解析/登记对应真实目标，不能用跳板机地址。
- `system_identity_key`：对规范化目标 IP 做稳定哈希或标准化编码。
- `connection_identity_key`：`IP + port + service_name/database_name + environment`，用于区分同一系统下不同库实例。
- `parent_system_code`：数据源所属一级系统。
- `namespace_role`：Owner/Schema 的业务主题，仅用于内部导航。

规则：

1. 新增连接时若目标 IP 已存在，必须挂到已有系统，不能再建同 IP 新系统。
2. 如果用户选择不同系统但输入相同 IP，后端返回冲突并提示现有系统。
3. 同 IP 不同端口/service/database 允许新增不同连接实例。
4. `manual_import` 没有 IP 时必须人工选择系统，并标记 `identity_source=manual`，不能自动生成独立系统。
5. 连接经跳板机时仍以最终数据库 IP 归并，跳板信息只属于连接通道配置。

### 3.3 当前三系统初始化映射

通过一次可回滚的数据迁移/整理脚本完成：

| 旧系统/来源 | 新一级系统 | 内部层级 |
|---|---|---|
| HIS_SOURCE、HIS 真实源端连接 | HIS | 连接实例 → Owner → 表 |
| HRP、HRP 直连或镜像来源 | HRP | 连接实例 → Schema/Owner → 表；镜像需标 `mirror` |
| DATA_CENTER、ODS 主连接 | 数据中心 | 连接实例 → HIS/LIS/PACS/YDHL/SM/JHEMR/CDA 等 Owner → 表 |
| 当前以 LIS/PACS/YDHL/SM/JHEMR 名义登记但实际目标 IP 等于数据中心 | 数据中心 | 只保留为数据中心内部 Owner/业务域，不保留一级系统卡片 |

迁移前必须输出 dry-run：系统数、数据源数、表数、字段数、关系数及旧新编码映射。迁移不得删除元数据、关系或历史快照。

- 最近连通检测、最近元数据采集时间。
- 操作：查看资源、管理连接、检测全部、采集元数据、编辑系统。

不得把数据中心内部 Owner 显示为第四、第五个系统卡片。

### 4.4 连接配置抽屉

字段分组：

**基础信息**

- 所属业务系统（同 IP 自动锁定）。
- 连接名称、连接编码、环境、启用状态。
- 数据库类型。

**目标数据库**

- 真实目标 IP/主机。
- 端口。
- Service Name/SID/Database Name，按数据库类型动态显示。
- 连接模式：direct/jump_host/dblink/manual_import。
- 跳板配置引用，仅展示引用状态，不显示私钥或密码。

**认证信息**

- 用户名：按权限显示或部分脱敏。
- 密码：空白表示不修改；只提供“设置/更新”，永不回显。
- 凭据状态：已配置/未配置/解析失败/待更新。
- 凭据来源：服务器文件/密钥管理/环境变量引用。

**采集与安全**

- 采集模式、Owner 白名单、超时、最大行数、大表策略。
- 强制只读标识固定开启且不可关闭。
- 最近检测状态、耗时、脱敏错误。

保存后先做服务端校验，再允许用户主动点击连接检测；不能在每次打开页面时自动探测业务库。

## 5. 凭据安全方案

### 5.1 禁止的实现

- 禁止给 `asset_data_sources` 新增明文 `password` 列。
- 禁止 GET API 返回密码、Token 或完整凭据内容。
- 禁止浏览器 LocalStorage/Pinia 保存数据库密码。
- 禁止日志打印连接串、用户名密码组合或异常中的密文。
- 禁止前端用星号假值覆盖真实密码。

### 5.2 推荐实现

1. 平台库只保存 `credential_ref` 和可选的 `credential_username_masked`/状态摘要。
2. 新增凭据写入端点使用单独请求模型，密码字段 `SecretStr`，写入服务器安全凭据提供器。
3. 返回只包含：`credential_configured`、`username_masked`、`credential_source`、`updated_at`。
4. 密码为空表示不变；显式“清除凭据”使用独立二次确认操作。
5. 连接检测审计操作者、数据源、结果、耗时，不记录密码和敏感异常全文。
6. 只有平台管理员/数据源管理员可设置凭据；普通资产浏览者只能看脱敏连接信息。

## 6. 后端数据模型和迁移

### 6.1 模型调整

优先复用 `asset_systems` 和 `asset_data_sources`，避免新建重复主表。建议新增：

**asset_systems**

- `endpoint_host_normalized`：一级系统主目标 IP。
- `system_identity_key`：同 IP 唯一。
- `identity_source`：auto/manual/migrated。
- 可选统计字段不持久化，使用聚合查询。

**asset_data_sources**

- `connection_identity_key`：同一连接实例唯一。
- `username_masked`：只存展示摘要；真实用户名随安全凭据保存，或按现有凭据方案决定。
- `credential_status`：configured/missing/invalid。
- `jump_host_ref`：跳板配置引用。
- `readonly_enforced`：必须为 true，不能由普通 API 关闭。
- `last_check_elapsed_ms`、`last_error_code`；错误内容必须脱敏。

如 `host_masked` 实际用于连接真实地址，建议重命名/新增 `endpoint_host` 并明确该字段可被有权限用户查看；API 对无权限用户返回掩码。不要继续让“masked”字段同时承担真实连接地址和展示脱敏两个职责。

### 6.2 约束和索引

- `asset_systems.system_identity_key` 唯一索引。
- `asset_data_sources.connection_identity_key` 唯一索引。
- `asset_data_sources.system_code` 外键或应用级严格校验。
- `(system_code, enabled)`、`(system_code, last_check_status)` 索引。
- 所有迁移手写 `upgrade()`/`downgrade()`，禁止 autogenerate。

### 6.3 数据归并迁移

执行顺序：

1. 生成 dry-run JSON/CSV，列出当前系统、真实 IP、连接、表字段关系数量和目标映射。
2. 检查同 IP 冲突与无法确定真实 IP 的记录。
3. 建立/校正 HIS、HRP、DATA_CENTER 三个一级系统。
4. 更新数据源 `system_code`。
5. 同步更新 `asset_tables/asset_columns` 等冗余 `system_code`，但不改变 `source_code/schema/table`。
6. 关系边通过表/数据源重新计算系统归属；不能凭旧 system_code 推断。
7. 旧 LIS/PACS/YDHL/SM 等系统记录如无独立 IP，先标记 `merged/inactive`，确认无引用后再归档；迁移中不直接删除。
8. 对系统数、连接数、表数、字段数、关系数做迁移前后守恒校验。

## 7. API 整改

### 7.1 聚合查询

新增或扩展：

- `GET /api/v1/systems?include=summary,sources`：返回系统、连接、资产和健康统计。
- `GET /api/v1/systems/{system_code}`：系统详情。
- `GET /api/v1/systems/{system_code}/resources`：连接 → Schema → 表的懒加载骨架。
- `GET /api/v1/sources/{source_code}`：有权限控制的连接详情，不返回密码。
- `GET /api/v1/sources/{source_code}/schemas`。
- 保留现有 `/assets/tree`、`/assets/tree/tables`，但统一业务系统语义。

### 7.2 配置和凭据

- 保留 `PUT /api/v1/systems`，增加 IP 唯一归并校验。
- 保留 `PUT /api/v1/sources`，改为结构化连接配置并校验同 IP 系统归属。
- 新增 `PUT /api/v1/sources/{source_code}/credential`：设置/更新凭据，密码不回显。
- 新增 `DELETE /api/v1/sources/{source_code}/credential`：二次确认清除。
- `POST /api/v1/sources/{source_code}/check` 返回状态、耗时和脱敏错误码。
- 删除系统/连接必须先返回影响分析；默认禁用代替物理删除。

### 7.3 权限

| 操作 | 最低权限 |
|---|---|
| 查看系统和资产统计 | 资产浏览权限 |
| 查看地址/用户名掩码 | 数据源查看权限 |
| 新增/编辑系统连接 | 数据源管理权限 |
| 设置/清除凭据 | 平台管理员或凭据管理员 |
| 连通检测/元数据采集 | 只读探查权限 + 审计 |
| 禁用/删除连接 | 高权限 + 影响分析 + 二次确认 |

## 8. 数据资源树与页面视觉优化

### 8.1 树节点规范

每层使用固定图标和语义：

- 业务系统：服务器/应用图标。
- 连接实例：数据库图标，显示类型和健康点。
- Schema/Owner：文件夹图标。
- 表/视图：表格/视图图标。
- 字段：字段类型图标。

节点副信息只显示一项核心统计，避免一行塞入多个标签导致错位。长名称单行省略，Tooltip 展示全称。

### 8.2 主区设计

- 面包屑明确当前位置。
- 列表表头吸顶，列宽响应式，操作收进“更多”菜单。
- 系统/连接/Schema 层使用卡片或简洁列表；表/字段层使用高密度表格。
- 支持全局搜索表名、中文名、字段名、Owner、连接。
- 搜索结果显示完整路径：`数据中心 / Oracle@目标IP / HIS / PAT_VISIT`。
- 快照、采集、连通检测放进连接详情页签，不在首页同时堆叠。

### 8.3 状态与空页面

- connected：绿色。
- failed：红色并显示脱敏原因。
- not_checked：灰色，提供检测按钮。
- collecting：蓝色进度。
- disabled：灰色禁用。
- 无资产时区分“未采集”“采集失败”“筛选无结果”，不能统一显示“暂无数据”。

## 9. 关系图谱重构

### 9.1 第一阶段：先恢复稳定显示

1. 浏览器复现并记录：API 响应、节点数、边数、容器尺寸、选中引擎、控制台错误和截图。

## 12. 验收标准

### 12.1 系统归并

- 系统页面当前只显示 HIS、HRP、数据中心三个一级系统。
- 数据中心内部 LIS/PACS/YDHL/SM/JHEMR/CDA 等只显示在 Owner/Schema/业务域层。
- 同一真实目标 IP 不能创建两个一级系统。
- 未来独立 IP 数据库可以新增为新业务系统。
- 跳板机 IP 不参与业务系统归并。

### 12.2 连接配置

- 每个系统能查看连接实例、类型、地址、端口、service/database、用户名掩码、凭据状态和最近检测。
- 有权限用户可以设置/更新密码，但所有 GET 响应和页面永不回显密码。
- 连接检测、采集、快照和错误均可追溯。
- 业务源库连接强制只读。

### 12.3 数据资源页面

- 菜单不再同时出现概念重复的“系统总览”和“数据源与库”。
- 层级严格为系统 → 连接/库 → Schema/Owner → 表 → 字段。
- 搜索结果显示完整路径。
- 页面在 1366×768、1920×1080 和窄屏下无严重溢出、错位和操作遮挡。

### 12.4 关系图谱

- 默认进入页面可以显示关系或明确说明为何为空，不能出现无反馈白屏。
- 节点、边、标签无明显错行、重叠和截断误导。
- 一级系统分组符合三系统口径。
- 用户能理解四种任务模式和图例。
- 节点点击、边点击、上下游、方向、深度、聚合、全屏和导出可用。
- 关系详情显示字段映射和证据，长 SQL 不直接堆在线条上。
- 71 号 EXAM_NO 当前正确关系得到展示。

## 13. 不做事项和红线

1. 不把数据中心内部 Owner 直接改造成独立业务系统。

8. 不删除旧系统记录，先迁移、标记合并并验证无引用。
