# 108 关系图谱无法打开专项排查整改与测试计划

## 0. 执行入口与结论

本文件是本次“关系图谱无法打开”事件的专项执行入口，承接：

- `97_关系图谱与字典下发复核整改计划.md` 的 G1～G5；
- `98_Neo4j关系图谱分析副本建设与复核说明.md` 的 PostgreSQL 事实源和故障降级边界；
- `100_Neo4j_S0阻断问题修复与PoC放行计划.md` 的物理键、同步与测试门禁。

本次故障不需要等待 Neo4j。第一目标是让 PostgreSQL 关系边表驱动的基础关系图谱稳定可用；Neo4j 仍是后续隔离 PoC，不得作为本次修复前置条件。

当前裁决：

```text
页面路径：可达，GET /asset/graph = 200
图谱 API：可达，认证后 graph/options/diagnostics 均出现 200
图谱数据：存在，生产 asset_relations = 537
默认空图根因：生产前端仍发送 confidence=A + validation_status=A_rechecked
生产 A_rechecked 数据：0
本地修复：源码已去除 A_rechecked 幽灵默认，但未完整发布
生产版本状态：前端旧分包 + 后端新旧文件混合，发布不原子
```

所以，“无法打开”当前至少包含两类现象：

1. **已确认的默认空图**：旧生产前端的互斥筛选使默认查询命中 0 条；
2. **仍需浏览器捕获的白屏/交互失败**：路由和 API 均可达，若用户看到整页白屏，必须通过浏览器控制台、网络请求和截图进一步确认缓存、分包或运行时异常，不能继续只靠 curl 推断。

## 2. 问题清单

### P0-01：生产前端仍使用不存在的幽灵状态

- 位置：生产 `index-DFxNRzYF.js`；对应源码 `frontend/src/views/asset/graph/index.vue`。
- 复现：默认进入 `/asset/graph`，旧包组合 `confidence=A` 与 `validation_status=A_rechecked`。
- 影响：537 条关系存在但默认显示空图，用户认为功能无法打开。
- 修复：发布当前已去除该默认值的源码；视图默认完全由 `/options.view_modes` 决定，不在前端二次猜状态。
- 验收：首次进入只发送 `confidence=A`，不发送空或幽灵 validation status；返回和渲染关系数均大于 0。

### P0-02：生产后端为混合文件版本

- 位置：`backend/app/api/v1/graph.py` 与 `backend/app/schemas/graph.py`。
- 复现：新 API 构造 `physical_key`，旧 schema 不含该字段，响应静默丢弃。
- 影响：物理节点唯一化未真正进入生产；同名表跨系统仍有合并风险；前后端契约不可复验。
- 修复：禁止逐文件热更，后端按同一 Git SHA 构建不可变镜像；启动时输出脱敏版本号；健康/版本接口返回 backend SHA、schema revision、frontend build ID。
- 验收：容器内关键文件清单、镜像标签和构建清单一致；契约测试确认 `physical_key/display_id` 存在。

### P0-03：缺少原子前后端发布和回滚门禁

- 位置：`deploy/`、Nginx 静态目录和现有发布脚本。
- 现象：生产 `index.html` 与图谱分包仍为 2026-07-13 构建，API 文件却已更新到后续版本；静态目录保留多批历史 hash 分包。
- 影响：用户可能命中旧 HTML、旧分包或新 API 的任意组合；缓存刷新后表现不一致。
- 修复：每次发布生成 manifest，先完整上传版本目录，再原子切换软链接；HTML `no-cache`，hash 资源长期缓存；保留上一个完整版本回滚，不在活动目录混放无归属分包。
- 验收：发布前后 build ID 一致；强制刷新、普通刷新、新会话三种方式均加载同一版本；回滚一次可恢复。

### P1-01：图节点和边仍未真正使用物理键

- 位置：`backend/app/api/v1/graph.py`、`backend/app/schemas/graph.py`、`frontend/src/api/asset.ts`、图谱组件。
- 问题：当前 `id/source/target` 仍主要使用 `schema.table`；`physical_key` 只是可选附加字段。
- 影响：ODS 的 HIS 镜像和 HIS_SOURCE 同名表可能被 `_table_map_for` 字典覆盖；系统/来源筛选与节点点击可能串库。
- 修复：渲染真值统一为 `system_code|source_code|namespace|schema|table`；增加 `display_id`；边 source/target 使用物理键；表详情继续保留现有路径，通过 query 携带 system/source，不破坏现有路由。
- 兼容：旧 `schema.table` 查询只有在物理端点唯一时解析；多命中返回 409/明确候选，不随机选择。

### P1-02：页面加载链缺少可观察错误状态

- 位置：`frontend/src/views/asset/graph/index.vue`。
- 问题：`onMounted` 顺序等待 options→diagnostics→graph；options 或 graph 抛错时没有页面级 catch；finally 只关闭 loading，用户可能只看到空白或通用空状态。
- 修复：建立 `initial/loading/success/empty/filter_empty/auth_error/permission_error/api_error/contract_error/render_error` 状态机；options、diagnostics、graph 使用可控的 `Promise.allSettled`；显示 correlation ID、重试按钮和脱敏诊断摘要。
- 验收：401、403、404、500、超时、返回结构错误、零数据和筛选为零均有不同提示，不出现无限 loading 或白屏。

### P1-03：诊断接口把合法的同端点多关系视为不健康

- 位置：`backend/app/api/v1/graph.py:diagnostics`。
- 问题：仅按 from_table/to_table 分组；多字段关系会触发 warning 并令 healthy=false。
- 修复：改为统计稳定业务键重复、端点缺失、物理键缺失、未解析端点、孤儿表引用、层级分布和当前筛选命中；同端点多关系作为信息项而非错误。
- 验收：合法多边不降低健康状态；真正重复业务键才报 P0/P1。

### P1-04：全局图 API 负载和证据字段过重

- 证据：120 条边响应约 229546 字节。
- 问题：全局首屏同时返回字段映射、验证指标、说明等详情；节点增加后会影响解析和渲染。
- 修复：全局图只返回节点摘要和边摘要；边证据点击后调用详情 API；支持 server-side count、cursor/limit 和聚合；响应带 `total/returned/truncated`。
- 指标：初始图 P95 API ≤2 秒、前端可交互 ≤3 秒、默认 payload 目标 ≤500KB；超过阈值自动聚合并明确提示。

### P1-05：邻居图和表详情定位存在跨来源歧义

- 位置：`/api/v1/graph/neighbors`、`openTable()`。
- 问题：邻居查询只传 `table=SCHEMA.TABLE`；前端通过拆 node.id 跳表详情。
- 修复：邻居查询优先接受 system/source/schema/table 或 physical_key；旧 table 参数只作唯一兼容；详情跳转显式带 system/source query。
- 验收：两个不同来源的同名表能分别定位、分别查上下游、分别打开正确详情。

### P1-06：G6 异常缺少可靠回退

- 位置：`AdvancedRelationGraph.vue`。
- 问题：`graph.render()` 异步异常没有统一捕获；初始化失败可能留下空容器。
- 修复：捕获 import/init/render/destroy 异常，发出 `render-error`；父页面自动切回 SVG 并显示一次性告警；默认仍为 SVG，高级引擎按需加载。
- 验收：模拟 G6 抛错后 SVG 正常出现，页面无未处理 Promise rejection。

### P1-07：缺少真实浏览器和发布后烟雾测试

- 当前只有转换函数测试，没有覆盖路由懒加载、HTTP、DOM、画布和浏览器 console。
- 修复：增加组件测试与浏览器 E2E，生产发布后执行只读烟雾测试并保存脱敏截图、console error 和网络摘要。

### P2：后续可用性完善

1. 主入口只保留“表级图谱、上下游、待复核”，系统/Schema/业务域放二级分析。
2. 显示“总关系数、当前筛选命中、实际返回、隐藏候选、截断数量”。
3. 支持节点自动补全，不要求用户记住完整表名。
4. 支持一键适配、重置视角、聚焦一跳/两跳、返回全局。
5. 边证据抽屉显示字段映射、方向、验证等级、样本指标、来源文档和限制条件。
6. SVG/PNG 导出带标题、筛选条件、生成时间和数据批次，不导出敏感信息。
7. 大图按系统/来源/Schema 聚合，可下钻，不静默丢边。
8. 图谱与关系复核中心、关系配方库、表详情互相跳转并保留物理来源上下文。
9. 增加键盘操作、ARIA 文本摘要和色盲可区分线型。
10. Neo4j 只在 PostgreSQL 基础图稳定且性能证据确有需要后进入隔离 PoC。

## 3. 目标 API 契约

### 3.1 节点

```json
{
  "id": "DATA_CENTER|ods_8_216||HIS|PAT_VISIT",
  "physical_key": "DATA_CENTER|ods_8_216||HIS|PAT_VISIT",
  "display_id": "HIS.PAT_VISIT",
  "system_code": "DATA_CENTER",
  "source_code": "ods_8_216",
  "namespace_name": "",
  "schema_name": "HIS",
  "table_name": "PAT_VISIT"
}
```

缺少 system/source/schema/table 的关系不能进入正式图层，必须计入 diagnostics unresolved，不得退化成空前缀物理键。

### 3.2 边

```json
{
  "id": "relation_business_key",
  "source": "完整起点物理键",
  "target": "完整终点物理键",
  "display_source": "HIS.PAT_VISIT",
  "display_target": "HIS.DIAGNOSIS",
  "relation_layer": "formal",
  "relation_type": "formal"
}
```

数据库自增 ID 和旧 rel_id 作为属性保留，不再作为跨环境永久身份。相同端点允许多条不同业务键边。

### 3.3 图响应元数据

```json
{
  "nodes": [],
  "edges": [],
  "meta": {
    "total_relations": 537,
    "matched_relations": 192,
    "returned_relations": 120,
    "truncated": true,
    "filters": {},
    "data_version": "...",
    "backend_build_id": "..."
  }
}
```

前端必须显示 matched/returned/truncated，不能把 limit 截断误报成数据缺失。

- `/asset/graph` 或引用分包非 200；
