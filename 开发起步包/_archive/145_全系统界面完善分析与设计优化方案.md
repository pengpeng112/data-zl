## 一、总体结论

系统整体完成度中上：共享组件库（RePageHeader/ReStatCard/ReToolbar/ReEmptyState/ReChart/ReDetailDrawer 等 20 个）已成型，主链路（采集→目录→图谱→复核→质量）闭环可用。但存在三类系统性问题：

### 1. 安全/管控类硬伤（最高优先，涉及 ~12 个页面）

高危写操作普遍缺少前端二次确认与操作留痕：

| 页面 | 高危操作 | 现状 |
|---|---|---|
| ops/sql-workbench | 执行生产 DML | 点"二次确认执行"直接发请求，**无确认弹窗**；参数 JSON 解析失败返回 `{}` 继续提交 |
| ops/runs | 审批/执行 | 操作人靠 `ElMessageBox.prompt` **手输账号**，可冒充任何人，审计形同虚设；驳回无原因 |
| asset/relation-review | 批准/驳回关系（含批量） | **无任何确认**，驳回无需原因（比已删除的 candidates 页倒退） |
| asset/admin | 创建 API Token | 新 Token 明文用 `ElMessage.success` 弹出，几秒消失不可复制，极易丢失 |
| identity/authorizations | 整体替换用户角色 | 无确认、原因非必填、"授权人"可手填伪造（默认 "console"） |
| identity/local-accounts | 停用账号/解锁/强制改密 | 无确认**且无 try/catch**，失败抛未处理异常 |
| identity/sync-diffs | 写主档/批量执行 | 零确认 |
| identity/roles | 保存权限矩阵 | 无确认，立即生效 |
| dict/mappings、dict/sync-diffs、metadata-changes/changes | 停用/忽略/解决 | 无确认、无错误处理 |

### 2. 功能缺陷级 Bug（确定存在，需优先修）

1. **asset/systems 的"编辑"功能名存实亡**：点编辑不打开表单，直接用旧值调保存，且 `description_cn` 硬编码 `""`——**每次"编辑"都会清空系统说明**（index.vue 165-181 行）。
2. **identity/persons 筛选语义错位**：筛选下拉传 `person_type`，选项却是"医生/护士/药师/正式"，前三者属 classification、后者属 person_type，筛选结果很可能错误。
3. **dict/medical OverviewPanel 字段错位**：读 `cfg.enabled`，后端字段是 `push_enabled`，总览"写通道状态"永远显示"关闭"；且统计只查 diagnosis 类别，漏手术。
4. **metadata-changes/diff 数据连接硬编码死数据**（`his_8216/jhemr/lis/...`），与 snapshots 页动态加载的真实 source_code 脱节，环境不符则整页不可用；另有 stale state bug（切连接后旧快照 ID 残留）。
5. **ops/sql-workbench 静默降级**：连接接口失败时兜底一条硬编码假数据且 `write_allowed: true`，误导用户以为平台库可写。
6. **query-center 路由/权限归属错误**：视图在 `views/query-center/`，路由挂 `/asset/queries`，权限点却复用 `asset.ai_draft.view`（与 AI 工具页相同），目录、路由、权限三者不一致。
7. **login 页密码规则 8-18 位 vs local-accounts 重置密码"至少 12 位"**，两套策略并存。

### 3. 一致性问题（全站性，适合一次性立规范）

- **错误处理 4 种策略并存**：graph 有完整错误状态机 / 部分页 el-alert / 大量页面静默 `catch(()=>{})` / 部分靠全局拦截器。静默吞错页面超过 15 个。
- **同一枚举多处映射**：关系验证状态在 GraphToolbar/GraphEvidenceDrawer/relation-review 三份字典文案不一致（"样本通过"vs"抽样通过"）；质量状态/严重程度在 quality、ai-quality、reportMarkdown 重复三份；nullable 判定 tables 页认 `'Y'/'true'`、table-detail 只认 `'Y'`。
- **API 调用方式分裂**：多数走 `@/api` 封装，relation-review、sync-logs、snapshots、ops/audit、query-center 裸写 `http.request` 字符串路径。
- **空态组件混用**：ReEmptyState 仅 5 页使用，其余用 el-empty 或无空态。
- **主题 token 两套**：`--re-*` 旧变量（table-detail、dict/general）与 `--border-light` 新变量并存；welcome 暗色 vs 全站浅色。
- **权限点覆盖不一致**：systems、identity/sync-diffs、dict/medical 有 v-perms；mappings、general、changes、query-center、ops/tools 全页无权限控制。
- **"当前页统计"口径误导**：identity/sync-diffs、dict/sync-diffs、ops/audit 的统计卡只统计当前页 20 条。
- **裸 textarea 当 SQL 编辑器**：ops 模块全部 SQL 输入无高亮/补全/校验。
- **原生 prompt/confirm 残留**：asset/admin 用原生 `prompt()`/`confirm()`。
- **数字/时间格式化**：仅 welcome 有千分位/万单位；多数页面时间原样输出 ISO 字符串。

## 三、结构性调整建议（菜单/路由层）

### 3.1 "关系"主题入口收敛（当前 6 个菜单项平铺）

现状：关系图谱、关系路径、关系命中率、关系配方库、血缘与影响、关系复核中心 6 项平铺在"数据资产"菜单下。

建议目标形态（4 个入口）：
- **关系图谱**：吸收"关系路径"作为 explore 模式的双端点子模式；血缘影响分析结果区增加"在图谱中展开"导流按钮
- **关系复核中心**：已吸收候选关系（删除 candidates 死代码收尾）
- **关系命中率**：保留独立（质量监控定位独特），作为跳转枢纽
- **关系配方库**：保留独立

血缘与影响：保留轻量"变更影响"表单入口，深度探索导流图谱，避免两套血缘叙事。

### 3.2 查询与指标中心独立

从 `/asset/queries` 迁出为独立一级菜单 `/query-center`，配置独立权限点（新建 `query.view` 等，不再复用 `asset.ai_draft.view`），目录/路由/权限三者对齐。去除页头硬编码本地路径 `F:\python\数据资产\取数` 和内部计划编号"126"。

### 3.3 AI 上下文与 AI 工具边界梳理

- ai-context：专注"搜索表→导出脱敏上下文"，吸收 ai-tools 的"系统上下文摘要"卡片

## 四、全局规范建议（先做规范再改页面，事半功倍）

建议作为独立先行任务，供后续所有页面整改统一遵循：

### G1 统一错误处理规范
- 制定单一模式：列表加载失败 → ReEmptyState 错误变体（图标+文案+重试按钮）；操作失败 → ElMessage 展示后端 `detail`；禁止静默 `catch(()=>{})`
- 短期落地：全局搜索 `catch (() => {})` / `catch { }` 逐处补齐，优先 15 个静默页面

### G2 统一枚举字典层
- 新建 `src/constants/assetEnums.ts`：关系验证状态、质量状态/严重程度、同步差异状态/严重度、账号状态等集中维护（文案+tag 颜色），替换至少 6 处私有映射
- 同步统一 nullable 判定（兼容 'Y'/'true'）、系统枚举后端驱动（消除 relation-rates、dict/general 等 6 处硬编码系统清单）

### G3 统一危险操作确认规范
- 分级：L1 状态变更（启停/忽略）→ ElMessageBox.confirm；L2 审批/授权/执行写操作 → confirm + 必填原因/影响预览；L3 写主档/生产 DML → confirm + 输入确认词/密码 token（沿用 dict/medical 的 confirmation_token 模式，该页是现有最佳实践）
- 所有审批/授权操作人一律取登录态，删除手输账号入口

### G4 统一 API 访问层
- 裸 `http.request` 页面（relation-review、sync-logs、snapshots、ops/audit、query-center）迁移到 `@/api` 封装并补类型定义；启用 `api/ops.ts` 已封装但未使用的 submitSqlTemplate/approveSqlTemplate/listSqlRuns/getOpsEvent

### G5 统一展示规范
- 数字：抽取 welcome 的 fmt 为 utils（千分位/万单位），全站应用
- 时间：统一 `formatTime` 工具，替换 ISO 原样输出
- 空态：列表页统一 ReEmptyState（当前仅 5/35 页）
- 主题 token：淘汰 `--re-*` 旧变量；确认 welcome 暗色定位（保留则需文档化为"指挥中心大屏"设计语言）

### G6 权限点审计
- 逐页核对写操作 v-perms 覆盖（缺口清单：query-center 全页、ops/tools、dict/mappings、dict/general、dict/sync-diffs、metadata-changes/changes、ai-tools 草稿审核、table-detail 注释编辑）
- query-center 独立权限点（见 3.2）

## 五、P0 页面详细设计优化方案

### 5.1 asset/systems（业务系统与数据资源）

**现状问题**：编辑功能缺陷（清空 description）、操作列 420px 塞 8 按钮、连接表无分页筛选、向导无分步校验、反馈文案夹英文/原始 JSON、Tab 状态不回写 URL。

**优化设计**：
1. 编辑改为打开完整编辑对话框（复用新增表单组件，预填当前值，保存走 upsert），删除"直接确认保存"逻辑
2. 操作列收敛：保留 测试/采集/编辑 3 个高频按钮，其余（凭据轮换×2、清凭据×2、写策略、禁用）收入"更多"下拉；危险项红色区分
3. 连接表加服务端分页 + 按系统/类型/状态筛选
4. 向导每步"下一步"前做当前步必填校验
5. 反馈文案中文化（connected→连接成功、failed→连接失败），采集结果改为结构化摘要（表 N/字段 M），JSON 明细放展开区
6. Tab 切换 `router.replace` 回写 query
7. 资源树叶节点提示改为跳转链接（"前往表资产"）

### 5.2 asset/relation-review（关系复核中心）

**优化设计**：
1. 批准：ElMessageBox.confirm 展示"来源表→目标表、置信度、将影响图谱"后确认
2. 驳回：强制填写驳回原因（ElMessageBox.prompt + 非空校验），原因写入审计
3. 批量操作：confirm 展示选中条数与分类分布
4. API 迁移至 `@/api/asset`，删手写 interface
5. Tab 与"验证状态"筛选去重：confirmed/rejected Tab 下隐藏状态筛选或自动锁定
6. 已确认关系的"编辑"改为"先撤销确认"引导
7. 状态文案切换到 G2 统一字典

### 5.3 asset/graph（关系图谱）

**优化设计**：
1. GraphToolbar 补引擎切换 UI（G6/SVG 手动切换 + 当前引擎标识 + 降级原因提示）
2. SVG 引擎补指针拖拽平移（pointerdown/move/up 绑定 pan）；`@wheel.prevent` 限定在画布容器
3. 修正 SVG 布局语义：layered 选项接 buildLayered 或在 SVG 模式下隐藏该选项；删除 buildForce 死代码
4. "多结果需补充条件"改为候选列表弹窗（渲染 `locate.search_results` 供点选）
5. 图例文案两引擎统一；工具栏统计区对非工程用户折叠为"详情"popover
6. G6 layered/hierarchy 模式避免每次 destroy 重建（diff 更新或渲染缓存）

### 5.4 asset/ai-quality（AI 质控分析）

**优化设计**：
1. 报告区加"复制 Markdown""导出 .md"按钮（live 区与结构化结果区各一）
2. 拒绝操作加 confirm + 复核备注必填（拒绝时）
3. 问题列表改服务端分页，勾选状态跨页保持（reserve-selection + row-key）
