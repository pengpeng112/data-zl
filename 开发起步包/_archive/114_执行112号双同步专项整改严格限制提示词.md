### 二、业务口径不得改变

- 诊断/手术：用户人工维护，审核通过后即时自动同步 HIS 和电子病历 JHEMR；不是夜间任务。
- 人员：HIS 每晚自动同步 CDMS 和 JHEMR。
- HRP：本期暂缓，不开发、不作为阻断。
- HIS 与 JHEMR/CDMS 分别事务提交、分别回读、分别记录状态；不存在跨库原子事务。

### 三、绝对禁止

1. 禁止对生产平台库执行迁移或写入。

4. 禁止启用 `APP_DICT_MEDICAL_PUSH_ENABLED`、`APP_IDENTITY_SYNC_ENABLED`、nightly、密码写入开关或新 worker 生产开关。

6. 禁止重新实现真实写连接器；必须复用并加固 `apply_one_action`、`_execute_write_sql` 和 identity executor bridge。

### 四、必须沿用的数据库实测事实

- 当前所有平台注册数据源 `write_policy=readonly` 且 `write_credential_ref` 为空。
- 诊断 push plan/action/run 和身份 batch/action/managed/scheduler 当前均为 0。
- HIS 诊断字典 50220 行/47655 个不同编码；手术字典 16450 行/16448 个不同编码；两表无 PK/UK。
- JHEMR `jhdict_icd_vs_clinic.serial_no` 非空且唯一，但无 default、无关联 sequence；`hospital_no+diagnosis_code` 已有一个重复业务键。

### 五、固定执行顺序

必须按 `P0 → A1 → A2 → A3 → B1 → B2 → T1 → D1`。不得把后续步骤提前。

#### P0 冻结和前置门禁

- 记录工作区、Alembic head、相关开关默认值和现有测试。
- 确认 111 S1/S3/S4 通过。
- 没有显式隔离 `APP_TEST_DB_URL` 时只跑纯逻辑测试，不得连接 `.env`。
- 生产/目标库只允许通过仓库受控只读连接器执行限量 SELECT；查询前过静态只读门禁，不输出明细。

#### A1 持久化 outbox 和状态机

- 在平台 `asset` schema 新增 `asset_<模块>_<实体>` 命名的 outbox/任务表，手写 Alembic upgrade/downgrade，禁止 autogenerate。
- 审核记录和 outbox 必须在同一个平台数据库事务提交；审核回滚不得留下任务。
- worker 使用数据库租约、attempt、next_retry_at、lease_expires_at、dead-letter 状态；并发领取使用 PostgreSQL 安全行锁机制。
- worker 默认关闭；进程重启后任务可恢复。不得使用裸线程代替持久化队列。
- 单条和批量审核均生成稳定业务键、plan hash、目标状态；重复事件不得重复创建动作。

#### A2 打通既有字典执行器

- 保留旧 dry-run API 兼容路径；新增正式、非 deprecated、动作级授权的服务端执行入口。
- worker 只能按 plan ID 读取服务端已审批且 hash 匹配的动作，不能接受客户端 SQL/action。
- 复用现有写策略、confirmation token、credential、白名单、超时和审计门禁。
- HIS/JHEMR 每个目标使用目标内单事务包；现有单动作逐次 commit 不能直接用于 JHEMR 多表包，必须增加“同目标多动作共享连接/事务，全部成功才 commit”的抽象。
- 一方成功另一方失败时进入 `reconcile_required`，禁止自动反向删除或覆盖。

#### A3 冲突、回读和取号

- HIS 同编码查询必须处理 0/1/多行；多行或字段不一致一律 conflict，禁止任取第一行。
- 比较编码、名称、国临、医保、停用状态和医院编码；禁止覆盖已存在业务字段。
- JHEMR 同业务键多行时 conflict。
- 删除所有 `MAX+1` fallback。没有经 DBA 批准并配置的专用 sequence/安全 allocator 时，JHEMR ICD action 保持 blocked，不能 apply。
- 代码可支持白名单 sequence 名配置，但不得创建 sequence；sequence 标识符必须服务端固定/白名单，不能来自客户端。
- 回读失败不得标成功；重试只用于网络/瞬时错误，唯一冲突和业务冲突不自动重试。

#### B1 修正身份编排链路

- 将 orchestrator 的 CDMS/JHEMR apply 从仅写 `pending_reconcile` 改为在全部门禁通过时调用 `identity_sync_executor_bridge`。
- dry-run、secret 缺失、权限未确认、CDMS 语义未确认、密码门禁关闭时，bridge 必须完全不执行目标写入。
- 真实 bridge 返回值和 readback 决定 managed relation 状态；不得把 `pending_reconcile` 当成功。
- 目标失败记录 compensation/reconcile，不自动 DELETE。
- 不接入 HRP。

#### B2 CDMS/JHEMR 失败关闭

- 先只读确认 CDMS FID/FUSER/FUPDATEUSER 语义。证据不足时不要猜，不要把现有假设写死；增加明确 gate，使 CDMS apply 返回 blocked。
- FTYPE 8/32 始终禁止生成自动写动作，直到用户另行裁决。
- HMAC 和两个默认密码 secret 缺失时失败关闭；只测试文件存在、权限和接口，不创建真实 secret、不输出默认密码。
- JHEMR 多余 DELETE 由 DBA 后续回收。代码不使用 DELETE，并在 gates/健康检查中把“最小权限未确认”显示为 blocked。
- 身份和字典 credential ref 分开，不能因同一数据库账号具备两类权限就合并配置。
