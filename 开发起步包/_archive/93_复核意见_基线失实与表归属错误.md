## 2. 阻断性问题（必须修订）

### 问题 P1：§3.1 有 6 张核心表的 source_code 归属完全错误 🔴

93 号 §3.1 声称 17 张表都在 `source_code='ods_8_216'`，实测 **6 张根本不在 ods_8_216**：

| 表 | 93 号声称位置 | 实际位置 |
|---|---|---|
| EPR_INPATIENT_DOCINDEX | ods_8_216 / MTL | **ods_emr / MTL** |
| EPR_INPATIENT | ods_8_216 / MTL | **ods_emr / MTL** |
| EMRSD_CONTENT | ods_8_216 / MTL | **ods_emr / MTL** |
| JHMR_FILE_INDEX | ods_8_216 / JHEMR | **ods_emr / JHEMR** |
| JHMR_FILE_CONTENT_TEXT | ods_8_216 / JHEMR | **ods_emr / JHEMR** |
| MCS_DOC_FORM | ods_8_216 / YDHL | **ods_ydhl / YDHL**（且 mobile_nursing 源 LUNA_MCS_SDSEY 也有）|

**影响**：
- §3.1 的 UPDATE 语句 `WHERE source_code='ods_8_216'` 对这 6 张表全部匹配不到（落入 warning 清单），中文名补不上。
- §3.2 的列元数据同样匹配不到。
- §4.1 的 R10-R14 关系 from_table 写 `MTL.EPR_INPATIENT_DOCINDEX` 等，若按 source_code='ods_8_216' 定位，关系登记也会错。
- §3.3 his_source_value_desc 涉及这 6 张表的部分也会失效。

**修订要求**：
1. 把这 6 张表的 source_code 改为正确的（ods_emr / ods_ydhl）。
2. CSV 拆分：ods_8_216 的 11 张表一个 CSV，ods_emr 的 5 张表 + ods_ydhl 的 1 张表分别处理。
3. §4.1 R10-R14 的 from_source_code 改为 ods_emr / ods_ydhl，from_system_code 改为 DATA_CENTER（ods_emr 已归 DATA_CENTER）/ MOBILE_NURSING（ods_ydhl）。
4. 重新确认这些表在 ods_emr/ods_ydhl 是否已有中文名（实测 ods_8_216 的 PAT_VISIT 已有中文名，ods_emr 可能也有）。

### 问题 P2：§1.3 现状基线整体失实，阶段 1 多个 upsert 任务多余 🔴

- T1.1「登记 DATA_CENTER 系统」→ DATA_CENTER 早已存在，应改为"UPDATE 补全 target_host=10.10.8.216 + description_cn"。
- T1.2「登记 ods_8_216 数据源」→ ods_8_216 早已存在且字段较全，应改为"核对并 UPDATE 缺失字段（如 write_policy/connection_options）"。
- T1.3「UPDATE his_source_10_10_10_15」→ 该源存在，但 his_ready 已不存在（表归并到 his_source），§4.1 R15 的 from_source_code='his_ready_10_10_10_15' **会失败**（需改 his_source 或重新设计镜像关系）。
- T1.4「删除空 system_code 记录」→ 空记录已不存在，此任务无操作（保留作幂等检查即可）。
- T1.5「回填 31 个 schema」→ ods_8_216 实际 23 个 schema，且 §3 的中文名（MTL/JHEMR/YDHL）对应的表不在 ods_8_216，schema 中文名回填要分源处理。

### 问题 P3：§3.1 部分表已存在中文名，UPDATE 规则需明确"不覆盖" 🟡

实测 `PAT_VISIT` 已有 `table_name_cn='病人住院主记录'`（name_cn_source='已有资产'）。93 号 §3.1 说"中文名优先沿用 his_ready 同源表既有值"，但实际 ODS 侧部分表已有中文名。UPDATE 规则要明确：**既有非空 table_name_cn 不覆盖**（只补 value_desc_cn/business_desc_cn 等空字段）。

## 3. 次要问题（建议修订）

### 问题 P4：§1.3 schema 清单把源端 schema 与 ODS schema 混淆 🟡

93 号 §1.3 列了 31 个 schema（含 MTL/JHEMR/YDHL），但这些是**源端** schema 分布，不是 ods_8_216 的实际 schema。实测 ods_8_216 只 23 个 schema。MTL/JHEMR 在 ods_emr 源，YDHL 在 ods_ydhl 源。T1.5 回填要按各源实算，不能照抄 31 个。

### 问题 P5：§4.2 凭据与连接方式描述需核对 🟡

计划说 ODS 经 SSH 通道（`.ssh/config_ai` 别名 data-asset-83）。实测凭据文件 `/etc/data-asset/credentials/ods_8_216` 存在 ✅。但 ods_emr/ods_ydhl/ods_lis 等拆分源是否共用 ods_8_216 凭据（同一物理库 8.216）需确认——若是，验证脚本要支持多 source 共用一套连接。

### 问题 P6：his_ready_10_10_10_15 已不存在 🟡

§3.3 和 §4.1 R15 都引用 `his_ready_10_10_10_15`，实测该 source 已不存在（被 his_source_10_10_10_15 取代，1236 张表）。R15 镜像关系要么删除，要么改 from 为 his_source_10_10_10_15 并重新定义（同名表映射需重新核对——his_source 的 MEDREC.PAT_VISIT → ods_8_216 的 HIS.PAT_VISIT）。
