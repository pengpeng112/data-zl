# 三系统数据库探查、HIS 视图关系治理与服务器升级一次性执行计划

## 0. 计划目标

本计划把用户提出的三项工作合并为一次连续执行：

1. 对三个新数据库端点执行受控只读探查，形成可复现的表、字段、约束、索引、视图、依赖和候选关系资产；
2. 对 HIS 源端当前有效、可正常读取定义的视图进行关系摄取，复核与既有正式关系的冲突，把可审核结果落入平台本地测试库，再幂等升级到 `10.10.8.83` 平台；
3. 对本机现有代码、文档和资产改动做完整审计，修复本次发布必需问题，只发布经过明确归属和验收的内容。

执行方式固定为：`只读基线 → 分来源探查 → 关系解析与限量验证 → 本地测试库落地 → 全量门禁 → 服务器备份/dry-run/apply → 生产验收 → 文档收口`。

“一次性完成”是指内部检查点通过后连续进入下一步；某个来源缺少数据库名、端口不通、凭据未安全注入、视图超时或关系冲突时，记录为 `SKIPPED/BLOCKED` 并继续其他来源，不以单项不确定阻塞全局。只有第 3.4 节列出的全局停止条件才中止服务器升级。

## 3. 全程安全边界

### 3.1 源库允许动作

- 仅执行目录/元数据 `SELECT`、只读 CTE、`SELECT 1` 连通测试和限量聚合验证；
- MySQL 会话执行 `SET SESSION TRANSACTION READ ONLY`，采集结束统一 rollback；
- SQL Server 设置 `READ UNCOMMITTED`、`LOCK_TIMEOUT`、`DEADLOCK_PRIORITY LOW`，只允许单条 SELECT，采集结束统一 rollback；
- HIS Oracle 11g 使用受控连接器、read-only transaction、`ROWNUM`、超时和最大返回行数；
- 元数据大对象和视图定义可以采集，但先做凭据/URL/Token 模式清洗后才写快照；
- 验证结果只保留聚合计数、覆盖率、孤儿率、重复键数和放大倍数，不落患者或人员明细。

### 3.2 源库禁止动作

- 禁止 `INSERT/UPDATE/DELETE/MERGE`、`SELECT INTO`、临时表写入、存储过程、动态 SQL、锁表、DDL、建用户、授权、备份、恢复、刷新/编译视图；
- 禁止 `SHOW PROCESSLIST`、全网/全端口扫描、读取服务器文件、注册表、错误日志或其他凭据；
- 禁止对大表做无条件 `COUNT(*)`、`SELECT *`、全表排序、全文 CLOB/BLOB/报告正文读取；
- 禁止为了测试账号能力而执行任何写后回滚探测；
- 禁止把高权限账号的“能够写”误记为本计划授权写入。

### 3.3 平台允许与禁止动作

允许：备份后向平台 `asset` schema 幂等写入连接元数据、表、字段、声明外键、关系复核草稿、配方草稿、导入批次和审计摘要。

禁止：绕过关系审核状态机、直接把视图 JOIN 升为正式 A/A+ 关系、覆盖人工确认中文名、删除其他来源资产、启用业务源写开关、生产 downgrade、发布与本次无关的人员目标写改动。

### 3.4 全局停止条件

以下任一发生时停止服务器 apply，但保留已完成的只读证据和 dry-run 结果：

1. 平台生产库身份无法确认或备份失败/不可读；
2. 发现命令、日志、快照、Git diff 或平台 API 正在输出口令/Token/患者敏感明细；
3. 发现任一业务源库写入、DDL、GRANT/REVOKE 或锁等待异常；
4. 远端 Git 分叉且无法证明发布 SHA；
5. 平台 dry-run 数量守恒失败、同一物理端点将被重复登记或导入脚本准备删除人工审核资产；
6. 生产健康/RBAC/登录/图谱主流程在升级后失败且不能立即回滚。

普通的单库不通、数据库名缺失、视图无权限/超时、关系冲突或样本不足不属于全局停止条件，按跳过策略继续。

2. 从视图 SQL 提取等值 JOIN、外连接方向、附加状态/日期/非空条件、函数包裹键、UNION 分支和跨库引用。

4. 为高频核心候选生成聚合验证：子键非空数、去重键数、父键重复、命中/孤儿、JOIN 放大、限定条件覆盖。
5. 普通表每条关系最多 10,000 个去重键；大表先按日期/父键集合缩小，查询达到超时即停止并标 `validation_timeout`。
6. 结果分为 `existing/candidate/partial/recipe_candidate/rejected`；视图 SQL 或样本验证不能单独把关系标成 A+。
7. 跨三个新系统、HIS、ODS 或其他实例的关系在没有共同强业务键前进入 `cross_system_pending`，不升正式。

验收：每条关系都有来源 SQL 指纹、物理端点、组合键、限定条件、验证范围、指标和风险说明；无明细输出。

### S5：HIS 有效视图清单和“正常执行”判定

1. 从平台 `HIS_SOURCE` 当前上下文、关系配方、正式关系和 review 草稿取得最新基线；仓库回退使用 `16` 快照、HIS 源端资产包、132–134。
2. 从 HIS Oracle 11g `ALL_OBJECTS/ALL_VIEWS/ALL_TAB_COLUMNS/ALL_DEPENDENCIES/ALL_ERRORS` 读取业务 Owner 下的视图状态、定义、字段和依赖；不使用 `_archive` 关系。
3. “有效视图”至少满足 `OBJECT_TYPE='VIEW'`、`STATUS='VALID'`、定义可读取；INVALID 视图只进异常清单。
4. “正常执行”不以全量查询判断。对低风险视图可执行带超时的 `SELECT 1 ... WHERE ROWNUM <= 1`；涉及巨表、DBLINK、函数、聚合、全文或复杂 UNION 的视图只做静态解析，不触发运行。
5. 运行验证出现权限、远端 DBLINK、函数异常或超时，只标 `runtime_blocked/runtime_timeout`；禁止刷新、编译或修复源视图。
6. 每份视图定义计算 SHA-256；清除常量中的凭据、患者 ID 条件值、URL 参数后才进入证据文件。

验收：得到 VALID/INVALID、parseable/unparseable、runtime_ok/runtime_skipped/runtime_error 的分层清单，且不把“VALID”误写成“业务关系已验证”。

### S6：HIS 视图关系摄取、查重与冲突复核

## 5. 跳过与冲突处理矩阵

| 场景 | 状态 | 继续动作 |
|---|---|---|
| 某端点不通 | `BLOCKED_ENDPOINT` | 记录端点和脱敏错误，继续其他库 |
| 未安全注入凭据 | `BLOCKED_CREDENTIAL` | 不从聊天/仓库搜密，继续其他库 |
| SQL Server 数据库名不能唯一判断 | `PARTIAL_DISCOVERY` | 采可访问库元数据并标待确认，不猜主库 |
| 职业病 1433 不通 | `BLOCKED_ENDPOINT_OR_PORT` | 不扫描其他端口，继续 |
| 视图 VALID 但运行超时 | `RUNTIME_SKIPPED` | 保留静态解析/依赖，不做全量执行 |
| 视图 SQL 无法解析 | `DEPENDENCY_ONLY` | 只保留 ALL_DEPENDENCIES，不造 JOIN |
| 组合键冲突可限量验证 | `CONFLICT_RECHECKED` | 保存指标，按结果进入 draft/partial/rejected |
| 冲突仍不能消除 | `UNRESOLVED` | 写冲突清单，不入正式关系，继续 |
| 大表缺少业务键/时间边界 | `BLOCKED_UNBOUNDED` | 不执行验证，仅保留候选 |
| 高权限账号无法换成只读账号 | `ASSET_IMPORTED_CONNECTION_DISABLED` | 完成离线资产导入，生产连接禁用/待换凭据 |
| 应用代码门禁失败但数据导入器可独立安全运行 | `CODE_RELEASE_SKIPPED` | 只做平台资产导入，不切后端/前端 |
| 平台备份或 dry-run 守恒失败 | `GLOBAL_STOP` | 不 apply，保留报告并停止服务器升级 |
