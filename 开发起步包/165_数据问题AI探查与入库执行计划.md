## 0. 目标

## 1. 铁律（STOP 白名单沿用 163 §1 前四类）

1. 探查执行（E3 及此后任何全量 run）一律**夜间窗口+单模板超时 120s+整轮墙钟上限 60 分钟**；白天只允许单条模板的语法/结构核验级试跑（聚合、限量，同 164 §2 先例）。**（v1.2 注记 2026-08-30：经用户明确授权一次性豁免——E3 首轮+同窗收敛两轮可于当日日间执行，源侧仍走 8.83 受控连接器只读、单模板 120s/整轮 60 分钟限额不变；本豁免仅 2026-08-30 本轮有效，此后任何全量 run 与生产 X2 首轮仍一律夜间。）**
2. **入库零患者明细**：evidence_sql 只存模板文本与参数名（**禁止任何 ID/住院号/姓名字面量**，T8/T9 双源比对在执行器内存完成，见 §3 模板 schema）；error_summary/note 入库前过 `app/services/data_masking.sanitize_text`。
3. 平台库写入门禁：E1–E5 全部落**隔离测试库**（隧道 data_asset_test，`APP_TEST_DB_URL`；**alembic 命令必须显式 `APP_DB_URL=$APP_TEST_DB_URL` 前缀**，防误指 .env 生产库——146 §11 教训）；**生产建表 apply（X1）与生产首轮探查（X2）归等待域**（备份→dry-run→apply→二次 dry-run 收敛 0→/health 200）。
4. **AI/执行器不得裁决终态**：执行器只写 `open`、更新观测与 relapse；`confirmed/false_positive/resolved` 仅人工（166 transition）。服务层 `upsert_finding` 永不含终态写入路径（单测断言锁死）。
5. **源库连接拓扑**：run_probe 源侧复用 sjzc 同款 **8.83 容器受控连接器通道**（凭据不出服务器、源查询在容器内执行、本机零直连业务库）；写侧=平台库 SQLAlchemy。执行器身份 `probe:<run_id>`；每 run 写一条 GovernAuditLog 汇总（module=probe，action=run，含模板数/新增/更新/复发数）——沿用 identity_nightly 夜跑"专用服务+审计"先例，不接入 asset_action_executors（AI 工具写门禁域不变）。新探查主题走"新增模板→下轮执行"，禁止即席连生产探索。
6. 模板 SQL **无注释**（db_connectors 门禁禁注释）、一律 `execute_readonly(sql, params=)` 参数化执行（`:START_DATE/:END_DATE` 契约）、禁字符串插值；大表（HIS.LAB_RESULT 等）必须键子查询限定（A4 裁决）。
7. 迁移手写 upgrade/downgrade（`down_revision`=当前 head `b0c1d2e3f4a5`，动手前 `alembic heads` 核对防分叉）；零 Git 写；凭据零落盘；pnpm（166 侧）。

## 2. 数据模型（round-4 A1/A2/A11 裁决定稿）

### asset_probe_runs

| 列 | 类型 | 说明 |
|---|---|---|
| id | SERIAL PK | |
| run_id | VARCHAR(64) UNIQUE NOT NULL | 格式 `probe-YYYYMMDD-HHMMSS` |
| started_at / finished_at | TIMESTAMPTZ | |
| status | VARCHAR(16) | running/done/partial/blocked |
| probe_count / finding_new / finding_updated / relapse_count | INTEGER DEFAULT 0 | |

| error_summary | TEXT | sanitize_text 后入库 |
| created_by | VARCHAR(64) | `probe:<run_id>` |
| created_at | TIMESTAMPTZ DEFAULT now() | |

### asset_probe_findings（问题身份一行，观测随窗更新）

| 列 | 类型 | 说明 |
|---|---|---|
| id | SERIAL PK | |
| probe_type | VARCHAR(16) | R-REF/R-CNT/R-KEY/R-XSYS/R-DOM |
| system_pair | VARCHAR(64) | 如 `HIS↔JHEMR`、`HIS(单库)` |
| object_desc | VARCHAR(512) | 人类可读对象描述 |
| object_key_digest | VARCHAR(32) | sha256(object_desc) 前 32 hex（入唯一键，防 btree 超限） |
| metric_name | VARCHAR(128) | 如 `doctor_code_missing_rate` |
| metric_value | NUMERIC(18,6) | 数值型（A2 裁决） |
| metric_unit | VARCHAR(16) | %/条/例 |
| threshold | NUMERIC(18,6) | 越阈判据 |
| window_start / window_end | DATE | 最新观测窗 |
| severity | VARCHAR(4) | P1/P2/P3 |
| status | VARCHAR(16) DEFAULT 'open' | open/confirmed/false_positive/resolved |
| first_seen_run / last_seen_run | VARCHAR(64) | |
| relapse_count | INTEGER DEFAULT 0 | |
| evidence_sql | TEXT | 模板文本（无字面量） |
| evidence_digest | VARCHAR(64) | sha256(规范化 SQL+参数窗) |
| resolved_by / resolved_at | VARCHAR(64)/TIMESTAMPTZ | 人工终态快照（完整历史走审计日志） |
| note | TEXT | |
| created_at / updated_at | TIMESTAMPTZ | |

**索引**：UNIQUE `(probe_type, system_pair, object_key_digest, metric_name)`（问题身份键，**不含 window**——A1 核心裁决）；普通索引 `(status)`、`(severity)`、`(probe_type)`、`(last_seen_run)`。

**语义**：
- **同窗重跑**（幂等键=问题身份键+同 window_start）→ 仅更新 metric_value/evidence_digest，不动 status；
- **新窗重跑命中既有行** → 更新观测（metric_value/window/last_seen_run），并做复发判定：原 `status=resolved` → 回 `open` 且 `relapse_count+1`；原 `confirmed` → 保持 confirmed 但 note 追加"新窗仍越阈"；原 `false_positive` → 不动（防噪音）；
- **越阈才产生行**（A2）：模板 `trigger` 不成立只进 runs.metrics_summary。

## 3. 探查模板库（12 条，round-4 A3–A6 修正版）

**模板 schema**（`backend/scripts/probe_templates/*.json`）：

```json
{
  "code": "T1", "probe_type": "R-REF", "name": "EXAM 医生工号缺失率",
  "severity_default": "P2", "window_kind": "month",
  "sides": [{"side": "a", "source_code": "his_source_10_10_10_15", "dialect": "oracle",
             "sql": "SELECT COUNT(*) TOTAL, SUM(...) MISS FROM ... WHERE REQ_DATE_TIME >= :START_DATE AND REQ_DATE_TIME < :END_DATE"}],
  "derive": {"metric": "doctor_code_missing_rate", "formula": "miss/total", "unit": "%"},
  "trigger": {"op": "gt", "threshold": 1.0, "value_type": "rate"},
  "object_desc_tpl": "EXAM.EXAM_MASTER.DOCTOR_USER 缺失率",
  "large_table_guard": null
}
```

- **单源模板**（T1–T5,T10–T12）：sides 单元素；**双源模板**（T6,T7,T8,T9）：两侧各一条聚合 SQL，`derive.compare` 定义内存比对（如按月键 FULL OUTER JOIN 后算差量/命中率），**比对用的样本 ID 只在执行器内存流转，两段 SQL 文本均不含 ID 字面量**（A3）。
- T6/T7（检验/影像对账）：`large_table_guard: "LAB_RESULT 必须按申请键+月窗子查询限定，禁全表 GROUP BY"`；SQL 以申请侧（LAB_TEST_MASTER 系）按月聚合为主，结果侧同窗聚合后在内存比对。
- T11：`derive.mapping` 内置 152 E5 的 JHEMR↔HIS 码映射表；未映射值产出"待人工映射清单"进 metrics_summary，不生成 finding（A5）。
- T12（R-DOM）：只产 finding（偏差清单，单轮 ≤50 条门禁），**不写值域库**；导入值域库=人工从导出文件走 149 submit（pending）（A6）。
- T1/T2/T5/T10 用 164 §2 已验证 SQL 定型；T3/T4/T6/T7 在 E2 白天结构核验（探列名/表名）后**冻结进 JSON，E3 夜跑禁止现场改 SQL**（防 evidence_digest 漂移）。
