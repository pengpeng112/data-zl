# 121 关系图谱知识图谱式重构执行修复计划

## 1. 目标与完成定义

本次不是继续调整颜色或节点大小，而是把当前“全量表关系散点图”重构为可理解、可定位、可验证的知识图谱式工作台。

完成后必须同时满足：

1. 默认进入“资产概览”，先看到系统、数据源和 Schema/Owner 的聚合结构，不再一次塞入 127 个表节点。
2. “关系探索”必须先选唯一中心资产，再按 1 跳/2 跳和明确方向展开；同名表通过物理键消歧。
3. “证据审核”只呈现关系置信度、验证状态、证据来源和待审核原因，不与普通浏览控件混用。
4. 表节点以中文名称为主标题、技术表名为副标题；没有中文名时才回退技术名，不得显示空白或对象字符串。
5. 系统、数据源、Schema/Owner、表/视图是物理层级；业务域是正交标签，不能伪装成物理父子层级。
6. 默认图、筛选图和中心探索图都由服务端按完整数据聚合或查询，不能对已截断的 120 条关系在浏览器内二次聚合后冒充全量结果。
7. 1440×900 真实浏览器中，默认视图无需放大即可读出主要节点名称；控制台异常、未处理 Promise 和契约错误均为 0。

## 2. 已核实基线与根因

### 2.1 生产表现

2026-08-09 只读核查的默认正式关系图：

| 指标 | 当前值 | 问题 |
|---|---:|---|
| 命中关系 | 192 | 已超过默认展示上限 |
| 返回关系 | 106 | 返回的是截断后的关系页 |
| 返回节点 | 127 | 全部挤入同一画布 |
| `truncated` | `true` | 前端聚合结果不完整 |
| 有中文名节点 | 0/127 | 资产表已有中文名但图节点未富化 |
| 有业务域节点 | 0/127 | 资产表已有业务域但图节点未富化 |

证据截图 `backend/scripts/evidence-119/accept_round_0.png` 显示大量固定小矩形被 `autoFit=view` 整体缩小，节点和关系都不可读。119 号只解决 G6 运行时崩溃，不能替代本次可用性整改。

### 2.2 后端根因

关系端点与表资产存在历史兼容差异：

- `asset_relations.from_namespace_name/to_namespace_name` 大量为 `NULL`；
- 对应 `asset_tables.namespace_name` 常等于 `schema_name`；
- `_table_map_by_physical_key()` 查询时允许 namespace 宽松匹配，但返回字典仍按表记录的完整实际键建立；
- 边端点使用关系记录中的空 namespace 取字典，最终 miss，中文名、业务域、角色、治理状态、字段数均丢失。

这里不能简单批量改写正式关系端点。正确方式是把“关系身份键”和“元数据富化查找键”分开：关系身份继续保持稳定，元数据查找按明确兼容规则解析，遇到多匹配必须失败关闭并进入诊断。

### 2.3 前端根因

- `AdvancedRelationGraph.vue` 把普通表统一画成 `rect`，默认约 126×42、字号 11；
- 默认 `autoFit: "view"` 会为了容纳全部节点继续缩小文字；
- `GraphToolbar.vue` 同时暴露 7 种视图模式、分组、布局、表名自由输入、方向、跳数和多组平铺筛选；
- `index.vue` 邻居查询只提交模糊 `table`，没有提交唯一 `physical_key`；
- `/graph/options` 返回全局扁平字符串列表，没有父子约束、计数、禁用原因或选中路径；
- 系统/Schema/业务域聚合在浏览器里基于已截断关系页计算，得到的是不完整且有偏的“概览”。

## 3. 目标信息架构

只保留三个顶层任务模式：

| 模式 | 用户问题 | 默认粒度 | 可用控件 |
|---|---|---|---|
| 资产概览 | 有哪些系统、库、Owner 和资产，规模如何 | 系统→数据源→Schema/Owner | 层级钻取、业务域筛选、类型筛选、返回上级 |
| 关系探索 | 某张表与谁有关，方向和证据是什么 | 中心表+1跳 | 中心搜索、方向、1/2跳、关系类型、证据侧栏 |
| 证据审核 | 哪些关系可信、待核或冲突 | 关系/证据 | 置信度、验证状态、来源、异常类型、审核入口 |

模式切换必须重置不适用于新模式的瞬时状态，不能把“上游+2跳”残留到资产概览。

### 3.1 物理层级与业务维度

物理层级固定为：

```text
业务系统
  └─ 数据源/数据库实例
      └─ Schema / Owner / Namespace
          └─ 表 / 视图
              └─ 字段（仅在详情抽屉中按需加载）
```

业务域、数据分级、表角色、治理状态属于标签或筛选维度，不得作为物理父节点。页面文案统一使用“数据源/数据库”和“Schema/Owner”，不要同时出现“系统库、系统大类、表空间、库类型”等未定义术语。

### 3.2 方向语义

普通外键/逻辑关联没有可靠数据血缘含义时，方向文案必须为：

- 全部方向；
- 引用它（入边）；
- 它引用（出边）。

只有关系类型明确为 lineage 且证据包含血缘方向时才显示“上游/下游”。方向的后端枚举仍可保持 `both/in/out` 兼容，前端显示文案由关系语义决定。

### 3.3 跳数语义

- 未选择中心表时隐藏或禁用跳数和方向，并给出“请先选择中心资产”；
- 选中中心表后默认 1 跳；
- 2 跳必须显示预计节点数，超过阈值先提示收窄筛选；
- 本轮不开放大于 2 跳的交互，避免不可控毛线团；
- 切换中心表后清空已展开节点和旧的分页游标。

## 4. 后端详细解决方案

### 4.1 统一物理键与富化键

在 `backend/app/services/relation_identity.py`（或等价服务）中定义并复用两种对象：

```python
PhysicalKey = (system_code, source_code, schema_name, namespace_name, object_name)
MetadataLookupKey = (system_code, source_code, schema_name, object_name)
```

要求：

1. `physical_key` 是节点稳定身份，不允许使用中文名、显示名或数组序号生成。
2. 富化先按完整物理键精确匹配。
3. 精确未命中时，只允许 namespace 为 `NULL`、空串或等于 schema 的兼容集合内按四元组查找。
4. 兼容查找只有唯一候选时才富化；0 个保留未解析，多个则标记 `ambiguous_metadata_match=true`，不得随便取第一条。
5. 把 exact/compatible/unresolved/ambiguous 数量写入 `meta.enrichment` 和 diagnostics，便于验收。
6. 不在本阶段直接批量改写 `asset_relations` 历史端点；若后续确需治理，另立迁移/审核任务。

建议响应字段：

```json
{
  "physical_key": "DATA_CENTER|ods_8_216|HIS|HIS|PAT_VISIT",
  "system_code": "DATA_CENTER",
  "source_code": "ods_8_216",
  "schema_name": "HIS",
  "namespace_name": "HIS",
  "object_name": "PAT_VISIT",
  "object_type": "table",
  "display_name": "病人住院主记录",
  "technical_name": "HIS.PAT_VISIT",
  "business_domain": "就诊",
  "metadata_match": "namespace_compatible"
}
```

`display_name` 必须是字符串；优先中文名，缺失时回退 object_name。`technical_name` 始终保留，作为消歧信息。

### 4.2 增加服务端聚合接口

保留现有 `/api/v1/graph`、`/api/v1/graph/options`、邻居和详情路径，新增或版本化以下只读端点：

#### A. `GET /api/v1/graph/overview`

参数：

- `level=system|source|schema|object`；
- `parent_physical_key`（除 system 外必填）；
- `business_domain`、`object_type`、治理状态等可选筛选；
- `limit/cursor`，禁止无界返回。

服务端基于完整匹配集合聚合，返回聚合节点、父子边、总数、当前路径和是否截断。聚合节点稳定键应包含层级和父路径，不能只用显示名。

#### B. `GET /api/v1/graph/filter-options`

输入当前已选物理路径和模式，输出下一级选项：

```json
{
  "selected_path": {"system":"DATA_CENTER","source":"ods_8_216"},
  "next_level":"schema",
  "items":[{"value":"HIS","label":"HIS","count":273,"disabled":false}],
  "business_domains":[{"value":"就诊","count":18}],
  "object_types":[{"value":"table","count":220},{"value":"view","count":53}]
}
```

每次父级变化后，下级选择必须清空并重新请求。禁止把四组无关全局数组一次性丢给前端。

#### C. `GET /api/v1/graph/tables/search`

参数至少包含 `q`、已选路径、`limit<=30`。搜索中文名、技术名和完整限定名，返回唯一 `physical_key`、层级路径、对象类型和业务域。相同 `PAT_VISIT` 必须显示系统/源/Owner 消歧。

#### D. 中心邻居查询

现有邻居路径保持兼容，但新前端只使用 `physical_key`：

- `center_physical_key` 必填；
- `depth=1|2`；
- `direction=both|in|out`；
- `relation_types` 可选；
- 返回 `center`、`nodes`、`edges`、`meta` 和 `warnings`；
- `meta` 含 matched/returned/truncated/enrichment/estimated_total；
- 中心键不存在返回 404，歧义键返回 409，契约错误返回 422，不能静默退回模糊表名。

### 4.3 证据与审核契约

边列表只返回轻量摘要：关系类型、方向、置信度、验证状态、证据数量、稳定业务键。点击边后按既有 `/graph/edges/{id}` 拉取详细证据。

证据审核模式至少区分：

- 正式且已验证；
- 候选待核；
- 冲突/歧义；
- 跨系统延后；
- 解析但未匹配资产。

严格沿用 `40` 的 A/B/C/D 治理口径。历史 SQL、视图依赖只能先作为证据；未经审核不得自动提升为正式关系。

### 4.4 性能与可观测性

- 概览聚合使用数据库侧 group/count，并对常用物理键列检查索引；未经测试不得盲目加索引。
- 对同一过滤组合使用短 TTL 缓存时，缓存键必须包含租户/权限范围、模式、完整筛选和数据版本。
- `meta.query_ms`、`meta.matched_total`、`meta.returned_nodes`、`meta.truncated` 必须可见。
- 记录 correlation ID、接口、耗时、数量和错误类别；不得记录 Token、查询凭据或敏感业务数据。
- 节点阈值建议：概览 <=80，探索默认 <=60；超过阈值服务端给出 `NARROW_FILTER_REQUIRED`，前端不强行渲染。

## 5. 前端详细解决方案

### 5.1 页面状态模型

`frontend/src/views/asset/graph/index.vue` 将状态拆为：

```text
mode
physicalPath = system/source/schema
businessFilters
centerPhysicalKey

requestState = idle/loading/success/empty/error

```

每个模式只组装本模式请求参数。任何请求必须用递增 request id 或 AbortController 防止旧响应覆盖新状态。

### 5.2 工具栏重构

重写 `GraphToolbar.vue` 为三段：

1. 顶部任务切换：资产概览 / 关系探索 / 证据审核。
2. 当前模式的主操作区：
   - 概览：面包屑、下钻层级、业务域、对象类型；
   - 探索：中心资产搜索、方向、1/2跳、关系类型；
   - 审核：证据来源、置信度、验证状态、异常类型。
3. 通用画布操作：适应内容、1:1、放大、缩小、重新布局、图例。

布局算法移至“更多/重新布局”，不作为业务筛选。删除自由输入表名后直接模糊查询的主路径。

### 5.3 节点视觉规范

`graphTransform.ts` 和 `AdvancedRelationGraph.vue` 按类型映射：

| 类型 | 建议外观 | 主标题 | 副信息 |
|---|---|---|---|
| 系统 | 圆角大卡片/六边形 | 系统中文名 | 数据源数、资产数 |
| 数据源 | 圆柱语义卡片 | 数据源显示名 | 类型、Schema数 |
| Schema/Owner | 分组容器/圆角卡片 | Owner 名 | 表/视图数 |
| 表 | 横向圆角卡片 | 中文表名 | `OWNER.TABLE`、字段数、业务域 |
| 视图 | 带视图徽标的卡片 | 中文名或视图名 | `OWNER.VIEW`、依赖数 |
| 中心表 | 加粗描边+中心标识 | 同表节点 | 不靠颜色单独表达 |

硬要求：

- 表卡建议宽 180–240、高 64–84，按受控范围适配文本；
- 主标题最多两行，副标题一行省略，悬浮展示完整内容；
- 字号不低于 12px，主标题建议 14px；
- 颜色、形状、徽标至少两种线索共同表达类型，满足色觉差异；
- 禁止把完整字段清单塞入节点；字段在右侧抽屉按需加载；
- 默认不显示所有边文字，选中/悬浮时显示关系摘要；
- 超过可读节点阈值不调用 `autoFit=view` 无限缩小，改为提示收窄或分层钻取。

### 5.4 布局与交互

- 概览用层次/径向布局，物理父子关系方向稳定；
- 中心探索用中心辐射或约束力导布局，中心固定，1跳和2跳分圈；
- 审核用按状态分组的层次布局；
- 单击节点：选中并打开摘要；双击或显式按钮：下钻/设为中心，避免单击误跳；
- 单击边：打开证据抽屉；
- 支持键盘聚焦、Esc 关闭抽屉、清楚的加载/空/错误状态；
- 图例只显示当前图实际存在的类型和状态。

### 5.5 错误与空态

至少区分：权限不足、登录失效、中心不存在、中心歧义、筛选无结果、结果过大、后端契约错误、渲染错误。G6 渲染失败保留现有 SVG 回退，但回退发生必须显示非敏感诊断编号，不能伪装成功。
