## 4. 给「探索计划 AI」的输入约束（必读）

1. **方法与门禁**：元数据采集走 8.83 容器受控连接器（`ops-runbook` Skill §1 标准件 + sjzc 技能 live 通道）；夜间窗口执行批量采集；导入平台走幂等（139/155 先例：备份→dry-run→apply→二次收敛 0）；只读，业务源库写入恒为 0。
2. **优先序建议**：B 类 14 系统按业务价值排（急诊/病案/院感/新输血/科研/医保正式 > 预约/叫号/不良事件/互联互通/听力 > 测试库与早期空登记复核）。
3. **特殊口径**：院感是 Oracle 12c（容器名/PDB 语义与 11g 不同）；科研 MySQL 非标端口 4306；听力是国产兼容 PG（HuaChainSQL，按 PG 协议连）；互联互通多 schema 按业务 schema 采；新输血用 Xiheng_user（不用 sa）。
4. **采集深度**：首轮表级（表/视图清单+字段+注释+行数估算），参照 155/159；关系/值域/质控深化在表级完成后另行立项。
5. **C 类解锁是协作项**：计划里把"需向厂家/网络科申请的清单"单独成节（照 §3 表），不要把解锁假设为已具备。
6. 安全红线照 AGENTS.md：凭据零落盘零外显；Excel 原件（全院明文密码）建议收编后移除，密码轮换入 G12。
