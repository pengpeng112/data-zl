## 4. 数据安全分类分级设计

### 4.1 多维标签，禁止混为一个等级

| 维度 | 建议内容 |
|---|---|
| 业务分类 | 身份、就诊、诊断、检验、检查、手术麻醉、用药、护理、病历、费用、随访、管理等；支持树形分类和多标签 |
| 信息形态 | 结构化、自由文本、图像、音视频、时序、衍生特征、向量、模型工件 |
| 个人信息属性 | 非个人信息/个人信息/敏感个人信息/待核；身份标识、医疗健康、未成年人等可多选 |
| 内部保护等级 | 项目内部 P1—P4，见下表；不是等保级别或国家数据分级的替代 |
| 法定/行业识别 | 一般数据、重要数据识别状态、核心数据识别状态及依据；未识别保持待核，不自行认定为一般数据 |
| 处理状态 | 原始、去标识化、脱敏展示、匿名化待评估、匿名化已评估；不因脱敏自动改变其他标签 |
| 使用条件 | 用途、项目/机构、法律依据或授权引用、有效期、保留期限、地域/环境、可否导出或进入训练 |

业务“核心表”只表示业务优先级，不能映射成法律意义的“核心数据”。重要/核心数据识别依据主管部门目录和适用规则，交有权人员核定；AI 仅提出候选。

### 4.2 内部保护等级草案（上线前经院内审定）

| 等级 | 示例与默认处理 | 最低保护措施 |
|---|---|---|
| P1 已批准公开 | 已审定公开的字典/指标说明/发布结果 | 发布审核、完整性与版本管理；不能仅凭“聚合”判公开 |
| P2 内部 | 非患者级的内部配置、业务统计 | 登录、部门/用途授权、审计、导出控制 |
| P3 敏感 | 患者级医疗事件、去标识化纵向数据、可能识人的统计 | 加密、行列权限、项目隔离、限量查询、到期回收、导出审查 |
| P4 严格受限 | 身份映射、可回识密钥材料、含标识原文、识别风险特别高的组合 | 独立角色/凭据与受限区域、严格服务访问、强认证方案、全程审计、默认禁止下载 |

P1—P4 为项目工程控制草案，不能声称出自 GB/T 43697 的等级编号。密钥只存受控密钥设施，分类元数据仅存 key_ref。未分类默认拒绝普通读取/导出，进入限制区域待定级，不落入 P1/P2。

### 4.3 继承与变更规则

- 字段标签向结果列、表、视图、数据集、导出文件继承；混合结果默认取最高保护等级，并合并用途限制。
- JOIN、纵向关联、自由文本、罕见病、小样本组合会提升识别风险；即使输入等级未变也要重评估。
- 衍生列、SQL 表达式血缘无法解析时保持受限；掩码、哈希、假名化不是匿名化证明。
- 降级须证据、审批人、版本、生效时间及影响分析；保留旧版本记录。修改分类立即影响后续查询、后台任务、缓存和未完成导出。
- 匿名化风险按外部辅助信息、稀有组合、重复查询差分等评估；固定小单元阈值只能作为控制，不能证明法律上的匿名化。

### 4.4 全链路实施点

统一策略判断主体、角色、项目、用途、资源版本、字段、行范围、时间和环境；列表、详情、计数、统计、搜索、下载、对象链接、后台任务均校验，禁止仅前端隐藏。

身份映射与用途假名分开管理：同项目内稳定、不同用途默认不可直接关联；不使用可枚举的身份证普通哈希。密钥轮换有版本和重算策略。

开发使用合成数据；本机、外部 AI、日志、错误堆栈、提示词、Git 不出现真实患者信息或密钥。文书脱敏覆盖正文、附件、页眉、图片文字、DICOM 元数据及可能烧录在像素上的标识；后两者在多模态阶段验收。RAG、向量和模型工件纳入同类访问、保留与泄漏评估。

数据流转审计保留主体、用途、资源版本、规则、动作、结果和理由，不记录原始患者值。审计禁止普通账号修改；拒绝请求也留痕。导出采用受控目录、有效期、下载授权和审计，不生成永久公共链接。

撤销/删除：按法律依据、保留义务和授权到期区别处理；传播至缓存、导出、派生数据、向量及下游使用方。必要保留采用受限封存，不能无条件硬删；备份按到期策略处理，恢复后重放删除/撤销清单。已训练模型不能假定删除样本即消除影响，按评估决定停用、重训或其他处理。

技术边界：

1. 来源适配器负责分页、类型序列化、水位、删除语义；清洗规则不依赖某台服务器地址。目标写入器与源只读凭据彻底分离。
2. 加工步骤包含固定输入/输出版本、幂等键、重试/取消/超时/资源预算和质量断言；优先复用现有调度，不新增并行调度权威。
3. 临时输出完成质量和安全检查后原子切换为发布版本；失败保留前一有效版本。检查点和写入提交边界一致，重跑不会漏数或重数。
4. 采集记录旧值修改、迟到、撤销、删除；无可靠更新时间/日志时，制定分区回查和对账策略并明示无法保证的部分。
5. schema 漂移：新增字段默认受限；兼容扩展在验证后纳入；类型/键/语义变化隔离该源，其他独立任务可继续。
6. 业务时间、结果可用时间、平台时间分别记录；跨源没有共同快照时记录各水位和允许时差。训练特征以预测时点实际可用信息为准。
7. 数据集版本状态建议 draft→validated→approved→published→deprecated/revoked；验证通过不自动获得人工批准，撤销后禁止新下载。状态机在 B03/B10 定稿。
8. 新来源、新病种、新模态通过适配器/规则/产品定义扩展；OMOP、FHIR、ClickHouse、Iceberg 是可选出口/引擎，不作为底座表的强耦合依赖。

## 7. 新旧一致性与高质量验收口径

对账至少同时保留：来源记录数、逻辑事件数、纳入/排除/隔离数、合并映射数量和原因。去重为多对一，不能简单用“源行数=目标行数”验收；目标中的每条事实及每条被排除记录都有去向或依据。

质量分为来源覆盖、身份准确、关联完整、语义有效、时间合理、时效、可追溯、用途适合八类。每项必须有分母、范围、版本、阈值、容差和严重度，不用单一总分掩盖关键错误。

建议的硬门禁（工程要求，非法律阈值）：

- 发布清单、来源/规则/身份/安全版本引用齐全率 100%；权限反例用例全部拒绝。
- 合成黄金样例中已知错误合并为 0；真实患者匹配采用有代表性的人工核验样本，报告误合并/漏合并及不确定性，不能以“小样本零错”声称总体零错。
- 所有必需对账均执行；未解释关键差异、关键来源缺片、未知质量分母阻止认证。源本身缺陷可在用途允许并披露后保留，不能为通过验收伪造完整。
- 安全审批和质量认证独立：高质量不等于可训练或可交易，获准使用不等于数据质量合格。
- 性能、同步延迟、恢复时间/可接受数据损失目标由 B01 提案、B17 实测、B18 前确认，不写未经测试的承诺。
