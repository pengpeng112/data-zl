### DEF-04 账号禁用后旧 JWT 仍然有效
- P1（安全）｜高｜后端认证中间件｜app/main.py:497-507
- 复现：登录 r194_expiring 取 token → `UPDATE asset_auth_users SET enabled=false` → `GET /api/v1/auth/me`。
- 预期：401/403（账号已禁用）。
- 实际：200；受角色门禁的接口也按原角色继续放行。登录入口本身正确拒绝（401）。
- 根因：中间件 JWT 路径 decode 后只解析角色，不复核 AuthUser.enabled/存在性；会话表过期同样不影响无状态 JWT。
- 影响：禁用/撤号在 access token 自然过期前不生效（I12 断言失败）。
- 建议：JWT 路径增加账号状态复核（或短时效+黑名单）。
- 回归：I12-disabled-token。

### DEF-05 官方 RBAC 种子脚本产生的权限行在运行时全部无效（action 值漂移）
- P1（部署/bootstrap）｜高｜backend/scripts/seed_platform_rbac.py vs app/core/security.py:59-61
- 复现：空库迁移后运行 `python -m scripts.seed_platform_rbac` → 用任意非 platform_admin 角色账号访问带权限码端点。
- 预期：角色默认权限生效。
- 实际：全量 403（例：asset_viewer 访问 /quality-issues → 缺少权限: quality.issue.read；quality_admin 同样全拒）。
- 根因：seeder 写 `action="allow"`，运行时 granted 逻辑仅当 action∈{None,"","access","*"} 时按裸 resource 匹配；"code:allow" 归一化后多一段不匹配。测试套件与 permissions API（permissions.py:424/495）均写 "access"，唯 seeder 漂移。
- 影响：按仓库文档初始化的新环境，非管理员角色全部不可用（fail-closed，无越权风险）。
- 建议：seeder 改 "access" 或匹配函数兼容 allow。
- 回归：bootstrap 后 viewer 访问 3 个默认权限端点全 200。
- 备注：本轮隔离环境已将夹具修正后继续测试（`update asset.asset_role_permissions set action='access'`，236 行）。2026-09-18 复核更正：该修正**未独立落盘**（environment.json/seed_summary.json 均无记录，原"记录于 environment.json"说法失实）；复现方式=重跑种子后执行上述 update。
