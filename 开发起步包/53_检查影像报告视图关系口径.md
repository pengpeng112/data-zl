# 检查影像报告视图关系口径

> 来源：用户提供的山东省第二人民医院检查/影像报告视图梳理。
> 适用范围：HISUSER/HIS 源端检查、影像报告相关 SQL 和视图生成，尤其是 `V_INP_EXAM_REPORTS` 类视图。
> 状态：用户确认口径，后续 AI 写视图时优先沿用；如需变更，必须先做只读验证并记录新证据。

## 1. 核心表

### 1.1 检查主表

`EXAM.EXAM_MASTER em`

| 字段 | 含义 |
|---|---|
| `EXAM_NO` | 主键 / 报告号 |
| `PATIENT_ID` | 患者号 |
| `VISIT_ID` | 住院就诊次数 / 门诊流水相关字段 |
| `RCPT_NO` | 收费号 |
| `ORDER_ID` | 医嘱 / 申请相关字段，正式口径不作为门诊主关联 |
| `REQ_DATE_TIME` | 申请时间 |
| `EXAM_DATE_TIME` | 检查时间 |
| `REPORT_DATE_TIME` | 报告时间 |
| `REQ_DEPT` | 申请科室 |
| `PERFORMED_BY` | 执行科室 |
| `REQ_PHYSICIAN` | 申请医生 |
| `EXAM_CLASS` | 检查类别 |
| `EXAM_SUB_CLASS` | 检查子类 |

### 1.2 检查报告表

`EXAM.EXAM_REPORT er`

| 字段 | 含义 |
|---|---|
| `EXAM_NO` | 关联检查主表：`er.EXAM_NO = em.EXAM_NO` |
| `REPORT_TIME` | 报告时间 |
| `DESCRIPTION` | 检查所见 |
| `IMPRESSION` | 检查结论 |

报告时间优先级：`NVL(er.REPORT_TIME, em.REPORT_DATE_TIME)`。

### 1.3 住院就诊表

`MEDREC.PAT_VISIT pv`

住院检查关联：

```sql
pv.PATIENT_ID = em.PATIENT_ID
AND pv.VISIT_ID = em.VISIT_ID
```

住院部分该关联口径基本可用，后续不要轻易修改。住院流水号建议：

```sql
pv.PATIENT_ID || '_' || TO_CHAR(pv.VISIT_ID)
```

### 1.4 患者主索引

`MEDREC.PAT_MASTER_INDEX pmi`

关联：

```sql
pmi.PATIENT_ID = em.PATIENT_ID
```

用于补充 `pmi.NAME`、`pmi.INP_NO` 等基础信息。

### 1.5 门诊收费/治疗明细

`OUTP_TREAT_REC a`

门诊检查回填就诊流水号的关键表。与门诊就诊主表关联：

```sql
a.VISIT_DATE = b.VISIT_DATE
AND a.VISIT_NO = b.VISIT_NO
```

关键字段：`APPOINT_NO`、`ORDER_ID`、`ITEM_CLASS`、`CHARGE_INDICATOR`。

### 1.6 门诊就诊主表

`CLINIC_MASTER b`

关键字段：`PATIENT_ID`、`CLINIC_NO`、`VISIT_DATE`、`VISIT_NO`。

### 1.7 科室字典

`COMM.DEPT_DICT`

```sql
req_dept.DEPT_CODE = em.REQ_DEPT
exec_dept.DEPT_CODE = em.PERFORMED_BY
```

## 2. 门诊 / 住院判断原则

1. 若 `MEDREC.PAT_VISIT` 能通过 `PATIENT_ID + VISIT_ID` 命中 `EXAM.EXAM_MASTER`，认为是住院检查记录。
2. 住院记录就诊流水号使用 `pv.PATIENT_ID || '_' || TO_CHAR(pv.VISIT_ID)`。
3. 若 `PAT_VISIT` 未命中，则按门诊检查处理，通过 `OUTP_TREAT_REC + CLINIC_MASTER` 回填门诊流水号。

## 3. 门诊检查正式关联口径

门诊检查正式主口径：

```sql
OUTP_TREAT_REC.APPOINT_NO = EXAM_MASTER.EXAM_NO
```

必须同时限制：

```sql
a.ITEM_CLASS = 'D'
AND a.CHARGE_INDICATOR = '1'
AND a.APPOINT_NO IS NOT NULL
```

再关联门诊主表：

```sql
a.VISIT_DATE = b.VISIT_DATE
AND a.VISIT_NO = b.VISIT_NO
```

推荐 SQL 片段：

```sql
LEFT JOIN (
    SELECT
        appoint_no,
        patient_id,
        clinic_no,
        visit_date,
        visit_no
    FROM (
        SELECT
            TO_CHAR(a.appoint_no) AS appoint_no,
            TO_CHAR(b.patient_id) AS patient_id,
            TO_CHAR(b.clinic_no)  AS clinic_no,
            b.visit_date          AS visit_date,
            TO_CHAR(MIN(b.visit_no)) AS visit_no,
            ROW_NUMBER() OVER (
                PARTITION BY TO_CHAR(a.appoint_no)
                ORDER BY b.visit_date, MIN(b.visit_no), TO_CHAR(b.clinic_no)
            ) AS rn
        FROM outp_treat_rec a
        JOIN clinic_master b
          ON a.visit_date = b.visit_date
         AND a.visit_no   = b.visit_no
        WHERE a.item_class = 'D'
          AND a.charge_indicator = '1'
          AND a.appoint_no IS NOT NULL
          AND b.visit_date >= DATE '2026-01-01'
        GROUP BY
            TO_CHAR(a.appoint_no),
            TO_CHAR(b.patient_id),
            TO_CHAR(b.clinic_no),
            b.visit_date
    )
    WHERE rn = 1
) e_or
       ON e_or.appoint_no = TO_CHAR(em.exam_no)
      AND e_or.patient_id = TO_CHAR(em.patient_id)
```

## 4. 需要先聚合门诊明细的原因

1. `OUTP_TREAT_REC` 是收费/治疗明细表，同一个 `APPOINT_NO` 下可能有多条收费明细。
2. 若直接用 `e_or.APPOINT_NO = em.EXAM_NO` 明细关联，会导致检查报告视图行数放大。
3. 已核查：`APPOINT_NO` 非空时没有串到多个 `PATIENT_ID + CLINIC_NO`；重复主要来自同一个 `APPOINT_NO` 下多条收费明细。
4. 因此先 `GROUP BY` 后用 `ROW_NUMBER()` 取 `rn=1` 是当前正式口径。
5. 修复后核查：`V_INP_EXAM_REPORTS` 总行数 298048，去重数 298048，重复明细 0 行。

## 5. ORDER_ID 口径结论

曾比较两个口径：

| 口径 | 说明 |
|---|---|
| A | `OUTP_TREAT_REC.APPOINT_NO = EXAM_MASTER.EXAM_NO` |
| B | `OUTP_TREAT_REC.ORDER_ID = EXAM_MASTER.ORDER_ID` |

2026 年后检查数据核查结果：

| 指标 | 数值 |
|---|---:|
| 检查总数 | 298043 |
| `EXAM_MASTER.ORDER_ID` 非空数 | 7223 |
| `APPOINT_NO` 口径命中数 | 141450 |
| `ORDER_ID` 口径命中数 | 7223 |
| 两者都命中数 | 7223 |
| 两者门诊号一致数 | 7222 |
| 两者门诊号不一致数 | 1 |
| 仅 `APPOINT_NO` 命中数 | 134227 |
| 仅 `ORDER_ID` 命中数 | 0 |
| 两者都未命中数 | 156593 |
| `APPOINT_NO` 一对多风险数 | 0 |
| `ORDER_ID` 一对多风险数 | 1 |
| `APPOINT_NO` 患者不一致数 | 0 |
| `ORDER_ID` 患者不一致数 | 1 |

结论：`ORDER_ID` 覆盖很低，没有独有命中，还存在患者不一致和一对多风险。正式视图不要使用 `EXAM_MASTER.ORDER_ID = OUTP_TREAT_REC.ORDER_ID` 作为主关联口径。

## 6. `V_INP_EXAM_REPORTS` 推荐字段逻辑

### 6.1 就诊流水号

优先级：住院优先，门诊其次，最后兜底 `em.PATIENT_ID + em.VISIT_ID`。

```sql
NVL(
    CASE
        WHEN pv.patient_id IS NOT NULL THEN
            pv.patient_id || '_' || TO_CHAR(pv.visit_id)
        ELSE
            NULL
    END,
    NVL(
        e_or.clinic_no,
        em.patient_id || '_' || TO_CHAR(em.visit_id)
    )
) AS "就诊流水号"
```

### 6.2 住院号

```sql
NVL(pv.inp_no, pmi.inp_no)
```

### 6.3 住院次数

```sql
NVL(
    TO_CHAR(pv.visit_id),
    NVL(e_or.visit_no, TO_CHAR(em.visit_id))
)
```

### 6.4 就诊时间

```sql
NVL(
    pv.admission_date_time,
    NVL(
        e_or.visit_date,
        NVL(em.req_date_time, em.exam_date_time)
    )
)
```

### 6.5 报告时间

```sql
NVL(er.report_time, em.report_date_time)
```

## 7. 后续 AI 写视图时的硬规则

1. 住院部分优先沿用 `MEDREC.PAT_VISIT` 的 `PATIENT_ID + VISIT_ID` 关联，不要随意改。
2. 门诊部分必须先聚合 `OUTP_TREAT_REC`，不允许直接明细表关联。
3. 不建议使用 `ORDER_ID` 作为正式关联主口径。
4. 查询 2026 年以后的检查数据时，门诊 `e_or` 子查询建议限制 `b.VISIT_DATE >= DATE '2026-01-01'`。
5. `EXAM.EXAM_REPORT` 不含患者主键，必须经 `EXAM_NO` 关联 `EXAM.EXAM_MASTER` 后再补患者、住院、门诊信息。
6. 任何变更必须先做只读验证：总行数、业务主键去重数、重复明细数、患者不一致数、一对多风险数。
