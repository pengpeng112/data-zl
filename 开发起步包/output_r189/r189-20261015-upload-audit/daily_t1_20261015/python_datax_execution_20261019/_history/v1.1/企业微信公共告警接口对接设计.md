# 企业微信公共告警接口对接设计

## 1. 依据、职责及当前状态

主依据：`F:/python/前后端代码/qywx/docs/08_通用告警推送公共接口对接指南.md`；v2完整协议补充：同目录`06_v2接口与连接器接入指南.md`。08描述公共接口已在生产使用，06保留早期“生产另批”历史说明；当前客户端仍需管理员确认部署地址、可达路径、独立源、订阅及凭据，不能以文档自称已运行推断本任务已接通。

在抽取工程实现AlertClient+持久化Outbox+投递状态跟踪，复用公共relay的订阅路由；不新建企微机器人服务、不修改qywx仓库代码、不在请求指定收件人。本包只做契约及模拟验收计划，真实注册/配置/联调/外发均未执行。指南003966为联调示例账号，不自动视为本任务获准收件人。

采用v2为告警主路径：

- `POST http://10.20.1.153:3000/api/v2/events`：202持久化入队；200 duplicate为幂等命中；两者均不直接证明送达。
- `GET http://10.20.1.153:3000/api/v2/events/{event_id}`：event_id是POST返回的服务端UUID，不是source_event_id。仅查自身源，签名body为空字节。
- 按任务列表区分pending/processing/sent/dead/cancelled/needs_attention及outcome_uncertain。所有期望目标sent且没有不确定项才标客户端DELIVERED；零目标、部分失败或取消均不能显示已通知成功。sent只证明relay目标投递成功，不证明人已阅读或故障已处理。

v1发完即走不作为本轮关键告警的默认路径。日报推送可选，默认关闭；若启用也用同一客户端和持久记录，不靠另一个临时脚本发消息。

## 2. 触发条件和分级

类别建议固定`category=sanjia_etl`，源候选`sanjia-etl`，实际值由管理员登记/订阅确认后填写，不能假定已存在。接入配置默认enabled=false，凭据未知保持WAITING_INTEGRATION_SETUP，软件模拟和其他抽取任务继续。

| 代码 | 条件 | 级别与时机 |
|---|---|---|
| EXTRACT_FAILED | 源连接/SQL/驱动失败、读取不完整、DataX非0或dirty | yellow首次受控重试后仍失败；接近截止/涉及关键来源则red |
| SOURCE_LATE | 源或ODS未到约定可见点、异常零行不能证真零 | yellow，超过已确认延迟预算/影响deadline升级red |
| VIEW_BLOCKED | INVALID、缺时间/字段、历史上界、定义漂移等阻断 | yellow并生成局部人工工单；已影响截止升级red |
| QUALITY_BLOCKED | 必填/值域/字节精度、冲突ID、父键异常或数据隔离 | yellow；已证重大错连、广泛冲突或无可用合法版本red |
| RECONCILE_DIFF | 受控同范围ID缺失、内容或关系存在未解释差额 | red，不以条数相等或重试次数掩盖 |
| COMMIT_UNKNOWN | 正式提交结果不明、回执/平台状态不一致 | red立即提醒，内容要求先对账、禁止盲重写 |
| WORKER_STALE | worker/调度长期无心跳、租约异常、队列无法推进 | 独立巡检产生red；检测阈值依据实际心跳预算 |
| SLA_AT_RISK | 预计剩余处理/重试时间超过deadline余量 | yellow提前、red逾期；deadline未知显示待配置，不捏造省要求 |
| DELIVERY_REJECTED | 省端拒绝或应有反馈超时 | yellow/red按截止和范围；与企微relay投递失败分开 |
| ALERT_DELIVERY_FAILED | relay入队/状态查询/目标投递失败或队列积压 | 本地异常及独立监测，不能向同一坏通道无限递归发告警 |
| RECOVERED | 对应失败已复核恢复，或差异/工单已闭合 | blue notice，用新事件关联原incident，不把原告警内容改掉 |

阈值、静默/聚合窗口、升级余量、值守规则均是候选配置，管理员/业务确认后生效。red阻断事件不因常规静默完全丢失；计划维护可标记MAINTENANCE及范围/到期，但仍留本地事件与日报。

## 3. 事件与去重规则

`incident_key`按环境/任务/规范表/错误类别/受影响窗口或组范围构造摘要，不含患者键、密码或原SQL。连续同源连接失败可聚合一个源级incident，并在本地关联受影响表；避免77条重复刷屏，表级影响仍要完整可查。

每个incident有OPEN、ESCALATED、RECOVERED等生命周期事件及单调revision。`source_event_id`使用短namespace+incident_uuid+event_kind+revision，≤200字符。初次发送前冻结包括occurred_at、body和metadata的**确切UTF-8请求字节**及payload_hash并持久化。

- 同一事件重试：source_event_id、全部请求体字节完全不变，更新header时间戳/签名。不得每次重算occurred_at、追加尝试次数或改body导致409。
- 状态升级、周期提醒/计数快照、恢复通知：新revision和新source_event_id，原事件不可变。次数/最新错误在本地状态更新，不能偷偷改旧payload。
- 同源故障抑制与聚合建议初始窗口10分钟、持续故障30分钟提醒，最终按值守需求配置；这是频控候选，不是硬编码生产规则。severity升级和首次恢复按新事件及时通知。
- 重试时当前秒未变会得到相同HMAC签名；至少等跨到新秒再重签，不人为跳时钟绕防重放。通道时钟须同步，偏差按指南±300秒。

展示消息示例（合成、未发送）：

```text
标题：[三甲上报] 影像路径抽取失败
正文：业务日期：2026-10-19。
来源：HIS影像；对象：V_EMR_EXAM_IMAGE_PATH。
失败环节：源数据读取，错误类别：连接失败。
影响：本批路径数据尚未完成，主报告处理状态需在任务页核对。
处理要求：检查源连接；恢复后按原批次范围重试。请勿直接重写正式数据。
```

真实发送使用实际批次脱敏摘要；affected_records未知就写未知，不编造条数或把读到的部分当总量。内部batch_id/incident_id等仅用于管理员定位，可放metadata，不把患者ID、姓名、证件、电话、地址、正文或路径载荷放消息。

metadata按白名单构造，最多32键，建议仅system、environment、canonical_table、source_group、stage、business_date、batch_id、incident_id、error_class、error_code、affected_count、task_status、ticket_ref、deadline、detail_ref等。detail_ref为需权限访问的内部任务详情引用，不带token/患者参数，不用未经校验的外链。错误码仅保留ORA/驱动类别等白名单，不使用str(exception)/完整SQL堆栈做消息body；不能指望relay敏感键脱敏替代发送方脱敏。

## 4. HMAC认证与状态查询

每系统独立source_id和secret，不复用其他业务源。候选配置仅存secret_ref，真实密钥在授权服务器密码库/受控环境解析，禁止入Git、报告、聊天、日志或CLI参数。注册、订阅/收件人、凭据轮换属于管理员动作，本包不自动执行。

发送方算法：

1. 按JSON UTF-8一次序列化并持久化body_bytes。
2. ts为当前Unix秒字符串；signed_bytes = UTF8(source_id + '.' + ts + '.') + body_bytes。
3. HMAC-SHA256(secret,signed_bytes)，hex小写。
4. 发送同一body_bytes，headers包含X-Source-Id/X-Timestamp/X-Signature和Content-Type: application/json。
5. GET签名以空body_bytes计算，不把URL/UUID或JSON空对象加入body；使用响应event_id查询。

base_url限定院内已配置允许地址，发送路径固定/api/v2/events，不能将事件metadata变成任意URL/SSRF入口；控制台收件人通过relay订阅决定，请求里绝不带receivers字段。实现先用本地FakeTransport/模拟服务，真实HTTP请求只能在明确联调范围下做，不在本轮触达生产接口。

## 5. Outbox、重试与投递状态

在既有控制存储复用/新增`asset_reporting_alert_outbox`及incident记录，均为候选资产表，真实迁移另验。任务失败状态与告警事件尽量在同一平台事务提交。sender独立处理outbox，不在DataX进程错误回调中同步循环HTTP阻塞所有任务。

outbox至少包含：event_id_local/source_event_id、incident/revision、immutable_body_bytes/payload_hash、source_id、secret_ref（不含secret）、created_at、next_attempt_at、attempts、relay_event_id、acceptance_state、delivery_state、target_status_summary、last_error_class/HTTPcode、Retry-After、查询次数及到期/待人工原因。调用时再取密钥和新签名。

| 响应/故障 | 客户端行为 |
|---|---|
| POST202 | 保存relay_event_id，标ACK_QUEUED，转状态查询，不当sent |
| POST200 duplicate | 校验返回信息和关联，复用relay_event_id，继续查询目标状态 |
| HTTP超时/断连/不确定5xx | 原ID原字节重试、新时间戳签名；可能已入队，不能换ID重复发 |
| 400/422 | 永久报文错误，停该事件，记录需修代码/配置，不盲重试 |
| 401 | 停通道自动重试并记录凭据/时钟待核，避免5次失败触发锁定；不自动轮换凭据 |
| 409 | 区分防重放与同ID异内容。已证签名重放可跨秒新签名有界重试；内容冲突/无法分类则NEEDS_ATTENTION，不自动换ID掩盖冲突 |
| 429 | 退避至少60秒且尊重更长Retry-After/认证锁定期限；限制本源POST+GET总体频率 |
| 503 | 按Retry-After后重试，原ID原字节；本地队列不丢 |
| 其他5xx | 指数退避+抖动、有最大尝试/最长积压预算，耗尽进待人工队列，不无限循环 |
| GET404 | 核源身份/UUID及可能部署差异，分类待人工或有界查询，不跨源试探，不新建告警刷屏 |
| pending/processing | 按轮询预算等待，候选间隔30—120秒，受实际限流约束 |
| 全期望目标sent且无不确定 | DELIVERED，保留逐目标摘要与时间；不等于人已读 |
| dead/cancelled/needs_attention/部分失败/outcome_uncertain | 不能报全目标送达，记录目标摘要及人工处理，不自行调用admin重放/改目标接口 |
| 零目标/缺任务列表 | ROUTE_UNRESOLVED，管理员核订阅；不要把202和0任务当成功，也不要凭空添加receivers |

管理员修订订阅不保证改变历史事件的冻结目标。需要重放/采用新配置时由管理员按relay流程操作；客户端新提醒事件须有明确新revision与原因，不能原ID改内容。重放可能至少一次投递/结果不确定，不承诺企微终端绝无重复。

候选超时可为连接3秒、读取10秒，具体按院网实测；总重试/积压预算与源QPS配置、业务截止协调。超过预算保留可恢复记录并本地标告警通道异常，不丢弃或把pipeline状态改成功。告警发送失败不阻止合法独立业务组推进，但值守/时效风险必须可见。

控制数据库不可用时，失败摘要写授权worker本地受限脱敏spool，再恢复入outbox并去重；容量/保留期/磁盘阈值有界，溢出必须被独立巡检检测，不能静默丢。worker自身崩溃由独立于被监测进程的既有调度/巡检检查心跳并发送异常；该监测不启动第二套抽取入口。relay也不可用时只记本地/已有获准独立监测渠道，不递归向坏relay发送它自己的失败告警。

## 6. 10批计划中的落点与验收

- E01：管理员接入待办及配置字段/消息隐私契约；收件人只作管理端订阅事项。
- E02：incident/outbox Repository、不可变事件、重试/投递与任务状态分离。
- E03—E05：读失败、质量阻断、提交未知、差集等事件接入统一异常分类，不在适配器重复散发HTTP。
- E06：AlertClient、HMAC、POST/GET、限流去重、升级/恢复、sender与独立心跳检测。
- E07：完整离线正反向场景，人工工单/日报能查告警状态。不得用“模拟202”当企微已送达。
- E08：隔离协议联调与生产审阅材料可分别推进，真实源/订阅/密钥的管理员待办、撤销步骤和凭据保管写清。
- E09：获准后使用指定测试订阅验证入队→查状态→目标收到，禁止为测401/锁定而对生产源反复发错签名；防重放/锁定破坏性用例放隔离模拟环境。
- E10：灰度上线和真实观测，抽取时效、数据质量、告警入队/送达/积压分别验收。恢复推送仅在恢复证据成立时发送，不以简单重试退出0自动闭故障。

对接完成条件：正确签名/字节、原ID重放、异内容冲突、GET空body签名与UUID、202非送达、逐目标状态、鉴权限流、断网重启恢复、隐私、去重恢复、独立失联监测均有实际环境分级证据；真实联调必须有管理员提供的独立source/secret_ref/测试订阅/允许来源IP和具体批准，本包交付时均未完成。
