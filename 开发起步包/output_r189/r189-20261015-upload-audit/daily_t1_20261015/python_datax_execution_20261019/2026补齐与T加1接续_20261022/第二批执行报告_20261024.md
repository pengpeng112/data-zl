## 生产实况暴露并修复的缺陷（全部先隔离验收/单元回归后上线）

镜像 t1→t1k 迭代中修复六项（每项均带单元回归 478 过）：

1. Oracle 计算列数值以 float 返回 → 行源统一 `Decimal(str(v))` 规整（金额精确哈希门禁正确拦截后修复）；
2. 字节长度按 UTF-8 度量误报（前置机 ZHS16GBK：OTHER_ID_NAME 12BYTE vs 视图 5-6 汉字）→ ByteLengthRule 按目标库字符集度量（Oracle 字符集名→Python 编码映射）；质量门两度正确拦截真实宽度风险（含 CURRENT_ADDRESS_VILLAGE 单行超长，GBK 语义下合法）；
3. `SYSTIMESTAMP AT TIME ZONE 'Asia/Shanghai'` 在旧版 Oracle 时区文件报 ORA-01805 → 改 SYSTIMESTAMP 原样取回、Python 侧 +08 换算；
4. 回执绑定类型判断写反（str.isoformat）→ 修正为 datetime→墙钟 isoformat；
5. apply 门禁拒绝发生在 APPLYING 之后导致状态机卡死 → ApplyPort.precheck 公开门禁预检前置 + 拒绝回退容忍非法转换；
6. 列型元数据误用种子包空投影（漏 CHAR 空格规整、漏时间列强转）→ 一律取冻结件真实列型；capture 对视图 VARCHAR2(19) 时间列按冻结目标类型转 datetime。

试点返工留痕：首批 capture 遇早间旧视图状态（OTHER_ID_NAME 全行超宽）与上述缺陷，控制面批次记录清理重跑共 4 次（`试点证据_20261024/`），最终批次一次通过。
