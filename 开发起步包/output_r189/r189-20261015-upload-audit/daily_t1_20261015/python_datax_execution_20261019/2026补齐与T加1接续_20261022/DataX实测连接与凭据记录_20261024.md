# DataX 实测连接与凭据记录（2026-10-24）

## 1. 抽取方式（怎么抽的）

- **引擎**：8.53 上真实 DataX 独立引擎 `/home/datax/bin/datax.py`（DATAX-OPENSOURCE-3.0），**不依赖 datax-web 调度**；
- **调用形态**：`python3 /home/datax/bin/datax.py --mode standalone <job.json>`——脚本本身不可执行且系统只有 python3（无 python），**必须加 python3 前缀**；job 路径是位置参数（引擎无 `--jobfile` 选项）；
- **编排位置**：本地（Windows 工作机）经 SSH/SFTP 编排——job 文件 SFTP 写到 8.53 `/root/.t1_job_*.json`（0600，跑完即删），argv 经 base64 交 8.53 本地 python 执行，stdout 尾部回传解析指标；
- **job 结构（这版引擎的两个硬要求）**：reader 与 writer **都必须用 `connection:[{...}]` 数组结构**（reader：`connection:[{querySql:[...], jdbcUrl:[...]}]`；writer：`connection:[{jdbcUrl, table:[...]}]`）——平铺写法直接 NullPointerException；
- **成功判据**：exit 0 + 读出记录总数=写通信总数（英文 `Total N records ... Error M records` 最后一行）+ 脏数据=0 + 暂存表 COUNT=写通信数（四方一致）；
- **窗口语义**：querySql 内 `锚点列 >= TO_DATE('起','YYYY-MM-DD HH24:MI:SS') AND < TO_DATE('止',...)` 半开区间；
- **驱动**：本地编排用 paramiko 5.0.0（backend/.venv）；引擎侧 MySQL 连接用其自带 mysql-connector-java 5.1.47（连 MySQL 9.x 正常，10-20 先例确认）。
