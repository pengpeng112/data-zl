# 报错后隔离失败范围、告警、继续独立任务

**默认继续。** 某条记录、某个时间窗或某张表失败时，将准确失败范围及断点持久化、发告警、入待补队列，执行其他不受影响的合法任务。失败不能变成成功或永久跳过；本轮有待补时总体为PARTIAL_SUCCESS_WITH_BACKLOG，日报显示未完成表/窗及原因。这里是要实现的行为，尚非运行系统已具备能力。

| 遇到的错误 | 隔离到哪里 | 继续抽什么 | 何时补回 |
|---|---|---|---|
| 单行必填/超长/值域或冲突 | 受影响记录组 | 其他已完整捕获且父键合法的组 | 数据/视图修好后，复核同ID及依赖再按批准规则补 |
| 一个日期窗的SQL/视图错误 | 该窗或该路线 | 其他独立日、其他表/源；未决写入例外见下 | 自动修复软件兼容或人工修视图后按原窗重取 |
| 瞬态断连/监听器故障 | 先该窗；连续失败升级物理源 | 其他正常源 | 有界退避、抖动、冷却后单探针；恢复后原范围补抽 |
| 超行数/字节/执行预算 | 未完整分片 | 其他完整分片/任务 | 时间二分或稳定keyset细分；到最小精度仍无安全入口则待工单 |
| 装载已确认回滚 | 该装载批 | 其他独立表；同表仍守单写/版本 | 保留stage，同一幂等操作恢复 |
| COMMIT_UNKNOWN | **同一目标表全部正式写任务** | 其他不依赖该表的任务 | 核目标同事务凭据/键及内容，确认结果再恢复，不能直接换下一天写 |
| 父表部分失败 | 依赖这些父键的子组 | 已证父键及其他独立组 | 父组成功后恢复对应子组；子载荷留待补 |
| relay暂时发不出去 | 告警通道/outbox | 控制状态正常且安全的抽取 | 持久待投递，有界重试和独立巡检，不能因消息失败全停 |
| 共享控制存储不可用/目标身份不符/无法保证唯一写者 | 实际共享且安全性不可证明的范围 | 其他已证明安全、能持久化的独立范围 | 控制存储/身份/栅栏恢复并核未决操作；仅确实影响全部任务才全局暂停 |

源查询直接抛错、未返回记录时，不能假称已找到“坏的一行”后跳过；只能通过有界拆窗/稳定业务键定位，未定位前该窗保持未完整。重试次数、总时长和最小粒度按每表/路线画像冻结，禁止无限重试、无限拆同一个窗，禁止把失败当作0行。

失败记录至少保存：任务/源身份、原固定起止窗或keyset摘要、配置/定义版本、attempt、安全错误类别和代码、完整清单状态、是否存在未决提交、下次重试/人工恢复条件、责任人及告警incident引用。原始键和载荷仅在受控服务器安全区，普通日报和企微不含患者或原SQL。

允许10月3日失败后继续独立10月4日，但必须保留区间缺口账本，连续捕获水位不能越过未捕获缺片。质量失败与捕获失败不同：只有全部分片已完整捕获且问题组载荷已可恢复时，可按原策略推进捕获游标；质量、装载和省端回执仍是未闭合。晚到历史月轮巡是另一个队列，不能借后续日成功把旧缺口销掉。

告警在第一次失败及显著升级时发出，同源监听器风暴按物理源聚合，保留受影响表/窗摘要，不刷77条相同消息。消息有：对象/窗口、失败分类、当前隔离范围、正在继续的范围、待补数量或未知、下一次尝试/恢复条件、**建议动作**及安全`detail_ref`。后续恢复仅在断点/对账通过后通知，不以进程退出0宣布恢复。

告警发送仍遵守v2不可变字节/幂等revision、202只入队及逐目标查送达；401只暂停通知通道盲重试，不自动停合法抽取。受控凭据认证失败若属于业务源本身，则暂停该源并通知，不能继续该源逐表暴力重连。

工程落点：E02失败/缺口状态与持久队列；E03读取恢复及拆窗；E04行组隔离；E05未知提交及回读；E06继续调度/重试/熔断/告警；E07日报和人工工单；E08/E09验收；E10逐表上线观测。机器版本见`故障隔离与继续执行规则.json`，必须实现，不以在提示词中写了continue代替。
