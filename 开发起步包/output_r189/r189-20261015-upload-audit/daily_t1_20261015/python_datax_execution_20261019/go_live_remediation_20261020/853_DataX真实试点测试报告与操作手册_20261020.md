## 2. ⚠️ 最重要的一条坑：mysqlwriter 的 job 结构

**症状**：mysqlwriter 初始化即 `NullPointerException`，栈顶 `OriginalConfPretreatmentUtil.simplifyConf(:58)`。报错极具误导性（看似驱动/连接池问题——换 mysql 驱动 5.1.47→8.0.23、换 druid 1.0.15→1.2.4 均无效，全走了弯路）。

**根因**：writer 参数用了"顶层平铺"写法（顶层 `jdbcUrl`+`table`）。这版 DataX（2023 开源版）的 **mysqlwriter 必须用 `connection` 数组结构**，否则简化配置时空指针。

**正确写法**：
```json
"writer": {
  "name": "mysqlwriter",
  "parameter": {
    "username": "root",
    "password": "***",
    "connection": [{
      "jdbcUrl": "jdbc:mysql://127.0.0.1:3306/sanjia_fushen?useUnicode=true&characterEncoding=utf8&useSSL=false&rewriteBatchedStatements=true",
      "table": ["目标表"]
    }],
    "column": ["COL1", "COL2"],
    "writeMode": "insert"
  }
}
```
**错误写法（会 NPE）**：顶层平铺 `"jdbcUrl": "...", "table": [...]`。

**第二个坑（shell 反引号）**：经 `exec_command` 远程执行含反引号的 SQL（`` `COL` `` MEDIUMTEXT）时，反引号会被远端 shell 当命令替换吃掉导致建表 SQL 残缺。**解决：SQL 一律 base64 管道传递**（`echo <b64> | base64 -d | mysql ...`）。

**其他确认的事实**：
- mysql-connector-java-**5.1.47（生产引擎自带）连 MySQL 9.6 正常**——无需升级驱动；
- reader 端 `querySql` + `TO_DATE` 半开区间谓词在真实 ODS 上工作正常（4137 行量级与预期相符）；
- CLOB（主诉/现病史等）完整落地（MEDIUMTEXT），无截断报错；观察项：`PRESENT_ILLNESS` 最长 1000 字符，**待与视图定义核对是否源端 SUBSTR**（不判定为抽取截断）；
- exit 0 时指标仍必须解析（读出/写入/脏）——本测试 errorLimit record:0 生效，脏>0 会直接判失败，与 R03 代码判定语义一致。
