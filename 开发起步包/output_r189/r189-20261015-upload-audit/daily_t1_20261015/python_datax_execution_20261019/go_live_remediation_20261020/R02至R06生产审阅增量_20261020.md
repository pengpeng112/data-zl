## 2. 生产装配差异（相对原运行手册）

`app/services/reporting_pipeline/runtime.py` 提供两条显式分开的装配线：

| 维度 | `build_simulation_cycle`（模拟） | `build_production_cycle`（生产） |
|---|---|---|
| 状态仓储 | 内存 | `SqlAlchemyControlRepository`（PG asset schema） |
| 目标身份 | 允许 DBOPER 回退（报告 identity_degraded） | `require_verified_target=True`：TaskSpec 未验证目标即不派发 |
| 版本账 | 内存 | `PgVersionRegistry`（asset_reporting_version_evidence） |
| 批准核验 | 静态集合（显式 simulation 信任级） | `PlatformApprovalVerifier`（asset_action_executors + 批准登记双查询） |
| 围栏 | `enforce_fence=False` 必须显式声明 | 默认强制：缺 lease_validator / token 的装载即拒 |
| 暂存 | 内存 | `DurableFileStageStore`（受控目录，分块+原子清单） |
| 告警 | FakeTransport | `UrllibTransport`（显式 base_url；未提供则 outbox 留存不发送） |
| 输出标记 | `simulation=true` | `simulation=false` |

CLI 同一入口双模式：`daily-report`/`resume` 的 `--state-db` 指向控制面 PG 即读真实持久状态；缺省为模拟并显式标记。`simulate` 仅模拟；`capture/apply` 等六个真实动作子命令保持 NOT_IMPLEMENTED 直到 R03/R04 绑定与逐例批准完成。

## 3. 值守新增观测项（并入原观测计划）

1. **outbox 心跳**：`asset_reporting_alert_outbox` 最老 `next_attempt_at` 与 `PAUSED_AUTH` 计数——401 停盲重试后需人工核凭据；relay 不可达时抽取不阻塞、outbox 积压可见。
2. **连续完成游标**：日报 `continuous_completion` 段——`capture_h` 与 `continuous_through` 的差即待补缺口；不得用捕获水位口径向上汇报"已连续完成"。
3. **覆盖年龄**：日报 `rescan_coverage_age`——`NO_HISTORY_VISIT/DEGRADED_*` 时按声明的保障等级解释，不宣称全历史 30 天可见。
4. **隔离组账**：`asset_reporting_quarantine_groups` OPEN 行数与 `rows_quarantined`——坏组独立工单化，独立合法组继续。
5. **版本冲突**：装载结果中 CONFLICT 计数（无可靠版本顺序的同键不同内容）——人工核口径，不自动覆盖。
