### R03：补真实读取和DataX运行，先只写暂存

- Python RowSource绑定仓库受控连接器，禁止新建本机业务直连。针对Oracle11g thick、SQL Server、PostgreSQL/MySQL按当前登记源复用通道；分页必须唯一稳定键，读写不共用源端写凭据。
- 超时必须落实在实际驱动/连接/进程上；页间取消不足以中止正在阻塞的fetch。连接断开后丢弃不完整attempt并恢复，不伪造完整结束；CLOB在连接关闭前完整读取或流式转存，再做Unicode/字节校验。
- DataX用参数数组运行，固定插件/模板/对象白名单，核实读写插件及实际错误指标；任务文件仅短时存受控目录、最小权限、完成清理。凭据从长期受控密钥库解析，不复用补抽`/tmp/e2_env`。命令行、stdout及错误不得回显密钥或患者/SQL正文。
- DataX writer只指向批准的stage，不直接旁路写正式业务表；无stage权限的路线只采集/模拟，禁止自动改目标。DataX-only路线禁止失败后擅自切换Python。
- 递归拆窗沿用现算法；超行数/字节/超时有界拆分，到最小粒度用已核keyset或PARKED，不能截断当成功。父窗只在全部子窗完整后闭合；源级重试、熔断预算共享，监听器风暴只放一个半开探针。

### R04：装载必须接真实安全边界

- ApplyPort绑定平台`asset_action_executors`已批准执行器，不用临时直连DML脚本。配置中的approval_ref是引用，不是凭据；由受信服务复核对象、实例、Owner/租户、操作、范围、期限及调用身份，不能由调用方传一组字符串就自认已批准。
- 生产apply强制当前lease_resource及fencing_token，在实际目标提交处落实单写者/围栏；只在PG提前查一次token仍有过期竞态，需要执行器与目标侧配合原子验证。若现有执行器不能满足，先提交明确接口/目标辅助结构方案，暂停该写动作，其他开发继续。
- 修版本比较：当前`_version_after`先转float，大整数可能丢精度，非数值回退字典序也不适合未声明的版本类型。按已核类型使用整数/Decimal或规范时间及并列规则；无可靠顺序的同键不同内容进入CONFLICT，不用采集时间冒充版本。版本历史耐久化并包含目标/租户/表。
- 目标DML与operation_id/batch_id/manifest_hash/范围/结果摘要的提交凭据在**同一目标事务**持久化；跨PG+Oracle的两段状态允许最终一致，不能把PG状态提交当Oracle提交证明。目标辅助表及权限先准备DDL/回退/范围供逐例批准。
- 提交后断线记COMMIT_UNKNOWN，冻结该表写者；恢复先查目标同事务凭据并核manifest及键/内容。凭据缺失但仍无法确认事务结束时继续冻结，禁止自动重放。确定提交、确定回滚和仍未知三个分支均留证。
- 月替换先完整捕获并验证全发布范围，再同事务删除该范围和插入，不先删提交。多源及父子集合必须齐备；有隔离/失败/缺段时不能拿不完整stage删除整月，能否缩小为独立完整组须另有明确作用域与批准。
- 正式表不加DATETIME也可按源窗捕获；撤销/时间跨月移动/目标无时间列时，用耐久键归属和已批准发布范围执行，禁止引用目标不存在的时间字段。不能因此默认获得目标加列许可。

- 修DAG：只在当前可运行节点集合中按模式选择优先级，不能拓扑排完再整体按T1排序。父表失败/待补时相关子组PENDING_PARENT，其他独立表继续。同表不同模式按批次/窗口身份排队，不能被`by_table`字典覆盖丢任务。
- 租约token作为执行上下文传到采集/装载/续期，目标身份从已验证TaskSpec取，不硬编码一个DBOPER资源用于所有实例。物理源并发及熔断预算跨工作者共享；捕获可并行，正式同表写保持单写者。
- 派发并不等于成功。`task.run()`返回失败/隔离/待父状态需被识别；熔断、租约忙、未就绪、依赖未完形成待办和下次调度时间。只要本轮有应完成但未闭合窗口，总体PARTIAL/WAITING_WITH_BACKLOG；仅无任务本来应运行时可NO_WORK，不能所有跳过仍SUCCESS。
- 异常日志只存结构化类别、白名单错误码和受控detail_ref；不直接把`str(exc)`放日报/企微。每个失败窗记录表、源、范围、attempt、原因、影响、下次动作、工单/告警关联和时间。
- 每天按院区已确认业务时区固定昨天`[D-1 00:00,D 00:00)`；任务启动冻结H，跨午夜重试不漂窗。视图保留可历史查询范围，业务窗由外部绑定参数传入，禁止在所有视图固化`sysdate-1`或用动态SYSTEM_TIME作水位。
- **2026连续性**：旧2021—2025基线不证明已经接到上线日前一天。逐表查已验收最后连续窗，冻结H0；先保留H0以后日常捕获，再按预算补齐最后连续窗到H0之间的缺口。历史和当日可并行捕获，正式写串行并防旧覆盖新。未补齐时capture/apply进度和连续完成游标分开，日报不能报全历史完成。
- 迟到策略沿用“日常+有限回看+历史业务月轮巡”，至少覆盖EMR_DOC_ORDER_CHECK、EMR_IN_FEE_INFO_CHILD；来源同步时间与业务时间分别记。所谓月度重扫必须明确管理历史起止月和**每个月被重访的最长间隔**，不能只重扫当前月，也不能60个月每月只扫1个月却宣称历史变化30天内可见。预算不足就降低声明的保障等级并登记风险；无修改日志/CDC就无法保证任意旧记录更改次日发现。

### R06：告警要能送到人，日报要能说明欠在哪

- 真实HTTP transport接现有企微v2契约；使用受控source_id/secret_ref，消息原字节不可变、修改内容用新revision；202仅ACK_QUEUED，继续按event_id查询逐目标状态，达到约定必需目标sent才记DELIVERED。
- outbox耐久领取、超时重领、幂等发送、逐目标轮询、投递失败及恢复事件均可重启续跑。401立即停该凭据盲重试并告警/挂起，429按Retry-After且至少60秒；同物理源断连聚合，不每表每次刷屏。
- 消息写业务表名、窗、错误类别、受影响量/未知、重试状态、建议动作、处理时限及detail_ref。不要包含姓名、病历号、SQL、密钥或原始异常；detail_ref指向受权限保护工单，不是公开患者明细。
- 抽取任务失败不等告警HTTP返回才继续；告警不可达时outbox留存、运行日报可见，既有运维监控观察worker/outbox心跳和最老积压。不能企微自己坏了就完全失声，也不擅自新增短信/收件人。
- 日报每表列昨天捕获/合格/隔离/待父/装载/回读、待补最早窗及数量、最后连续完成日、历史重扫最老月份和覆盖年龄、任务/源延迟、告警实际投递、建议动作。无可靠源快照/可见性基准时标对账待稳定，不把源查询时点变化误判成漏抽。
- deadline缺失单列DEADLINE_UNCONFIGURED/SLA_UNKNOWN；可配置明确标为院内目标的截止，不能冒称省端SLA。上级采集、校验成功/失败及回执缺失分开，前置机装载成功不直接变成省端完成。

### R07：真实试点分段验收

本地R01—R06先连续完成；真实验证按对象和动作取得等价批准后推进，缺项只停对应段。

1. 从实际READY候选中选3—5项启动，不预设某表必然就绪。优先包含Oracle普通表、CLOB表及一组父子；护理DataX-only、血透87和LIS双源是全量上线前必须补测的特殊路线，可安排在后续试点小组。
2. 先受控限量只读验证源身份、当前定义、时间边界、投影、键、数据类型及性能，不使用全表COUNT代替按窗完整捕获。预算写明源/对象/SQL/参数/时段/通道及实际取消能力。
3. 已批准stage落地后验证真DataX/驱动和完整清单，再做quality/readback模拟；未批准正式apply就停在stage，不能跳到正式表“先试一条”。
4. 获得准确目标和窗的执行器批准后真实装载、按键/内容回读；同一已提交批次重复请求无新增重复/覆盖历史证据，提交后断线测试优先用隔离环境，禁止在生产制造监听器风暴。
5. 告警管理员先登记本工程source、订阅、白名单/网络和测试接收范围；只向本次明确指定的测试订阅发脱敏测试，不能沿用指南示例收件人。验POST入队、逐目标送达、恢复消息及工单detail_ref。401锁定等破坏性用例用模拟服务。
6. 每条试点记录当前配置/定义/插件版本、批准范围、固定窗、数量守恒、键/内容差异、耗时、源可见性、隔离、真实回执和恢复动作。至少两个相邻日窗通过，新增负例/特殊通道通过后才扩围；现场错误反写工单，不删证据再跑成绿。

### R08：逐表交接、分组上线、观测及收口

- 切换前获取**新鲜**8.53任务/调度/写者快照；对每表列旧入口、源/目标、作用窗、事务、最后成功点、未决提交、日志及交接责任人。未知提交不切换、不并发新写者。确认交接窗口后按批准停旧入口/撤旧排程并保留可回退配置；本计划本身不执行这些动作。
- 每组约5—10项，实际依源负载和父子关系调整，不硬凑10项。父子放在同一组或父先通过，重扫让位日常。组内失败只冻结受影响表/依赖，其他已就绪项继续；未就绪项持续列清原因，不能靠从分母删除来宣称77项通过。
- 新入口先关闭写开关/只计划演练，再按批准启用对应表；配置版本、镜像/脚本指纹、调度入口、密钥引用、预算及回退命令留档。目标DDL/生产迁移/cron/发布逐项具备批准，不能以本次“给计划”视为授权。
- 观测**7个业务日**，业务日口径由院方/上级确认；每天出昨日任务和待补清单，值守签收。硬失败仍未恢复、持续积压、错序/旧覆盖、告警未送达或数量内容不守恒时不结束观察；问题修复后重验受影响项目并按风险延长，不掩盖失败日。
- 月漂移在7日内可做受控演练，但不能据7天结果宣称已验证完整月周期；完整历史覆盖周期验收另记待观测并保留排程/负责人，不无限推迟院内日常功能的阶段签收。
- 回退先停止新表派发、核在途事务及COMMIT_UNKNOWN、对账后再交还旧入口，不让两个写者同时恢复。代码回滚不等于回滚已提交数据；正式数据修复须另有明确范围、备份和批准。不盲downgrade删运行审计。
- 收口签分层结论：本地工程验收、真实路线验收、逐表院内T+1运行、7日运维交接、省端回执分别签。省端回执未知不阻止院内开发和已批准落地，但REPORT_READY保持UNKNOWN，不能写成“省里已全部完成”。

## 5. 报错后的统一处理

原则：**跳过当前失败窗口，留缺口、继续独立任务并告警；不把跳过当完成。**

| 情况 | 当前处理 | 继续范围 | 恢复条件 |
|---|---|---|---|
| 源暂时断连/超时 | 按表预算有界重试/拆窗；同源熔断并聚合告警 | 其他物理源继续；同源等待半开单探针 | 通道恢复，从未完整窗口续采 |
| SQL/视图/列错 | 当前表/受影响路线挂工单，保留原失败窗 | 其他表继续；依赖子组待父 | 用户修视图，当前哈希与小窗复核通过 |
| 单行长度/精度等质量错 | 能可靠定位且组独立时隔离该行/组 | 同批其他独立合格组及其他表继续 | 人工修正后只重试隔离范围；整月替换不得携不完整集发布 |
| 父未到、同键内容冲突 | PENDING_PARENT/CONFLICT，不造父、不盲覆盖 | 独立组/表继续 | 真实父到齐或冲突口径/版本依据核实 |
| 目标事务失败且确定回滚 | 当前事务整段回滚，记录待补 | 其他独立表继续 | 原幂等operation在安全条件下重试 |
| 提交结果不明 | COMMIT_UNKNOWN，冻结同表全部写者并告警 | 其他独立表继续；不能重放该表 | 核目标同事务凭据与内容，确定提交/回滚 |
| 告警接口异常 | outbox积压，退避/认证挂起，日报可见 | 抽取继续 | 通道恢复后幂等补发、查询实际送达 |
| 共享控制库/租约不可用、目标身份错误、批准失效 | 停依赖该安全边界的派发/正式写，保留现场 | 已获授权且不依赖失效边界的离线/只读工作继续 | 边界恢复并核在途状态；不能为继续而绕过门禁 |

失败清单必须含“表/窗/状态/错误码/未完成量或未知/下次动作/重试时间/告警送达/工单入口”。失败窗口不推进连续完成游标；后续成功窗可先落地，但中间缺口始终可查。
