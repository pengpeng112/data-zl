## 1. 铁律（STOP 白名单沿用 163 §1 前四类）

1. **值域 confirm/deprecate/resolve-conflict 与 finding 终态流转均为人工动作**：界面只提供入口+权限+审计；开发期禁止代点任何真实数据行（验收用 throwaway 测试行或 mock）。
2. 复用优先与文件分工：值域 API 全用 149 既有端点；探查列表/详情/runs 用 165 E4 契约；本计划后端增量**仅 3 端点+种子**（§3），且 **transition 端点与状态机函数写在 165 建立的 probe 路由/服务文件内（只增不改语义）**——B8 裁决。
3. **导出硬约束（B1 裁决，禁止照抄 governance.py 现实现）**：①端点必须挂 `require_permission`（GET 导出不在写路由静态扫描内，须显式 403 测试）；②导出动作写审计行（操作人/筛选/行数）；③文件名含导出时间与筛选标签（如 `probe-findings-20260901-153000-status-open.csv`）；④防公式注入（`= + - @` 前缀加 `'` 转义）；⑤列白名单逐列常量（§3）；⑥findings 导出**POST+body 筛选**（防 SQL 文本进代理日志）。
4. **无 mock 开关（B2 裁决）**：产品默认直连真实 API；165 未就绪/空数据=空态+引导文案（不显示假 0）；开发期组件测试用 Vitest `vi.mock` API 模块。
5. 权限码一律**点号**（B3）：`value_domain.confirm`、`probe.finding.read/manage`（种子/v-perms/后端依赖三处一致）。
6. 不改 126/144/146/149/153 语义（permissions.py 清单追加不属于改语义）；除 165 已建两表外零新迁移（manage 种子走 153 B5 幂等模式）；前端新页面一次建完，老页面只触碰 table-detail 一处（与 163 R5 文件冲突由执行窗互斥消除）；新接口一律进 `src/api/`（新增 `probe.ts`、扩展 `asset.ts` 导出函数），禁视图层直打 http.request；pnpm+typecheck 双过。

| 从\到 | open | confirmed | false_positive | resolved |
|---|---|---|---|---|
| **open** | — | ✓ | ✓ | ✓ |
| **confirmed** | ✓(重开) | — | ✓ | ✓ |
| **false_positive** | ✓(重开) | ✓ | — | ✓ |
