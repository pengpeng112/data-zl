## 2. 任务分解

### P0 高危必修（功能性缺陷，生产在跑）

- `frontend/src/views/asset/relation-review/index.vue`：
  - 三个筛选 el-select（:385/:390/:397 附近）`@change="loadRelations"` → `@change="doSearch"`；
  - 关键词 el-input `@keyup.enter="loadRelations"` `@clear="loadRelations"` → `doSearch`；
  - el-pagination `@size-change="loadRelations"` → `() => loadRelations(1)`（current-change 保留 loadRelations：翻页传页码语义正确）。
- 全试点页同模式扫描：grep 六个 usePagedList 页（dict/general、tables、relation-review、dict/sync-diffs、identity/sync-diffs、relation-rates）所有 `@change/@clear/@keyup.enter/@size-change` 直接绑定 `loadData/loadStdItems/loadSysItems/loadMappings/loadRates` 之处，逐一改为 `doSearch` 或箭头包装——**判定规则：事件首参是"值/事件对象"的必须包装；是"页码"的保留**。

**P0-2 防回归测试（两个测试盲区）**

- 批验收：`pytest tests/test_db_connectors_readonly.py -q` + `pnpm run test`。

### P1 中低修复（后端 4 项）

**P1-1 pymssql 占位符口径 fail-closed**（P2，kimi 独抓·背景交叉）
- `backend/app/services/query_parameter_validator.py`：sqlserver 方言提取到 `@name` 占位符时，若 SQL 同时含 `%(name)s` 形态则报"占位符风格冲突"；或更简——校验器对 sqlserver 仅接受 `@name` 并在执行侧 `db_connectors.py` pymssql 分支前做风格断言（含 `%(` 即抛 ValueError 明示"pymssql 需 %(name)s，请修订 SQL"）。**取简版：执行侧断言 + 校验器 warning**，不阻塞现有无参 sqlserver 资产。

**P1-2 import_results 归因**（P3）：`data_products.py:189` `user = "system"` → `user = get_request_operator(request, default="system")`（request 参数已在签名）。

**P1-3 A9 助手真实 PG 形态断言**（P6）：`tests/test_153_g1_g3.py` 补一条——构造带 `pgcode="23505"` 与 psycopg `UniqueViolation` 类名的 mocked IntegrityError，断言 `_is_unique_violation` 两种识别路径均 True（现有假会话测试保留）。

**P1-4 A2 NULL/"" 口径注释**（P7）：`quality.py` `_run_rule_col_null_comment` SQL 注释说明"PG GROUP BY 下 NULL 与 '' 分组（与旧内存归并口径微差）；如需归并改 COALESCE"，行为不改（kimi 裁决可接受）。

### P2 前端顺手项（3 项）
