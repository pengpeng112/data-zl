## 接手顺序

1. 根目录 `AGENTS.md`：安全红线、代码约束、文档维护规则。
2. 本文件：定位当前文档、资产包和归档历史。
3. `55_系统未完成事项统一执行计划.md`：唯一未完成事项执行入口。
4. 按任务读取下表指定的权威口径、证据或模块计划。

## 状态定义

| 状态 | 含义 | 使用规则 |
|---|---|---|
| 已完成 | 成果、代码或验证已达到当前验收口径 | 可直接引用；除非输入数据或用户口径变化，不重复执行 |
| 部分完成 | 已有可用成果，但仍缺人工、环境或后续功能验收 | 先复用已完成部分，只处理明确缺口 |
| 当前 | 当前规则、口径或模块计划 | 可继续维护，优先引用 |
| 进行中 | 尚有明确开发/验证任务 | 先读 55，再登记负责人 |
| 证据 | 一次性探查、验证或生成记录 | 只引用结论，不重复执行 |
| 参考 | 长期背景、原始资料或选型 | 不作为当前状态判断依据 |
| 归档 | 已被替代的计划或交接 | 仅历史追溯 |

### 后续 AI 最短接手路径

1. **跨会话/换 AI 交接**：先读 `66_多AI交接_未完成与待实现清单.md`，再读本 README 与 `55`。
2. 只需了解现状：读本 README 的“当前完成度总览”，再读 `55` 顶部状态和执行日志。
3. 做数据资产/关系任务：读 `40` 的治理口径，再读对应证据报告和机器可读资产包；不要从旧手工表结构重新推断。
4. 做代码任务：从 `55` 的真实未完成项进入；同时检查 `git status`，保留现有协作者改动。
5. 做登录、接入或权限：读 `59` 和 `43`；HRP 只读补采已允许，人员 apply 仍需审批；权限增强按 55 E9。

## 目录维护协议

1. 会话开始：用 Glob 比对 `开发起步包/*` 与本文件；发现孤儿文件先登记或归档，再处理任务。
2. 新增文档：先确定当前最大编号加一；首行写 `> 类别` 和状态；立即登记本文件；再写正文。
3. 状态变更：在本文件对应行更新状态、用途、日期和依据；同步修改文档首行状态横幅。
4. 文档替代：先将有效结论合并到当前文档，再连同配套 `_结果.json` 移入 `_archive/`；记录原因，不删除。
5. 不在文档中记录密码、Token 或连接串。仅记录环境变量名、密钥引用和脱敏网络信息。
