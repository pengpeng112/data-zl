## 1. 目标、交付与执行原则

让一次免费 AI 执行尽可能完成一次有证据的系统体检：发现普通用户实际操作的问题，检查前后端和架构的边界，复核历史任务的完成声明，并交付可复现的问题清单。**本轮只测不修**：可新建测试脚本、合成数据和报告，不改业务实现、不顺手发布、不推进其他开发计划。

完成测试任务不等于系统全部通过。没有浏览器、没有隔离库、没有某角色账号时，应交付明确缺口，不能用源码阅读或截图脚本替代真实操作结论。不得要求必须发现固定数量的缺陷。

执行 AI 获得本计划后按 S0—S8 连续推进；普通步骤无需逐项确认。必需信息缺失只阻塞依赖步骤，继续其余工作。一次会话可能有时长限制，优先完成 P0、全页面基本操作与最终交卷，再扩展 P1/P2；所有未完成用例保留，不以缩小分母伪装全覆盖。

交付目录为 `开发起步包/output_r194/<YYYYMMDD-HHMMSS>/`，复用计划每日执行时新建 run 子目录，不覆盖旧证据。创建后在 README 登记 `output_r194/`，仅把需要后续处理的结论回写 55。

前端在 `frontend/` 执行：

```powershell

```

`typecheck` 当前同时包含 tsc 和 vue-tsc，两者均须通过。缺依赖时先确认锁文件和 pnpm 版本，可用 `pnpm install --frozen-lockfile`；失败不得改锁强行过关。禁止运行会 `--fix`/`--write` 的 lint 脚本。不要用 clean:cache 清理共享环境。


可用浏览器工具时直接操作；否则优先复用已安装 Playwright/Selenium 或仓库既有工装，在 scripts/ 新建测试驱动。浏览器缺失可检查已安装浏览器及运行方式，无法启动即标BLOCKED_BROWSER，继续接口/静态，禁止冒充完成真人模拟。不得为省事拦截所有业务API后宣称真实集成通过。

每条验证标明一种或多种方法：`BROWSER_INTEGRATION`（本地页面+真实隔离平台API）、`BROWSER_MOCK`（接口故障/特殊态注入）、`API_INTEGRATION`、`UNIT`、`STATIC_REVIEW`、`HISTORICAL_EVIDENCE`。外部源模拟并不影响平台内部集成分类，但必须注明 `source_mode=mock`，不得宣称源端验收通过。

## 10. 结果、缺陷和覆盖率规范

### 10.1 用例状态

- PASS：预期断言全部满足，且证据可定位。
- FAIL：执行后实际违反预期，记录重现与影响。
- BLOCKED：缺角色、浏览器、隔离库、授权或依赖，写恢复条件。
- NOT_RUN：预算/时长未执行，不与BLOCKED混淆。
- NOT_APPLICABLE：经核实不存在该控件/本版本不适用，提供理由。
- PLANNED_NOT_IMPLEMENTED：193等明确未来范围，不计当前产品缺陷。

一个用例有部分断言未跑则不能总PASS，应拆子ID或保持NOT_RUN/BLOCKED并记已做部分。历史“通过”不能替代本次PASS。

```json
{
  "case_id": "J02",
  "priority": "P0",
  "status": "NOT_RUN",
  "method": "BROWSER_INTEGRATION",
  "environment": "local-isolated",
  "source_mode": "mock",
  "role": "synthetic_admin",
  "route": "/asset/tables",
  "steps": [],
  "expected": "同名表按source隔离，返回保留筛选",
  "actual": null,
  "evidence": [],
  "defect_ids": [],
  "blocked_reason": null,
  "started_at": null,
  "duration_ms": null
}
```

### 10.2 每条问题必须写清

`缺陷ID / 严重度 / 确定性 / 模块 / 环境版本 / 角色与数据前提 / 1—N操作步骤 / 预期 / 实际 / 复现频率 / 截图与请求摘要 / 文件:行定位（已确定才写） / 影响 / 最小修复建议 / 回归case_id`。

P0：越权/敏感泄漏/绕过写门禁/核心数据错误等；P1：主流程不可完成、状态或统计明显错误；P2：局部功能和可恢复体验；P3：轻微视觉与建议。区分根因与推测，一个根因影响多页可合并但列全影响页。没有充分证据的放“不确定项”，写两种可能原因及下一步核验方法。

### 10.3 分开计算覆盖率

1. 页面访问覆盖 = 已真实进入并断言的页面 / 当前有权限可测试页面；同时列全路由数、被权限/环境阻塞数。
2. 人工交互覆盖 = 已执行G子用例 / 已实例化适用G子用例。
3. 关键旅程覆盖 = 已执行J用例 / 12；PASS和FAIL均算执行，PASS率另算。
4. API风险分类覆盖 = 已分类方法路径 / 实际方法路径总数；API执行覆盖另列，不能用静态分类凑执行率。
5. 历史复核覆盖 = 已证据核对验收条目 / 抽取到的历史验收条目，列明待复验数量。
6. 各类状态总数必须等于完整用例总数；NOT_RUN/BLOCKED不得从报告消失。不对“系统完成百分比”拍脑袋汇总。
