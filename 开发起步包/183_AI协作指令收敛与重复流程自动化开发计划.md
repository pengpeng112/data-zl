# AI 协作指令收敛与重复流程自动化开发计划

## 1. 目标

把跨会话反复出现的接手、目录自检、测试环境预检和多 AI 证据整理变成可复用能力，减少重复提示词和因局部依赖缺失导致的整任务中断。所有自动化默认只读或 dry-run；需要外部写入的动作继续使用现有批准门禁。

## 2. 已完成的指令层修订

1. `AGENTS.md` 已区分业务源库、平台库、隔离测试库和本地文件修改，并明确局部阻塞只停止依赖步骤。
2. 查询治理已拆分为编写/审阅、保存/修订、执行、反馈四条路径；平台自动 active 与草稿人工执行批准已分开表述。
3. ODS/HIS/移动护理/Docare 技能已收窄停止范围；结构技能已收窄触发系统；历史关系核验请求不再二次确认。
4. 全局 `multi-verify`/`multi-review` 已改为明确的多 AI 请求才触发；人工终审和修复前复核停点保留。
5. skill-creator 的访谈与测试确认改为按信息缺口和副作用决定，不再把每个安全本地测试都变成确认点。

## 3. 开发批次

### S1：跨会话接手 Skill

- 新建 `.agents/skills/project-task-resume/`，入口只保留任务恢复决策和权限边界。
- 输入：用户当前要求、`git status`、README 当前入口、55 最新状态、相关执行报告。
- 输出：当前目标、已完成证据、未完成步骤、文件归属、可立即继续项、需要批准项和阻塞恢复条件。
- 不复制整份 README/55，不把历史一次性授权当作当前授权，不创建平行状态总表。
- 验收：使用 147 中断续跑、177 隔离库阻塞、180 分段授权三个真实案例；必须复用完成项、继续独立工作并保留明确批准点。

### S2：目录与编号只读检查器

- 新建 `tools/check_doc_index.py`，默认只报告，不修改文件。
- 识别编号正文、同号 `_结果.json`、同号输出目录、README 组合登记和归档条目；检查孤儿、幽灵、重复编号、缺类别、断链引用。
- `--fix` 只允许补本次明确指定文件的 README 登记；不得自动归档、移动或删除。
- 验收：用当前 `开发起步包/` 运行，报告可重复；已组合登记的结果文件不得被误报为孤儿。

### S3：测试环境预检器

- 新建 `tools/check_test_environment.py`，输出 `pure_logic_ready`、`integration_ready`、`migration_ready` 三类状态和可运行命令。
- 检查 `APP_TEST_DB_URL` 是否存在、数据库名是否含 test、是否命中 denylist、`APP_DB_URL` 是否一致、SSH 本地端口是否被其他进程占用；不打印凭据。
- 仅做连接/身份与清理能力预检，不执行 pytest、TRUNCATE、迁移，不杀占用端口的进程。
- 验收：缺 URL、生产 URL、共享不可清理库、端口占用和合法隔离库五类用例；复用 `backend/tests/db_guard/` 的既有规则，避免双份判断漂移。

### S4：多 AI 证据流程脚本化

- 为 `multi-review`/`multi-verify` 增加薄包装脚本：CLI 存在性预检、round 编号、输出 UTF-8 归一、SHA-256、缺席状态和结果清单。
- 不把模型输出自动裁成最终结论；无法证据裁决的冲突、高危项和不可逆决策继续交人工。
- 普通修复和常规回归不得调用该包装器。
- 验收：一个外部模型缺席仍收口；全部外部模型缺席时生成明确的未完成报告；不声称“四方完整”。

### S5：提示词和指令漂移检查

- 新建只读检查：扫描 AGENTS、CLAUDE、项目 Skill、全局 Skill 和 55 当前入口中的批准、停止、只读、全量测试、历史授权等关键词。
- 维护少量语义规则：业务源库只读不得放宽；平台自动 active 与人工执行批准不得混用；历史授权不得成为当前授权；局部阻塞不得宣称全任务完成。
- 输出机器可读 JSON 和简短 Markdown；只报告可能冲突，不自动改自然语言指令。

### S6：同名全局 Skill 收敛

- 盘点 `~/.codex/skills/.system/skill-creator` 与 `~/.codex/skills/skill-creator` 的加载优先级和实际调用方。
- 系统版继续承担普通创建/小修；用户版若仍需要完整基准评测流程，则迁移为独立的 `skill-evaluation` 包并收窄触发条件。
- 迁移前验证 Codex 的发现路径和现有调用，不直接改系统随附 Skill；系统更新可能覆盖的内容形成上游反馈清单。
- 验收：普通 Skill 小修改不强制访谈或 Claude 专用评测；明确要求基准评测时仍能调用完整评测流程。

## 4. 实施顺序与文件隔离

1. S2 和 S3 先行，提供后续 Skill 可调用的确定性工具。
2. S1 复用 S2/S3 输出，避免在 Skill 中重写目录和环境判断。
3. S4 独立修改全局多 AI 技能目录，不与仓库业务代码混改。
4. S5 最后接入回归，用本次发现的 12 类问题作为初始案例；S6 在确认加载优先级后独立迁移，避免两个同名 Skill 继续竞争。

每批只修改所列文件；开始前记录 `git status`，结束后用显式路径核对 diff。现有 dirty 工作区中的身份、前端布局、发布包和 181/182 资产不纳入这些批次。

## 5. 回归门禁

- Skill：运行系统 `skill-creator/scripts/quick_validate.py`；再跑真实行为用例，避免只断言固定措辞。
- Python 脚本：单元测试覆盖配套文件识别、路径/编号、数据库 URL 脱敏和拒绝条件。
- 数据库保护：继续跑 `backend/tests/db_guard/test_test_database_guard.py`；只有明确隔离库可清理时才跑根级 pytest。
- 文档：S2 零误报基线、README/55 引用检查、所有新增文档类别和编号检查。

## 6. 明确保留的批准要求

- 业务源库 DML/DDL、患者敏感明细输出。
- 生产平台迁移、apply、发布、权限、cron、env 和运行配置修改。
- 关系、值域、查询认证、指标和数据产品中现行规则要求人工裁决的终态。
- Git push/tag、force-push 及历史改写；force-push 不纳入本计划。
- multi-verify 明确触发后的问题清单人工复核。

任何未来实现若允许自动归档文件、自动修改生产配置、自动执行平台草稿、自动批准治理终态或自动创建 cron，均属于权限扩展，必须另行提出并获得明确授权。
