### 6.2 S4 每条边的验证设计

执行前先明确业务问题：“一条子记录应该有几个父记录？”不能一律以一对一验收。

| 指标 | 定义与解释 |
|---|---|
| 子记录总量与空键率 | 同一受限业务集合中的记录数；组合键任一列空与全空分别计数 |
| 父键重复 | 按完整候选键分组，记录重复键组数和涉及行数；聚合前后分别测 |
| 匹配覆盖率 | 子表非空键记录中至少匹配一次的记录数 / 子表非空键记录数，用 EXISTS 语义避免一对多放大 |
| 孤儿率 | 非空键且无父匹配的记录数 / 非空键记录数；分母0输出不可评价，不写0%或100% |
| JOIN放大 | 实际JOIN行数与同粒度左侧基数之比，同时记录INNER/LEFT语义和0/1/多匹配分布 |
| 条件效应 | 原始条件与移除/替换某限定的受控对照；记录覆盖变化，不将实验条件改写成业务事实 |
| 视图质量 | 受限集合的目标ID唯一性、必填缺失、字段长度、目标父子覆盖；人工拼ID唯一不能替代业务键正确 |
| 值域映射 | 非空源码数量、未映射/多映射/默认回退数量；标准合法不代表源语义正确 |

通用探针形态：`WITH child_scope AS (受控业务键或时间窗限定的子集合) SELECT 聚合指标 ...`。这只是设计形态，必须按真实字段、索引和方言生成，不提供猜测字段即可运行的万能 SQL。

推荐首轮资源上限：每源串行、每探针30—60秒且不超过连接器上限、每探针聚合返回最多50行、首轮最多200个不同业务键；键集也必须来自有界索引访问。扩大到1000键、更多时间窗或重试之前记录理由、执行计划和授权覆盖。不要用随机排序采样、外层 TOP/ROWNUM 或输出50行代替扫描约束。

索引/访问路径先读已有元数据或只读计划能力；Oracle `EXPLAIN PLAN` 可能写 PLAN_TABLE，不列入本任务允许命令。没有安全计划能力且无法证明有界访问时，标记待 DBA 计划证据，不冒险执行。

### 6.3 S5 执行与判定

- 源库仅单条 SELECT/只读 CTE，通过 8.83 受控连接器或已批准跳板；Windows 不直连源库。业务键用绑定参数或受控源端子查询，日志不落患者字面量。
- 批量业务探查在允许夜窗进行；执行前按目标源、对象/SQL、参数范围、时段、通道核对批准。白天仅平台已有元数据/离线分析可独立继续；白天 live 需相应已有批准或具体呈报。不能预设固定夜窗，需避开已有任务和源端维护窗。
- `HIS.LAB_RESULT` 必须由受限 TEST_NO 集合定位；超过千万行的批量普查对象只采元数据，定向验证另按门禁判断。Oracle11g使用受支持语法及 thick 客户端。
- 覆盖多个非相邻窗口：按实际数据可用性选择历史正常期、切换期和最近完整期；2025-04—06仅为189提出的切换核查候选范围，不能宣称真实切换日为2025-05-01。
- 分别抽查多次住院、多台手术、多份文书、退费撤销、空键、延迟同步等边界，源端只返回聚合摘要；没有边界样本如实说明。
- 0孤儿且0重复的有限样本只支持“本样本未发现问题”；可选父记录允许缺失，一对多允许预期放大。不得设统一99%通过线，按每条边事先记录的业务基数与容忍口径判断；异常未解释不得升高置信度。
- 对既有正式边：证据未变且仍在有效期可复用；数据源/定义/关键条件变化，证据过期或高风险疑点则重新验证。新异常保留冲突，不自动降级或删除正式边。
- 跨实例边仍按40号D类保留待验证层。实际存在DBLINK/同步对象只解决可达性，不证明身份语义、同步时点与覆盖一致。
- 超时/权限/歧义按源或候选局部阻塞，记录恢复条件；禁止换高权限、去掉过滤、关闭审计或不断扩大扫描重试。
- 验收：每条拟入库候选有已执行结果或明确未验证状态；source身份、SQL哈希、时间/参数范围和审计引用齐全，所有指标可解释其分母与抽样局限。

### 7.2 导入器与环境门禁

- 优先使用现有受控服务/API或已审计的批量入口。sjzc是只读入口，不能承担写入；也不能把产品AI工具改接写执行器。
- 若需要新适配器，先在本地实现，默认dry-run、显式目标环境、完整物理身份去重、单事务、并发防重、批次ID、审计和错误回滚；生产入口缺失时形成待开发项，不能临时直连写SQL绕过。
- 不使用134导入器默认SessionLocal/replace逻辑直接执行。禁止max(id)+1在并发生产分配ID，需采用当前模型支持的安全分配策略；禁止把已有approved记录重置draft。
- APP_TEST_DB_URL须核实为允许清理的隔离库；证明宿主/端口/数据库名和隔离标记，日志隐藏凭据。根pytest会TRUNCATE，未确认隔离库不得运行。
- 隔离测试覆盖：首次导入、完全重放、反向边重复、跨实例同名表不合并、带条件不同边不误并、组合键次序、已批准资产不覆盖、失败事务回滚、审计脱敏、无权限拒绝。
- dry-run不写业务表也不偷偷推进状态；以当前平台基线和payload哈希生成diff。重复同一输入应新增0、非预期更新0；证据追加也应幂等。

- 验收：离线/隔离门禁通过；完整导入包与变更摘要形成。平台不可用时本地包可交付，生产预演/回读仍标待执行。

## 8. S7—S8：平台入库、人工治理与AI回读

### S7 待审资产入库

提交批准包必须具体到：目标平台身份、run_id与文件哈希、候选ID清单、各类新增/更新数、将影响的表与状态、既有资产保持项、隔离测试结果、备份与批次撤销方案、操作者与窗口。没有实际diff不能询问“是否允许全部入库”。

### S8 人工治理终态及AI可用验收

- 待审记录由人工选择批准/驳回/补证，不允许AI因指标好看自动approve/confirm/activate。人工判定关系成立与生产发布许可分别按平台流程处理。
- 配方必须同时包含完整键、条件、状态码证据、业务粒度、支持系统/版本/窗口、负例和禁止误用说明。
- 正式发布后，通过普通AI读取入口，重新按系统、表和业务问题检索；记录资产ID/版本、引用来源、返回是否截断、是否含禁用/未审核资产。
- 选至少5个已审核案例和3个反例做只读回答验收：住院组合键、检验报告到项目、手术三键、字典映射、文书版本；反例包括跨实例同名表、同日多台手术、未知码。预期AI引用正确资产并在证据不足时拒绝确定关系。
- 这些回读用例不执行自动生成SQL，不再扫描源库；如需执行查询，另走查询治理和对应审批。
- 审核后重新导出机器可读资产，附版本/生成时间/哈希，使用已有导出机制更新适用的离线包；不能手工改CSV冒充平台发布。按现有缓存机制核对更新，无额外批准不重启生产或调整运行配置。
- 验收：已批准资产可从平台AI上下文获得；草稿不混入正式推荐；未审核/未批准资产明确留待办。若API当前不能返回必要适用条件，记录功能缺口，不能宣称“其他AI已可可靠复用”。
