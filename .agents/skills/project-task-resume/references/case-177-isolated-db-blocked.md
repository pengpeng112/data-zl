# 案例回放 177：隔离库与时点阻塞下的独立推进

> 类别：技能参考（只读回放，不是执行计划）
> 源文件：`开发起步包/177_全仓真实未完成项一次性执行计划.md` + 同号 `_执行报告.md`
> 证据目录：`开发起步包/output_r177/`

## 场景

R0→R7 一次性执行中，三类阻塞同时出现：①R1 夜跑熔断验证**未到时点**（计划排
在今夜 02:00）；②R5 CDMS 表现确认**用户未选**；③全量 DB 测试依赖隔离库重灌。
执行 AI 如何不空转、不越权地推进其余工作。

## 输入事实

- 计划本身把 R1/R5 列为"等待域"，明示未到时点/未答=SKIP 语义；
- 报告 §0：六项缺陷五修一跳（C6 白名单冲突 WARN 跳过）；门禁全绿
  （后端 1415P/1S/0F、前端 267/267 + build 三绿）；隔离库已重灌。

## 判定过程

1. **时点未到 → 延后而非伪造**：R1 夜跑验证按计划延后，报告明确"未到时点
   按计划延后"，不用"最新一行"夜跑记录替代次日 02:00 的判定行。
2. **用户未答 → 不越权记 SKIP**：R5 CDMS 需要用户在 C/A 表现中做选择，未答
   时整批 SKIP 并留等待域记录，不替用户猜表现、不空转等待。
3. **WARN 不阻塞**：C6 白名单冲突记 WARN 跳过，理由留痕，其余批次照常。
4. **可独立项全部推进**：R2 六缺陷修复、R3 身份线复核+F-2 实现（本地代码，
   生产未发布）、隔离库重灌与全量门禁——不因 R1/R5 等待而停摆。

## 输出形态

报告 + `_结果.json` + output_r177/（progress/exceptions/workspace_snapshot/
wait_domain.md）。等待域显式成文，批准点原样保留（Git push/发布/值域 confirm
零越权）。

## 回放要点

阻塞分三类处理：**时点型**（未到点→排程+延后声明）、**输入型**（用户未答→
SKIP 留等待域）、**资源型**（隔离库不可用→先跑纯逻辑，DB 用例标受阻）。
任何一类都不允许通过改用生产库、降低校验或猜字段来"解除"阻塞。
