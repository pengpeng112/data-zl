# 回滚方案（R189-T1，E08 静态审阅材料）

## 1. 代码层

- 单 commit 粒度回退（git revert）；reporting_pipeline 为纯新增模块，
  不触碰既有路由/服务行为；
- CLI `reporting_ctl.py` 无副作用命令（list/validate/daily-report/
  ticket-export）；apply 未实现生产路径，无回滚需求。

## 2. 迁移层（e3f4a5b6c7d8）

- `alembic downgrade -1`：按依赖逆序 drop 9 张 asset_reporting_* 表；
- 隔离库已验证 upgrade→downgrade→upgrade 往返（见 E08 证据）；
- 生产回滚前提：确认 asset_reporting_* 表内无需保留的控制状态
  （批次/水位/缺口账/outbox）；回滚即丢控制记录，业务源与正式报送表
  不受影响（本迁移不含业务表）。

## 3. 配置层

- relay 接入默认 enabled=false；断开 = 清 source_id/secret_ref 配置并
  停 sender（outbox 事件保留本地，不丢）；
- DataX 白名单移除目标暂存对象即阻断新 job；
- 任务启用回退：enabled=false（77 项默认即 false）。

## 4. 数据层边界

- 正式报送表的装载回退不在本包范围：按白名单执行器的提交凭据与
  版本保护逐操作处理（RETRACT/CONFLICT 规则），不做批量物理删；
- 月重扫错误发布的修复：重新冻结正确范围 → 完整捕获 → 再次原子替换，
  不直接 DELETE 目标补数。

## 5. 调度层

- 单入口：暂停 = 停调 run_cycle 或置全局 SAFETY_HOLD；
- 恢复前必须清 COMMIT_UNKNOWN 冻结（§3 对账流程），否则保持冻结。
