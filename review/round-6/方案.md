# 方案：AI 定期只读巡查界面 + AI 写 SQL 工作台（167 号计划草案 v0.9）

## 0. 用户原始需求（原话引述，2026-08-29 会话）

> "我需要加一个ai 帮助定期只读巡查的界面 可以与当前的ai质控与分析 界面在一起 一起优化下这个界面，借助当前内网对接的，可以先让他固定巡检数据中心，然后固定找个表有问题的帮着分析即可，因为我需要进行演示。 同时后期会改为更强大内网模型，就是为了证明我当前是在应用的。 还有就是加个界面 能够让ai试试帮我写sql的 界面，根据本机数据库的关系帮我写sql。 请针对上述两个需求生成详细的设计方案计划md文件，我让别的ai执行开发，界面一定好看直观一些。  如果不明白的你可以咨询我"

需求拆解（忠实转述）：①AI 定期**只读**巡查界面，与现有"AI 质控与分析"界面合并并一起优化；借当前内网模型；首期**固定巡检数据中心**、固定找有问题的表做 AI 分析，**用于演示**；后期换更强内网模型（界面须证明"当前在应用"）；②**AI 写 SQL** 界面，依据平台数据库关系生成 SQL；③产出详细设计方案 MD 交其他 AI 开发；④界面要好看直观；⑤允许就不明白处咨询用户。

## 3. 功能设计 A：AI 定期只读巡查（演示模式）

### A1 宿主页重构（ai-quality 页优化为"引擎状态卡 + 三 Tab"）

现状"分析任务/治理简报"保留为两 Tab，新增"**定期巡查**"Tab；页头加引擎状态卡。

### A2 引擎状态卡（常驻，"证明在应用"）

provider 徽标（内网模型 deepseek-r1@10.255.***.10）、configured/enabled 状态点、**最近成功调用时间**、**累计调用次数**（审计聚合）、"连接测试"按钮（既有端点）。角注："当前引擎由服务器配置驱动（APP_HOSPITAL_LLM_*），换更强模型无需发版"。

### A3 定期巡查 Tab（新）

- **巡查目标集卡**：默认"数据中心演示集"（3–5 张问题表：表名/中文名/已知问题标签如"注释缺失 92%"/"键重复"+选取依据）；目标集详情抽屉（字段数/质量指标摘要）；首期只读展示，清单文件化 `backend/app/services/ai_patrol_targets.json`。
- **立即巡查**（权限 `asset.quality.ai.analyze`）：逐表"指标摘要 → build_analysis_prompt（复用）→ hospital_llm"链，复用 ai_quality jobs 模型落库（type=patrol）；进度条逐表推进、单表失败继续；结果=每表一张分析卡（问题指标 + AI 分析富文本 + 跳表详情/质量页）。
- **巡查时间线**：历史 run 卡片流（时间/表数/发现问题数/结论摘要），点开回看。
- **一键演示**（演示剧本固化）：醒目按钮按剧本顺序执行（目标集→巡查→结论高亮）；**离线回放兜底**：LLM 不可达/超时→自动展示最近一次成功结果并标注"离线回放（引擎最后成功 HH:MM）"，演示不翻车。

### A4 后端增量（ai_quality.py 内薄层，零迁移）

| 端点 | 方法/权限 | 说明 |
|---|---|---|
| `/api/v1/ai-quality/patrol/targets` | GET / view | 目标集+每表已知问题摘要 |
| `/api/v1/ai-quality/patrol/runs` | GET / view | 巡查历史（分页） |
| `/api/v1/ai-quality/patrol/run` | POST / analyze | 触发一轮（同步逐表，单表超时 90s；审计；落 jobs type=patrol） |
| status 扩展 | 既有 | 最近成功时间/累计次数（审计聚合） |

新服务 `ai_patrol_service.py`：目标集加载、平台库内指标摘要组装（元数据+QualityFinding 聚合，**零源库连接**）、prompt 复用 `build_analysis_prompt`、结果入库复用既有 results 表。

## 4. 功能设计 B：AI 写 SQL 工作台（新页 `/ai/ai-sql`）

### B1 布局（左需求右结果）

- 左栏：自然语言需求 textarea + **示例问题芯片**（"近 30 天出院患者检查申请量按科室统计"等 4 条可点）；目标系统选择（默认 DATA_CENTER）；**关联表选择器**（系统内表搜索多选，选中强制入上下文）；依据偏好开关（关系配方/值域陷阱）；生成按钮（loading+可取消）。
- 右栏：**生成 SQL**（Monaco，只读+复制+可切编辑）；**依据卡**（注入的表/关系/值域清单标签云——透明可审计，直观体现"根据本机数据库的关系"）；**风险扫描徽标**（只读✓/大表 WHERE✓/方言✓，sql-risk-scan）；操作条：**存为草稿**（propose-sql→AI 草稿审核流）/**去试运行**（携 SQL 跳 sql-workbench try-run 只读）。
- 底部：本人生成历史（点击回填）。

### B2 后端增量（ai.py 内薄层）

`POST /api/v1/ai/ai-sql/generate`：入参 question/system_code/tables[]/prefer；流程=144 context resolve（关系+149 值域+陷阱）→ hospital_llm（system prompt 写死：Oracle 方言、只读、ROWNUM 限量、禁写）→ sql-risk-scan → 返回 `{sql, risk, context_digest}`；权限 `ai.context.read`；审计（question 脱敏 hash）。

### B3 安全

生成 SQL 永不直接执行（试运行仅 workbench 只读通道）；LLM 只收元数据与关系（零患者数据）；超时 90s 前端可取消。

## 5. 界面视觉规范（"好看直观"）

- 统一组件（RePageHeader/ReStatCard/ReToolbar/el-card/el-timeline/el-steps），主题色跟随；A 页=状态卡+时间线叙事，B 页=左右工作台。
- A：巡查时间线节点带问题数红黄绿徽章；AI 结论富文本（146 E3 渲染器+XSS 转义）；一键演示按钮主题渐变强调。
- B：Monaco 亮暗随主题；依据卡三色标签云（表/关系/值域）；芯片横排。
- 空态文案（A"尚无巡查记录…"/B"描述你的取数需求试试"）；响应式 1280+；组件测试每页 ≥4。
