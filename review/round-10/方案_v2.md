## 1.5 两层治理声明（本方案的前提，v2 新增）

- **Git 跟踪面**：代码、编号文档、tools、review、verify 等。移动用 `git mv`，历史可回溯。
- **本机 gitignored 面**：`取数/` 全部（含 exports——.gitignore 含 `/取数/*`）、根 `_tmp_*`、`*.log`、tar.gz、`_offline_build_*`、`.release_*`、`.pytest_cache`。这些**不在 Git 里**，整理=本机 `mv` + 迁移清单（旧路径→新路径→数量→大小→SHA-256）+ 事后核对；不适用"git status 纯 rename"验收，也不承诺 Git 级回滚（回滚=按清单反向 mv）。
- 已跟踪例外：`drivers/*.jar` 已跟踪且离线构建依赖——**保留原地不移动**。

  1. 3 个无编号目录改名 `14、市场监督管理费用明细`、`15、质量控制部药占比`、`16、PCCM统计`（续现最大号 13；**不回填**缺位 2/8；执行时重核最大号，若已被新任务占用则顺延）；

## 6. 风险与权衡（v2）
1. 不建顶级 docs/、不移动数据资产包：引用面论证（同 v1，三方无异议）。
2. output_r 归档收益可能近零（引用面大）：如实报告，不为凑数硬搬。

5. 取数为本机面：跨机器交接不依赖 Git（现状即如此，本计划不改变，仅清单+哈希留证）。
