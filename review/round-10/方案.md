# 数据资产仓库文件规范化治理方案（含执行计划，交下一执行 AI）

## 0. 用户原始需求（逐字引述，2026-09-11 命令参数）

> 当前项目目录内容较多，而且比较乱，包括查询的、开发需求计划、导出的数据、脚本还有程序等信息，而且这个项目会有多个ai进行开发，不同的ai和不同的agent成效，请你结合这个项目的历史聊天记录 对话及文件情况，搜索下github没有什么方式能够更好地规范 各个文件，特别是查询 和md文件等，便于后期的管理和不同agent ai快速获取。  其中调用 codex 请使用 5.6 sol low模式进行分析即可， 完成后给出个详细建议方案和计划，我回让别的ai按照这个计划进行整理处理

需求拆解（供审查对照，不改变原意）：①现状乱（查询/计划/导出数据/脚本/程序混杂）；②多 AI 多 agent 并行开发；③要结合历史会话与文件实况；④调研 GitHub 通行做法；⑤重点是查询（SQL）与 MD 文件的规范；⑥目标是后期可管理、不同 agent 能快速获取所需文件；⑦产出详细方案+计划，由另一 AI 执行整理。

## 3. 目标结构与规范（保留骨架，不做推倒重来）

### 3.1 根目录净化（只保留入口文件与核心目录）
```
根/
  AGENTS.md  CLAUDE.md  GIT_SETUP.md          ← 入口（不动）
  backend/ frontend/ deploy/ tools/ review/ verify/ 取数/ 开发起步包/ .agents/ .ssh/ .zcode/
  _scratch/        ← 新，gitignored：全部 _tmp_* 调试脚本（mv 保留）
  artifacts/       ← 新，gitignored：r178/r181_dist.tar.gz、_offline_build_123/、
                     .release_r169_20260830/、drivers/、qa-report-20260909/、
                     frontend 根的 build*.log/dev.err/dev.log/typecheck.log/vitest.log、
                     frontend/审查_grok.raw/.err
```
- 不新建顶级 `docs/`：编号体系+check_doc_index 工具链已成型，迁移动摇 187 个号的引用面（README/55/技能内大量 `开发起步包/NN_*.md` 路径）。
- 删除项仅限可再生缓存（`.pytest_cache/`）；其余一律 mv 归拢不删除。

### 3.2 取数（SQL）治理
1. 无编号目录补编号（续 exports 现最大号）：`14、市场监督管理费用明细`、`15、质量控制部药占比`、`16、PCCM统计`（名称保留原义；`20260730` 前缀日期改入目录内 README 口径字段）。
2. `取数/` 顶层历史散 SQL/TXT（exports 外）：逐个判定——已入查询资产平台（有 query_code）→ 移对应任务目录并登记；纯一次性探索 → `取数/_archive/sql_legacy/`；判定不了 → 留清单交用户。
3. 每个任务目录强制 `README.md` 头部字段：数据源（实例+schema）、统计口径、query_code 清单、导出文件清单——模板并入 `取数/START_HERE.md`。

### 3.3 开发起步包（MD）治理
1. `output_r*` 生命周期：保留最近 3 轮（r180/r181/r185/r186）+ 被引用者；其余 `git mv` 至 `_archive/output_r*/`（移前全仓 grep 引用，有引用则留原位并在 README 标注）。
2. `数据资产_*` 17 个包**不移动**（技能/README/历史报告引用面大），改由 §3.4 索引统一登记。
3. 归档惯例字段化：`_archive/README.md` 每行增加"被 NN 号替代/合并"可选列（ADR supersede 语义）。

### 3.4 机器可读索引（新工具，agent 快速获取的关键）
`tools/build_repo_manifest.py` → 仓库根 `repo_manifest.json`（gitignored 可选；建议入库）：
- 开发起步包：编号|文件|类别行|状态|标题（解析 `> 类别：`）
- 取数 exports：序号|任务名|README 完整性|query_code 列表
- 数据资产包：目录|行数摘要（读既有 manifest/catalog）
- tools/backend scripts：脚本|一句话用途（读 docstring 首行）
- artifacts/_scratch：清单+归属说明
AGENTS.md 路由节加一行：会话开始可用 manifest 快速定位，不必逐个 glob。

### 3.5 多 AI 协作强化（针对 184 号"并行互踩"）
1. AGENTS.md 增加「目录守护表」：目录→职责→基线要求（复用 dev_env.sh `--domain-baseline` 机制扩到 `_scratch/artifacts/取数`）。
2. backend/、frontend/ 薄子 AGENTS.md（agents.md 标准的层级惯例）：各自验证命令+文件约定，<30 行。
3. AGENTS 协作节补"改动尽早占位提交"规则（184 中断点结论）。

### 3.6 tools 分组
`tools/capture/` 子目录收拢 6 个 `capture_*.py`（更新其内引用与 README 登记行）。

## 6. 风险与权衡
1. **不建 docs/ 顶级**：编号体系 187 号+工具链已固化，迁移收益低于断链成本（此为本方案最大取舍）。
2. **数据资产包不移动**：跨技能/报告引用面大；用索引替代物理归拢。
3. **_scratch 不删除**：历史调试脚本可能被翻查（保留 mv 轨迹）。
4. artifacts 中的 tar.gz（~百 MB 级）建议后续迁移出仓库或转 Git LFS——本计划只归拢不入库（gitignored），不改变现有已跟踪状态（若已被 git 跟踪则保持跟踪并仅移动位置）。
5. 子 AGENTS.md 有双源漂移风险 → 约束为"仅指向根文件+验证命令"，正文不复制规则。
