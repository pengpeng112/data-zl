# 方案：数据资产平台一次性完善与 bug 修复执行计划（草案 v1，供 153 号计划）

> 起草：ZCode (GLM)，2026-08-26。评审目录 review/round-2/。
> 目标读者：multi-review 审查方（kimi/grok/codex）与后续执行 AI。
> 所有发现均带 文件:行号 证据，路径相对仓库根（backend/、frontend/）。

## 0. 背景与目标

平台后端（FastAPI，约 92 个 service、31 个路由模块，全量 pytest 1091 passed/1 skipped）与前端（Vue3+Element Plus，166 tests + 双 typecheck + build 全过）功能已生产运行，但经双路只读扫描（后端/前端各一次系统性代码体检）发现一批**真实存在、有行号证据**的正确性 bug、安全收口缺口、性能隐患与冗余。本方案把它们组织为**一次性执行计划**（编号 153），供单一执行 AI 在一个长会话内完成全部整改；周期可长，但不拆多轮。

设计原则（响应用户要求）：
1. **一次性完成**：P0→P6 七批顺序执行，每批有独立验收命令；全部完成后跑全量门禁。
2. **代码不冗余**：修 bug 的同时做"收敛型重构"（重复样板上移公共依赖、死代码删除），禁止复制粘贴式修补。
3. **零迁移**：本计划不新增任何 alembic 迁移、不改表结构；纯代码 + 测试。
4. **零外部动作**：不部署、不连业务库、不 Git push；生产发布仍由主 AI/用户另行执行。

## 1. 硬边界（执行 AI 不得越界）

- 不修改/删除既有兼容路径与旧表：`/relations/{id}/review`、`/dict-medical/*`、`/asset/queries` 前端路由、`asset_api_keys`/`asset_table_owners`/`asset_business_terms`/`asset_metadata_snapshots` 旧 MVP 表（AGENTS.md 约束）。
- 不改 126/144/146/149/151/152 既有语义；权限码新增只加 Depends 不删既有授权语义（RESOURCE_CATALOG 清死码除外，见 P3-5）。
- 不引入新第三方依赖（后端 requirements.txt 不动；前端 package.json 不动）。
- 不做生产部署/数据库迁移/Git 写操作；所有 DB 相关测试走 `APP_TEST_DB_URL` 隔离库。
- 安全整改保持"失败关闭"：脱敏、审计、权限收紧不得因测试麻烦而加白名单跳过。
