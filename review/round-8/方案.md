# 方案：全栈一次性模拟测试·问题发现计划（170 号草案 v0.9）

## 0. 用户原始需求（原话引述，2026-08-29 会话）

> "我有个免费的ai，但是只能使用一次，我需要通过你帮我分析下，给出一个详细的nd测试计划，让他一次性执行完成，对系统的全部的前端、后端模拟测试进行检查问题，并对检查出来的问题进行记录到md文件,不怕浪费token，但是一定要有测试效果和能够核查出来问题，测试过程中如不确定的完成后单独告诉，请生成计划给出提示词。"

拆解：①一次性免费 AI、单会话执行；②系统**全部前端+后端模拟测试**；③目标=**检查并发现问题**（非重跑既有测试）；④问题记录 MD；⑤token 不设限（深度扫荡）；⑥必须有测试效果、能核查出问题；⑦不确定项完成后单独列出；⑧计划+执行提示词。

## 2. 核心策略（"能查出问题"的四条线）

既有 1300+245 绿测试重复无意义。增量发现：

1. **S 线·全路由契约扫荡**：拉 `/openapi.json` 全路由，程序化生成探针矩阵——GET 全五类探针（未授权 401/403、必填缺失 422、类型错、分页边界 page=0/负/超大、错误路径），写类路由（POST/PUT/PATCH/DELETE）只测**鉴权+校验**探针（不真实执行）；输出"实际行为 vs OpenAPI 声明响应码"偏差清单——历史上此类扫荡最易成批发现真问题（声明 200 实际 500、422 细节漂移）。
2. **C 线·前后端契约比对**：`src/api/*.ts` 14 文件全部请求（路径/方法/参数名/响应字段消费）×OpenAPI 逐一比对，**漂移即问题**（前端调不存在参数、后端改名未同步）——脚本化报告，每条带两侧证据。
3. **A 线·前端源码规则扫荡**（无浏览器约束的深度静态检查）：v-html/未转义插值 XSS、写按钮无 v-perms、硬编码地址/魔法串、死路由/死 API、console 残留、空 catch、`as any` 泛滥点、明文敏感串——脚本+人工定性，每命中带 file:line。
4. **V 线·Vitest 薄弱页补测**：统计测试文件分布→top 薄弱 ≥6 页补源码断言式测试（不改页面代码；断言失败=问题）。

三条硬要求：①每问题带可复现命令或 file:line 证据；②清单分级 P0–P3；③**不确定项独立成节**（含不确定原因+两种可能解释+建议核查方式），完成后单独呈报——对应用户"如不确定的完成后单独告诉"。

## 4. 铁律

1. **只测不修**：问题只记录（file:line/复现/证据），禁止顺手修复——一次性 AI 的价值=完整问题清单。
2. 写类路由不真实执行；业务源库/LLM/外网零调用；测试库仅 data_asset_test 隧道。
3. 既有测试若失败→记录为基线事实，不混淆进新发现问题；工作区未提交改动（多会话）原样保留禁 checkout/stash。
4. 不确定项必须进独立节，不得硬下结论。
5. 零 Git 写；凭据零落盘；新增脚本进 `backend/_r170_work/` 与 `tools/`（不提交）。
6. 覆盖边界如实声明：本计划为模拟+静态测试，不含真实浏览器交互与真实数据规模性能（历史 round-3 教训），清单首节明示。
