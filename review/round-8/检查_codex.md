## 三、测试设计问题

### 19. 未授权探针不足以验证 RBAC

只测“未授权 401/403”无法验证：

- API Key 与用户 JWT 的差异

- 用户只能访问自身数据
- 执行器身份即使有管理员角色仍应被禁止的特殊规则

应建立角色矩阵，例如：

- anonymous
- asset_viewer
- ai_user
- reviewer/manager
- platform_admin
- executor/service identity

每个 operation 应从依赖和权限码生成预期矩阵。

### 20. 分页测试把参数硬编码成 `page`

方案写 `page=0/负/超大`：[方案.md:22](</F:/python/数据资产/review/round-8/方案.md:22>)。

实际接口可能采用：

- `offset/limit`
- `page/page_size`
- `skip/limit`
- cursor
- 无分页

脚本应从 OpenAPI 参数名和约束生成边界值，而不是固定参数。

### 21. 错误路径探针未定义适用范围

“错误路径”可能意味着：

- 不存在的静态 endpoint
- 错误资源 ID
- 错误 UUID
- 路径参数类型错误
- 尾斜杠
- URL 编码
- 超长路径参数

这些预期分别可能是 404、405、307、422。必须拆分类别，不能混为一类。

### 22. 缺少合法成功请求作为所有负向测试的控制组

对每个 operation，最低应有：

1. schema 可生成时的合法请求；
2. 对合法请求逐字段变异；
3. 记录合法请求是否因测试数据、权限或外部依赖不能执行；
4. 无法得到合法控制组时列为不确定项。

当前计划从负向探针直接开始，不能证明实际触达了目标逻辑。

### 23. 缺少响应体契约检查

当前只强调状态码，但前后端问题常来自：

- `data` 包装有无
- `items/total/page/page_size`
- `snake_case/camelCase`
- nullable
- 时间格式和时区
- 枚举漂移
- Blob content-type
- Content-Disposition 文件名
- 错误体结构
- 204 仍返回 body
- 数值被序列化成字符串

这应是后端路由探针和前后端契约比对的核心部分。

### 24. 缺少数据库副作用和审计验证

即使使用隔离测试库，写类成功路径也应验证：

- 写前/写后差异
- 审计记录
- 非目标表零变化
- 失败路径完全回滚
- 二次执行是否幂等
- 状态迁移是否合法
- 权限失败不产生副作用

当前方案完全回避这些检查。

### 25. 缺少性能烟雾门槛

用户说“模拟测试”，不一定要求真实规模压测，但至少应检查：

- N+1 查询
- 单接口 SQL 数量
- 小型测试数据下的超时
- 无分页查询
- 大响应体

### 27. 前端 XSS 规则描述本身不准确

方案将“未转义插值 XSS”列为扫描项：[方案.md:24](</F:/python/数据资产/review/round-8/方案.md:24>)。

Vue 普通 `{{ }}` 插值默认会转义，不能把普通插值命中当成 XSS。真正高风险的是：

- `v-html`
- `innerHTML`
- `dangerouslySetInnerHTML` 类等价路径
- URL 协议注入
- 不可信 CSS/style
- 富文本净化缺失

规则若不纠正，会产生严重假阳性。

### 28. “写按钮无 v-perms”不能机械判定为权限漏洞

某些按钮可能：

- 位于父级权限受控页面
- 只触发本地只读操作
- 后端强制鉴权
- 使用组合式权限函数而非 `v-perms`
- 本就允许所有登录用户使用

应将其作为候选，并联查对应 API 权限依赖和路由菜单权限，不能命中即问题。

### 29. `console`、魔法串、`as any` 不是天然产品缺陷

这些更适合作为可维护性候选。应定义阈值和例外：

- 构建插件可能移除 console
- `as any` 可能用于第三方库边界
- 硬编码地址可能是明确的开发代理
- 魔法串可能是固定协议值

否则问题清单会被低价值噪声淹没。

### 30. 缺少死代码判定方法

“死路由/死 API”不能只靠字符串检索。需要：

- 动态路由与后端菜单数据
- lazy import
- 权限控制
- re-export
- 测试或脚本调用
- 运维 CLI 调用

未定义这些会把动态使用误判为死代码。
