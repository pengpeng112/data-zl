# 审查_zcode（round-8 独立初审，固化后不改）

1. **需求覆盖**：一次性 AI/全栈模拟/问题落 MD/token 不设限/不确定项单列/提示词——§0–§6 逐条映射；"nd"理解为端到端模拟测试（结合上下文），已列覆盖边界声明防误解。
2. **自审疑点①（探针白名单完备性）**：333+ 路由中必然有"非 JSON 契约类"端点（文件下载/export CSV、SSE 流、openapi/docs 自身、健康检查）——探针矩阵须先分类（JSON API/流式/静态），流式与下载类只测 401/403/参数探针，防误报偏差。
3. **自审疑点②（写类探针的 422 构造）**：写类"必填缺失"探针需要知道 schema——从 openapi.json 的 requestBody schema 自动取 required 字段生成空请求即可程序化；但对无 schema 的 dict 端点会退化为只测鉴权——此限制须写进覆盖边界。
4. **自审疑点③（C 线解析可靠性）**：ts 文件用正则解析请求调用易漏（动态路径拼接/封装函数）——应先手工核对 api 层封装模式（request2 封装签名），解析器按实际封装写；漏检风险在报告中量化（解析覆盖率）。
5. **自审疑点④（与并行会话互踩）**：工作区多会话未提交改动+`_r170_work` 新目录——测试执行只加不改，pytest 全量可能与并行会话跑测试互踩测试库（conftest TRUNCATE）——T0 须检查并终止外部 pytest 进程（162 会话先例），或在偏差记录中排除数据竞争假象。
6. **自审疑点⑤（V 线补测的"新测试"归属）**：新增测试文件若断言失败属"发现问题"，但测试文件本身留库会成为后续基线的一部分——须确保新测试确定性（不依赖时序/数据量），否则标注 @skip 留档。
7. **同意**：四线策略/只测不修/独立不确定节/单批 90 分钟 PARTIAL 机制/MD 模板。
