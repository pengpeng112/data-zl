# 方案：关系图谱界面"Neo4j 式直观化"改造计划（round-5）

## 0. 用户原始需求（逐字引述，2026-08-29 会话）

> "请你分析下，我现在需要对关系图谱界面进行优化和完善，请你分析下看看如何进行完善，让更加直观，而且想 neo4j知识图谱 ，给出一个详细的改造计划"

会话背景（同日早些时候，用户在项目 PPT 讨论中明确）：系统架构已把 **Neo4j 图数据库**列为平台目标架构组件（"突出技术先进性"）；图谱需承担**摆脱厂商依赖、把系统间数据关系（HIS↔LIS↔PACS↔EMR 等）自主沉淀与直观呈现**的立意。用户本轮诉求=交互体验向 **Neo4j Browser** 的知识图谱范式看齐：搜索聚焦、渐进展开、力导向布局、属性面板、关系过滤等。

## 1. 目标

1. **直观**：普通业务/数据人员不培训即能"搜表→看关系→追血缘"，向 Neo4j Browser 交互范式对齐；
2. **渐进**：大图不全画——按需展开邻域（11,182 表全量渲染不可行），节点/边规模受控；
3. **可治理**：直观性服务于复核工作流（draft 边在图上一眼可见、一键处置）；
4. **技术先进性落地**：前端深化 G6 5.x；后端补邻域查询 API；Neo4j 作为**可选读模型**进入架构（引入与否单列决策，不默认上）。

## 2. 边界

- 只改 `frontend/src/views/asset/graph/`、`components/`（图谱域）与后端**只读**关系查询 API；不动关系数据模型、不自动写关系（复核仍走既有 batch-review 人工流程）；
- 沿用既有技术栈（Vue3+Element Plus+@antv/g6 5.1 已在 package.json），**不新增前端依赖**；Neo4j 引入属后端可选件，按仓库既有红线（离线依赖审计+用户单独授权）另列，不在本计划默认执行；
- 现有 4 视图模式（overview 下钻 / path 路径 / explore / review）路径与入口不变（164 既有约束"前端不改现有路径"）。

## 3. 现状盘点（2026-08-29 实测）

- 前端：`graph/index.vue`（1070 行，4 模式+筛选器）、`components/AdvancedRelationGraph.vue`（535 行，G6 5.x，SVG 降级、pan/destroy 复用已做）、`RelationGraph.vue`（简化版）、GraphToolbar（统计折叠）、graphNodeMeta（副标题截断，R5 刚补）；path 模式已有双端远程选择/方向/1–8 跳/三态结果。
- 后端：`/api/v1/relations/list|list-counts|path|field-mappings|hit-rates|batch-review`；path 带 direction/max_hops。**缺邻域渐进加载端点**。
- 数据：关系边含 validation_status/confidence(A/B/C)/relation_type/evidence；表 1.1 万张——全图渲染不可行，现有 overview 模式按层级下钻规避。
- 痛点（对"不直观"的归因）：①无全局搜索聚焦节点；②看邻域必须切层级/切模式；③边样式区分度低（类型/置信度/待审状态视觉不分离）；④无属性面板（要点开抽屉跳离上下文）；⑤path 结果只有列表+图，缺少走查感；⑥无边类型图例过滤。

## 4. 改造设计（三层，P0→P2）

### P0 直观性基础（本期必做）

| # | 改造项 | 设计要点 | 对标 Neo4j Browser |
|---|---|---|---|
| P0-1 | 顶栏全局搜索聚焦 | 表名/中文名/拼音前缀搜索（复用现有远程搜索）；选中后：未加载→调邻域 API 拉取并居中；已加载→聚焦+高亮+适配视口 | 顶部搜索框 + :style 高亮 |
| P0-2 | 双击节点渐进展开邻居 | 双击=展开 1 跳邻域（懒加载，默认上限 50 节点/超限提示改用 path 模式）；再次双击已展开节点=折叠其邻域；新节点入场动画 | 双击展开/collapse |
| P0-3 | 力导向布局（explore/review 模式） | G6 force 布局替代当前布局（overview 保留 hierarchy 下钻语义）；布局参数：斥力按度数自适应、连线距离分 relation_type；支持"重新布局"与布局冻结（拖节点后停止仿真，Neo4j 同款手感） | force-directed |
| P0-4 | 语义配色与图例过滤 | 节点按 system/domain 配色（延续现有）；边按 relation_type 选型（实/虚/粗细）+confidence 明度（A 实深/C 浅虚）；**待审 draft 边橙色虚线+呼吸动画**；图例=可点击的显隐开关（边类型×置信度×状态三维） | 图例过滤 |
| P0-5 | 属性侧栏（节点/边） | 点节点：右侧属性面板（表名/中文名/系统/库/行数/字段数/Owner/关联值域摘要/度数）；点边：关系卡（类型/置信度/证据链/来源 SQL 摘要/review 状态+复核按钮入口）。面板可固定/收起，不遮图 | 右侧属性面板 |
| P0-6 | 后端邻域 API | `GET /api/v1/relations/neighborhood?center=<schema.table>&hops=1&limit=50`：递归 CTE 取 k 跳邻域子图（节点+边+每节点度数），硬上限（hops≤3、limit≤200/跳）防爆炸；复用现有权限 value 域 | Browser 的 :NEIGHBORS |

### P1 进阶体验（次期）

- P1-1 path 走查增强：路径边序号徽标+依次点亮动画+步骤条（起→中转→终）；无路径时给"最近可达 N 跳内邻近表"建议；
- P1-2 minimap 小地图+框选缩放+视口撤销/重做（前进后退按钮）；
- P1-3 大图性能：同 schema 节点聚合"超节点"（度数闸门），双击解聚；G6 LOD（缩小时隐藏标签/细节）；目标 2k 节点/8k 边平移缩放不卡；
- P1-4 复核模式强化：review 队列侧栏（按置信度排序）+图上当前复核边高亮联动；侧栏内联 approve/reject（调既有 batch-review，仍人工权限）。

### P2 平台化（远期/可选）

- P2-1 **Neo4j 读模型适配层（可选件）**：图存储接口抽象（GraphStore 接口：neighbors/path/subgraph），默认实现=PG 递归 CTE；可选实现=Neo4j（数据由既有 asset_relations 同步，**只读副本**）。引入 Neo4j 须走单独授权+离线依赖审计（164 §6 红线沿用）；不引入也不影响 P0/P1 全部体验——"像 Neo4j"是交互对标，不绑定其存储；
- P2-2 视图状态 URL 序列化（模式+中心节点+过滤组合进 query，支撑分享与深链，G-07 已有基础）；
- P2-3 血缘互操作增强：lineage 页"在图谱中展开"带 context 跳转（已有，补参数）；图谱节点右键"查血缘"。

### 非目标（明确不做）

全量 1.1 万表一屏渲染；自动改关系数据；替换 G6 换库（cystoscape/force-graph 评估过，G6 5 已满足且零新依赖红线优先）。

## 5. 实施步骤（建议两批）

1. **第一批（P0）**：后端 neighborhood API+契约测试 → 前端属性侧栏/图例过滤（纯 UI，先行）→ 搜索聚焦/双击展开（依赖 API）→ 力导向布局接入 explore/review。验收后合入。
2. **第二批（P1）**：path 动画与步骤条 → minimap/视口历史 → 超节点聚合与 LOD → review 联动。
3. P2 按授权单独立项（Neo4j 适配层先行出具依赖审计与容量评估报告呈用户拍板）。

## 6. 验收标准

- 交互：搜索聚焦≤2 步定位任意已登记表；双击展开 1 跳邻域首屏 <500ms（邻域≤50）；图例三维过滤即时生效；属性侧栏不遮挡主图操作；
- 治理：review 模式 draft 边视觉可辨率 100%（组件测试断言样式类）；侧栏复核调用走既有 API 且权限不变；
- 性能：2k 节点/8k 边场景平移缩放 ≥30fps（开发环境 Chrome）；G6 降级路径（SVG）不回归；
- 质量：`pnpm run typecheck`（双过）+ `vitest`（新增≥8 组件/工具测试：搜索聚焦、双击展开上限、图例过滤矩阵、属性面板字段、邻域 API 契约、超节点聚合、path 步骤条、URL 序列化）+ `pnpm run build` 预算 PASS；后端 `pytest -k relations -q` 全绿+全量 0 failed；
- 兼容：4 视图模式入口与路由不变；`/relations/{id}/review` 等既有路径不动。

## 7. 风险与对策

| 风险 | 等级 | 对策 |
|---|---|---|
| G6 5.x force 布局 API 与现封装冲突 | 中 | AdvancedRelationGraph 已有布局引擎状态行与 G6→SVG 降级链，改造在 layout 层插槽化；先做 spike 分支验证再合入 |
| 递归 CTE 深跳（3 跳）在大关系集上慢 | 中 | hops≤3+limit 硬上限+度数截断；慢查询落 metrics 观测；必要时预计算邻接物化视图（只读） |
| 双击展开与既有"overview 下钻"语义打架 | 中 | 语义划分写进 UI 文案：overview=目录式下钻（层级），explore/review=图谱式展开（邻域）；help 提示 |
| 大图性能不达标 | 中 | P1-3 超节点+LOD 兜底；性能验收不达标则收缩默认 limit |
| Neo4j 引入被误解为"必须" | 低 | 方案明示可选件+授权门禁；PPT"目标架构"与实施解耦口径已在评审记录 |
| 复核内联按钮被误用为自动审 | 低 | 仅透传既有 batch-review 人工端点+权限码不变+审计已有 |

## 8. 完成定义（DoD）

P0 全项落地+验收全过+测试门禁全绿；P1 至少 path 走查与 minimap 两项；改造报告+截图（搜索聚焦/双击展开/属性面板/图例过滤/review 辨识各 1）+README/55 登记；P2 呈报不默认执行。
