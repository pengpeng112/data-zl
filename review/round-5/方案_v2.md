# 方案 v2：关系图谱"Neo4j 式直观化"改造计划（round-5 证据修订版）

> 本版按 round-5 三方审查+证据终审重写 §3/§4（v1 的三大事实错误已修正：邻域端点已存在、布局已是力导向家族、搜索/抽屉/聚合/URL/血缘跳转均已部分落地）。裁决链见 `分歧表.md`。

## 0. 用户原始需求与前置决策点

**用户原话（2026-08-29）**："请你分析下，我现在需要对关系图谱界面进行优化和完善，请你分析下看看如何进行完善，让更加直观，而且想 neo4j知识图谱，给出一个详细的改造计划。"

**决策点 A（已裁决 2026-08-29：用户选①交互对标，暂不引入存储）**："像 neo4j 知识图谱"的落地口径——
① **交互对标**（本计划 P0/P1 全部内容）：达到 Neo4j Browser 的使用手感，不引入图数据库存储；
② **存储引入**：另立 Neo4j 读模型专项（沿用既有 `GraphSyncAdapter` 骨架，Go/No-Go 指标：多跳邻域/路径查询 P95 超出 PG 前沿 BFS 上限、或出现图算法需求时才启动，含离线依赖审计+单独授权）。
决策点 B（已裁决 2026-08-29：用 G6 官方 Minimap——实测核心包自带导出，零新依赖，见 决策记录.md）。历史口径：`130` §2.3"当前需求是 Neo4j 式视觉，不是新建 Neo4j"、`138` Q07"首期不引入"、`01` 蓝图"Neo4j 第二阶段视需求"——本计划与之一致，默认①。

## 1. 目标（一句话）

**在现有 G6 图谱上，把"搜表 → 画布上长出邻居 → 侧栏看属性"做成连续手势**；不新造图 API、不上 Neo4j、不加新前端依赖（G6 官方插件包是否引入见决策点 B）。

## 2. 边界

- 前端改动域（**全路径**）：`frontend/src/views/asset/graph/`（index.vue+6 个 ts 工具）、`frontend/src/views/asset/components/`（AdvancedRelationGraph.vue、GraphToolbar.vue、GraphEvidenceDrawer.vue、RelationGraph.vue SVG 降级引擎）、`src/api/asset.ts`；后端 `backend/app/api/v1/graph.py`（只读扩展+鉴权补齐）。
- 不动：关系数据模型、四视图模式入口与路由（AGENTS.md 代码约束 §8）、129 号既有配色语义（D 类灰紫等）、复核工作流权限模型（`asset.relation.review`）。
- 契约红线：节点/边身份一律五段物理键（108 号整改），任何接口禁用 `schema.table` 作唯一键。

## 3. 现状盘点（2026-08-29 证据核验后）

**后端已有（v1 漏盘，全部实存）**：`/api/v1/graph`（主图）、`/graph/neighbors`（邻域：physical_key/center_physical_key、depth 1–2、direction、limit≤200，Python 前沿 BFS+truncated 元信息）、`/graph/tables/search`（表名/中文名/schema/namespace ilike，无拼音）、`/graph/overview`、`/graph/edges/{id}`、`/graph/options`、`/graph/diagnostics`；`/api/v1/graph-analysis/*`（上下游/最短路/影响/环路，默认 degraded）；`services/graph_sync.py`（GraphSyncAdapter/UnavailableGraphAdapter，PG 为唯一事实源）。**已知缺口：graph.py 全部端点 0 处 require_permission（仅登录态）。**

**前端已有**：四模式（overview 层级下钻=grouped(force-atlas2)/explore=radial/path=layered 预计算/review=grouped）+d3-force 兜底；explore 已有中心表远程搜索+1/2 跳+方向+整图替换式展开；非 explore keyword 仅画布高亮（focusKeyword）；节点/边详情抽屉（ReDetailDrawer/GraphEvidenceDrawer，后者无复核按钮）；边样式已分 A/正式/已验证/B/C/D/视图依赖五类（静态图例）；`aggregate_groups` 聚合+阈值自动聚合（≥140 节点/180 边）、≥220/320 强制 SVG；URL 已序列化 view_mode/center/keyword 等；lineage expandInGraph 已跳图谱。

**真缺口（v1 痛点修正后）**：①"知识图谱"标签名实不符——绑 `layered` 且 `usesPresetPositions()` 直接关布局引擎走环形散布，force 分支不可达（**现有最伤"像知识图谱"的点**）；②explore 展开是**整图替换**非画布增量生长；③搜索无跨模式统一入口、命中已加载节点无 fitView 聚焦；④抽屉跳离上下文、无度数/值域摘要；⑤图例不可点击过滤；⑥控件堆叠（模式+四种布局名+七八个筛选器同屏），画布高 `calc(100vh-400px)`——**不直观的主因是控件过多而非能力缺失**；⑦explore 默认 `confidence=A` 且 `show_review_layer=false`，跨系统（D 类）边默认不可见，与"HIS↔LIS↔PACS↔EMR 直观呈现"的立意相反；⑧path 结果只有列表+图，无走查感。

## 6. 验收（分层，与负载策略对齐）

- **功能**：搜索聚焦≤2 步定位任意已登记表；双击展开 1 跳为**增量合并**（画布节点只增不闪替）；折叠不误删共享邻域（组件测试：双中心重叠展开后折叠其一）；图例三组芯片即时生效；Inspector 不遮画布且零 N+1（网络面板断言）；
- **权限**：`/graph/*` 无 token=401、无 `asset.graph.view`=403（契约测试）；复核按钮无权限不可见且后端仍校验；
- **性能（分层）**：P0=阈值内（≤220 节点/320 边）平移缩放无感知卡顿；P1（LOD 后）=2k/8k 目标；指标拆三项：API P95（隔离库热缓存）<300ms、首见时间<500ms、布局稳定<2s；基准固定（Chrome 稳定版+指定机型+固定数据种子脚本）；
- **质量**：`pnpm run typecheck` 双过+vitest 新增≥8（搜索聚焦/双击事件延迟/引用计数折叠/图例矩阵/Inspector 字段/邻域契约/鉴权 403/布局绑定修正）+build 预算；后端 `pytest tests/test_graph*.py -q` 全绿+全量 0 failed。
